# 《让 Agent 真正交付》出版与国家级一流本科课程建设验收清单

这份清单不是给作者制造“已完成”的自我感觉，而是让课程负责人、教务人员、同行专家、编辑、技术审校和试讲者可以独立退稿。课程内容达到出版质量不等于具备国家级一流本科课程申报资格。

## 申报前置硬门

- [ ] 课程已纳入普通本科人才培养方案并设置学分，课程信息与教务系统一致。
- [ ] 学校已明确申报类型；如申报混合式课程，线上资源、线下活动、学时分配和平台记录真实可查。
- [ ] 已经过当批次要求的真实教学周期，并保留两期教学日历、学生过程记录、成绩和迭代证据。
- [ ] 课程负责人、团队、师德师风、政治审查、知识产权和安全材料符合当批次要求。
- [ ] 课程目标与人才培养目标有映射，能够计算 CLO 达成度并解释未达成原因。
- [ ] 有改革前后或连续两期的真实教学效果证据，不能只用满意度和平均分。
- [ ] 有校内外应用、同行评价、资源共享和持续建设计划，所有数字与身份可核验。

任一硬门缺失时标记“建设中”或“待校方确认”，不得用模拟数据补齐申报材料。

## 零、付费价值测试

编辑在看字数和截图之前，先回答四个问题：

1. 这段内容是否帮助读者少经历一次真实交付事故，而不只是多知道一个名词？
2. 读者是否得到可运行实现、可复制合同或可迁移判断中的至少一种资产？
3. 去掉 Codex 品牌和 FlowERP 示例后，方法是否仍能迁移到另一个真实软件项目？
4. 章节是否证明工作台因 ERP 问题而升级，升级后又确实改善了下一项 ERP 交付？

四问都答不出，内容即使正确也只是免费博客级资料，不足以支撑出版和付费。

## 一、课程项目主线

- 主线遵循明确先后关系：L01～L04 建成 Workbench V0，L05 起通过工作台持续构建 FlowERP；最终作品是工作台驱动的电商 ERP 持续交付系统。
- FlowERP 必须保留逐讲产品状态，不能退化为背景、冻结夹具或最终演示壳；同时不能把主课扩张成脱离工作台能力的 ERP 功能目录。
- 学习证据线记录学生的首次判断、失败、修订、同伴复核和迁移作品，不能用参考仓库已经实现替代学生目标达成。
- 每讲开头交代“上一讲留下什么状态、本讲改变什么、哪些状态必须不变、下一讲接什么”。
- 任何工具名都必须落到一个业务风险，不能以功能列表代替教学逻辑。
- 每讲明确交付 ERP 产品增量、工作台能力增量和证据增量；L01～L03 允许 ERP 状态不变但必须服务 L04 首次交付，L05～L15 不得连续两讲状态不变。
- L15 至少完成“摘要 → 结构化反馈 → 人工分诊 → 新版 Spec/Eval → 独立 Task 验证”的闭环；L16 必须现场抽取并交付一个此前未实现的小需求。Memory、自动资产晋级和新的 Agent 编排只作为挑战线。

### 自进化表述红线

- 自进化指工程资产在治理下升级，不得暗示模型自行训练、修改目标或突破权限。
- 反馈不能直接改代码；接受反馈不等于接受用户提出的解决方案。
- 执行者不能删除失败证据、降低 blocking 等级或放宽断言来证明自己成功。
- 进化记录要能关联 Feedback ID、Task ID、业务对象、失败签名、资产 Diff、报告与审核人。
- 新资产必须在下一次 ERP 交付中接受旧版本红、新版本绿的反证；否则只能称为“修改”，不能称为“进化”。

## 二、逐讲内容红线

每讲同时满足以下条件：

1. 内容足以支撑大纲规定的 30 分钟线上精讲和配套线下行动任务；不以字符数制造挑战度，也不靠代码、表格凑量。
2. 有一个本讲独有的核心冲突，不能重复使用“为什么重要—怎么做—作业”平铺。
3. 至少有一段真实仓库代码、命令、JSON 合同、SQL 状态或 HTTP 交互可供学员跟做。
4. 至少有一个正常路径、一个失败路径，以及失败后哪些状态必须保持不变。
5. 至少有一张承担解释任务的图：流程、状态、时序、数据流、工作方式或真实 Web 页面。
6. 有可执行验收命令、预期退出码与证据位置；不能用“应该成功”作结论。
7. 明确本讲不做什么，防止教学范围无边界扩张。
8. 收尾要改变双账本中的至少一个可描述状态，并自然制造下一讲的问题。

## 三、结果与轨迹双证据

- 结果证据回答“对不对”：Eval 名称、expected/actual、Harness decision、退出码与报告身份。
- 轨迹证据回答“怎样到达”：Repair Task、每轮文件变化、验证命令、失败签名、Graph 边、具名审核与停止原因。
- 不把同名失败直接解释成同一根因；确定性规则只能报告已观察异常，不能伪造唯一归因。
- 候选修复至少区分 Target 改善与 Guardrail 回归；不允许用总分净提升抵消任何核心业务不变量回归。
- Scenario/Holdout、自动 Diff Gate、失败黑名单等未在仓库实现的能力必须标为挑战线，不得写成当前运行事实。
- Trace 保存可审计动作骨架，不要求也不应长期保存模型全部思考文本。
- 评测数据、Spec 和断言也允许被质疑，但可疑用例继续保留并进入具名审核，不由修复者私自删除。

## 四、核心概念审校

| 概念 | 必须讲清 | 必须避免 | 图的类型 |
| --- | --- | --- | --- |
| Codex | 上下文、计划、工具、改动、验证、证据交接 | 把模型自述当完成 | 工作方式图 |
| FDE | 现场观察、结果界定、构建、证明、采用、反馈 | 等同于单纯写代码 | 现场闭环图 |
| Spec | 来源、目标、非目标、约束、验收、完成定义 | 形容词和实现细节冒充验收 | 合同生成图 |
| Prompt | 本轮意图、优先级和输出合同；与 Spec、规则、权限的边界 | 把一句提示词当长期合同或授权 | Prompt/Spec 对照图 |
| Context | 来源、版本、相关性、权限与按需装载 | 全仓库、全日志、旧对话一次塞满 | Context 编译图 |
| MCP | 连接协议、传输、身份、Resource/Tool、allowlist 与失败策略 | 把协议当工具、权限或权威数据 | 连接与信任边界图 |
| Tools | 输入/输出 Schema、副作用、幂等、超时和权限 | 用“做完 ERP”这类无边界能力冒充工具 | 工具调用时序图 |
| Agent | 观察—选择—行动—反馈；结果必须由外部证据裁决 | 把聊天回答、模型或单个 Tool 统称 Agent | 运行循环图 |
| Router | 局部下一跳选择、风险路由与枚举输出 | 让模型自由生成终态并绕过守卫 | 决策表 + 路由图 |
| Skills | 可复用 SOP、参考、脚本与触发边界 | 当作新 Agent、新权限或 MCP Server | 渐进加载图 |
| Harness | 区分广义 Agent Harness 与狭义 Eval Harness；前者管工作条件，后者管质量判决 | 把测试聚合器说成完整运行时，或把所有运行逻辑塞进质量入口 | 嵌套架构图 + 数据流图 |
| Loop | 失败签名、预算、进展、停止、唯一成功态 | `while true` 与假收敛 | 控制状态图 |
| Graph | 显式状态、边、守卫、持久化、人审恢复 | 日志提示冒充暂停 | 状态迁移图 |
| AGENTS.md | 版本化规则、作用域、目录边界、DoD | 把它当真实权限系统 | 约束层级图 |
| Memory | 团队资产与任务 Bundle 分离；来源、Scope、版本、ACL、证据、置信度、生命周期；用后序任务结果评价价值 | 当聊天归档、向量库或可靠业务规则数据库；只看召回率；越权后再过滤；无审核自动升级 Skill | 资产晋升图 + Context Bundle 装配图 + 前后序任务对照图 |

## 五、ERP 与 Agent 边界

- ERP 同时作为权威账本和控制系统出现，不被描述成菜单、数据库或聊天数据源。
- 明确区分课程五对象主线与产品仓库的扩展基线；不以课程范围否认现有能力，也不以仓库能力夸大课程承诺。
- Agent 能做的动作按 Read、Detect、Draft、Execute、Approve、Decide 分级；越往后权限、审计与人工责任越强。
- 问数回答必须说明指标口径、过滤范围、时间、来源和权限；不把自由 SQL 输出当可靠经营事实。
- 高影响动作通过 FlowERP 服务端权限、事务、状态机、幂等和审计执行；禁止直接写运行数据库。
- 采购审批、信用策略、资金安排、期间关账等责任动作保留具名人员控制，不用 Prompt 中的“请谨慎”替代。
- Web 和对话是工作入口，不替代订单、流水、审批、凭证等结构化核对界面。
- 所有尚未实现的自然语言查询、草稿 Schema 或自动决策能力明确标为建议合同或挑战线。

## 六、图文审校

- Mermaid 节点名称能被非作者读懂；箭头有方向，分支有条件，状态图有终态。
- 截图来自真实运行，不绘制虚构成功页；截图中出现缺陷时，正文要指出它证明了什么。
- 相邻图片承担不同问题，不用同一张总架构图反复充数。
- 图片路径有效、替代文本具体；截图中的 Task ID、状态和正文叙述一致。
- Web 图至少覆盖初始化、业务驾驶舱、库存、采购、任务排队、执行结果与反馈审核。
- AI 生成插图只负责建立场景或抽象关系，不替代真实状态和命令证据。

## 七、事实与代码审校

- OpenAI 产品行为引用官方文档，并在录课或出版前再次核验易变项。
- 每段代码对应仓库当前接口；示例字段、枚举、路径与运行结果一致。
- 所有业务不变量与根 `AGENTS.md` 一致：可用库存非负、预占原子、入库幂等、订单合法迁移、采购人审、证据可追溯。
- Hook、CI、Loop、Graph 复用 `python -X utf8 -m eval.harness --suite blocking`，不制造平行质量口径。
- Graph 运行在 Agent Harness 的工具、权限和状态边界内；受控修复 Loop 可以作为 Graph 节点或子流程；不得把三者画成简单替代关系。
- 报告的 `decision`、阻断数量和进程退出码一致；评测未执行不能表述为通过。

## 八、出版前自动门禁

```powershell
python -X utf8 -m unittest discover -s tests -v
python -X utf8 -m eval.harness --suite blocking
python -X utf8 -m workbench.cli demo
python -X utf8 -m agent.loop --max-rounds 3
python -X utf8 -m agent.graph --max-rounds 3
python -X utf8 -m workbench.feedback summary
```

文档检查还要报告：每讲非空白字符数、Mermaid 数、图片数、断链数、代码围栏是否配对、重复段落候选、核心概念是否有图、真实 Web 资产是否齐全。自动检查只提供退稿线索，不能替代技术编辑逐章阅读。

## 九、试讲退稿条件

- 学员听完仍无法回答“为什么库存不足时整单失败比部分成功更正确”。
- 学员把 Test、Eval、Harness 当作三个同义词。
- 学员认为 `AGENTS.md` 能替代沙箱和审批；认为 Memory 是可靠业务规则数据库；或不能解释一条经验为何被采用、排除、降级、过期与撤销。
- 学员把 Loop 的最大轮数用完称为成功，或把 Graph 的 `awaiting_human_review` 自动越过。
- 学员只会看绿色页面，不会拿 Task ID 对比 API、持久化状态和事件链。
- 答辩只演示正常路径，没有正确失败、幂等重放、重启恢复与剩余风险。

只有当一名没有参与写作的试讲者可以依照章节独立复现主线、指出至少一个失败证据、解释 Prompt、Context、MCP、Tools、Agent、Router、Memory、Skills、Harness、Loop、Graph 十一个运行机制的边界，完成冷启动交接，并在关闭原会话后让第三项任务正确采用一条经验、拒绝一条过期或越权经验、报告一次无效或负迁移结果，才进入排版定稿。
