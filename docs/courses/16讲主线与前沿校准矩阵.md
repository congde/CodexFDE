# 16 讲主线与前沿校准矩阵

> 校准日期：2026-08-19。本文是教学治理用的派生索引，不是新的课程大纲。16 讲标题、核心内容、演示结果、课内增量和通过标准仍以 `docs/课程大纲-Codex-FDE行动营-个人研发自动化工作台.md` 为唯一课程合同；如有冲突，以大纲为准。

## 一、校准原则

课程先在 L01～L04 建成 Workbench V0，再沿一条双增量因果链推进：**FlowERP 需求进入工作台 → 当前能力尝试交付 → 失败推动工作台升级 → 升级后的工作台完成或修复 ERP 增量 → 学生用首次判断、失败、修订、互评和迁移证据证明本人会用**。前沿做法必须服务这条链，不能把课程改成工具目录、ERP 菜单目录或热点名词巡展。

前沿内容分为三层：

| 层级 | 进入课程的规则 | 评价地位 |
|---|---|---|
| **稳定基础 B** | 已有稳定工程语义、公开协议或长期安全原则，并且直接支撑本讲大纲任务 | 可进入跟跑线和基础通过标准 |
| **当前增强 E** | 当前官方产品或行业实践已经可用，但变化较快、依赖特定平台或不是大纲必需 | 用于对照实验、挑战任务或迁移说明，不抬高基础通过线 |
| **观察项 W** | 仍在快速演进、存在兼容性或标准状态变化 | 只教评价方法和替换边界，不以采用某个工具或字段作为达成证据 |

课堂使用前还要做三项检查：官方资料的检索日期是否仍有效；当前仓库是否真的实现了所讲能力；学生证据是否来自本人真实操作。文档、截图、参考仓库绿色结果和 Agent 自述都不能替代学生达成。

## 二、16 讲双增量校准矩阵

| 讲次 | 工作台唯一增量 | FlowERP 产品增量/受保护状态 | 学生关键证据 | 硬边界与下一讲输入 |
|---|---|---|---|---|
| **L01 终局与接手** | 终局地图、环境基线、证据账、接手报告 | 建立 ERP 基线快照与能力地图，业务账不变 | 首次完成等级判断、命令实跑、AI 初稿修订、同伴冷复现 | 不把参考仓库完成冒充学生完成；向 L02 交付高风险边界 |
| **L02 `AGENTS.md`** | 分层规则、禁止项、验证入口和 DoD | 固化主数据、库存、订单、采购长期边界，业务账不变 | 无规则/有规则对照、合法替代路径、新会话复验 | 规则不代替事务和审批；向 L03 交付首个需求边界 |
| **L03 可验收 Spec** | Spec Schema、解析器、来源与语义签字 | 签字确认库存导出合同，产品代码暂不变 | 歧义账、正反边界用例、解析失败、跨组复述修订 | 不提前编码；向 L04 交付唯一可执行合同 |
| **L04 最小变更** | 受控执行、能力信封、结果摘要和最小 Eval | 由工作台实现库存导出首个增量 | 读写禁止集、真实 Diff、正反路径、独立复验 | 不顺手重构；向 L05 交付可被反例挑战的真实增量 |
| **L05 失败优先 Eval** | 业务/工程 Eval、失败签名、红绿协议 | 交付幂等入库，重复键只生效一次 | 两次同签名红、失败后状态、冻结 Eval 后绿 | 不删除或降级 Eval；向 L06 交付多个确定性用例 |
| **L06 Harness** | 用例发现、等级、JSON 报告、退出码 | 交付可用库存口径并保护非负库存 | blocking/observing/error 报告及退出码对照 | Harness 不猜根因；向 L07 交付唯一质量入口 |
| **L07 Codex Hooks** | 生命周期 Hook、来源审查、重入与超时 | 交付销售订单创建，缺货失败后订单与库存不变 | 合法订单、缺货阻断、Hook 协议与恢复证据 | Hook 不代替领域守卫；向 L08 交付待验证预占增量 |
| **L08 CI 远程复验** | 可信 Workflow、Evidence Envelope、身份与归档 | 交付整单原子预占，抓住超卖、部分预占和假绿 | A 假绿—B 诚实红—C 可信绿、文件边界、同伴法证 | 门禁与业务分两步修；向 L09 交付取消释放红色报告 |
| **L09 Repair Task** | 报告到最小修复授权的映射 | 修复订单取消未释放预占 | 报告指纹、允许/禁止集、受控 Diff、复验 | 不启动多轮；向 L10 交付状态机 Repair Task |
| **L10 有界 Loop** | 失败签名、预算、无进展/振荡和安全停止 | 修复订单非法状态迁移 | 收敛与未收敛 History、每轮 Diff、stop reason | 轮数用完不等于成功；向 L11 交付采购需求 |
| **L11 Subagents** | 读写集、冲突图、子任务合同和汇总核验 | 并行完成采购规格、Eval 与风险审查，串行集成采购申请 | 原始子报告、引用回查、单/多 Agent 对照 | 共享写集不并行；向 L12 交付待审批采购申请 |
| **L12 Graph 与人审** | 显式状态、checkpoint、回退和具名 HITL | 交付采购申请—人工审批—审批后入库 | Graph Trace、匿名/重复阻断、重启恢复、ERP 状态对账 | 交付 Graph 与采购状态机分离；向 L13 交付可服务化流程 |
| **L13 Task API** | Task 资源、幂等、持久化和并发状态迁移 | 从 API 提交并完成一项 ERP 补货需求 | API 矩阵、同 ID 重启查询、Spec/Eval/审核回链 | `202` 不等于完成；向 L14 交付权威 Task 与 ERP 状态 |
| **L14 Web 驾驶舱** | 状态投影、证据下钻、错误恢复和三方对账 | 增加真实 ERP 操作页并关联其交付证据 | DOM/API/SQLite/ERP 四方对账、断网与未知态 | 不用静态假数据；向 L15 交付真实页面反馈 |
| **L15 摘要与反馈** | Summary、Feedback、Evolution 与人工晋级 | 由真实反馈形成新版 Spec/Eval 并交付一个改进 | 原文/解释/决定、源任务、独立候选任务、红绿记录 | accepted 不直改裁判；向 L16 交付可抽查证据包 |
| **L16 冷启动答辩** | 启动、恢复、回滚和发布证据索引 | 现场抽取并交付此前未实现的小需求 | 环境指纹、陌生人操作、现场 Spec/Diff/Eval、人审和风险 | 不预演固定答案，不用口头补步骤；结果进入 CLO 改进 |

## 三、阶段性硬门

- **Gate V0（L04）**：工作台必须已能消费真实 ERP Spec、限制写集、产生 Diff、运行最小 Eval，并交付库存导出。
- **Gate V1（L08）**：ERP 必须已有幂等入库、可用库存、订单和原子预占；本地/远端质量结论一致。
- **Gate V2（L12）**：ERP 必须已有取消释放、合法订单状态和采购审批入库；自动化不能自批或无限返工。
- **Gate V3（L16）**：工作台与 ERP 均可冷启动；评审者能现场抽取新需求并沿证据链验收。

## 四、贯穿课程的产品化思考证据链

完整的领域和质量模型不等于可用产品。课程必须保留“先建立完整认知，再根据用户工作和风险做减法”的推理过程，防止学生把术语数量、页面数量或审批步骤误当作专业性。该思考线不改写大纲标题和基础通过标准，而是作为形成性评价与产品修订证据进入对应讲次。

| 检查点 | 本讲必须作出的产品判断 | 形成性证据 | 对后续产品的约束 |
|---|---|---|---|
| L01 终局判断 | 当前成果是 Dashboard、Coding Runner，还是能够辅助判断与交付的工作系统 | 首次分类、证据、反证条件、修订记录 | 不从页面和 Agent 数量反推产品 |
| L03 需求入口 | 输入是未经验证的 Signal、待实验假设，还是可以进入 Spec 的交付决定 | 需求判定卡、来源、替代方案、具名决定 | Spec 不能替代“该不该做”的判断 |
| L12 风险路由 | 哪些任务可快速通过，哪些需要标准或严格路径；哪些状态可以跳过、回退或停止 | 风险路由表、Graph Trace、拒绝过度设计的理由 | Gate 是条件化政策，不是人人走完的八道手续 |
| L14 界面压缩 | 哪些内部对象必须显示，哪些应折叠为决策简报、交付合同、证据包和结果复盘 | 内外对象映射、黄金路径走查、删除项说明 | 内部领域模型不能原样变成导航菜单 |
| L15 产品复盘 | 反馈要求新增能力，还是应隐藏、合并、简化或删除流程 | keep/add/merge/hide/remove 决策、来源与独立复验计划 | 进化包括减法，不能只增 Rule、Eval、Agent 和页面 |

讲师在 L16 答辩中随机抽取其中一条记录，要求学生解释：当时掌握了什么证据、为什么改变判断、做了什么减法、什么新事实会再次推翻当前方案。只有最终页面而没有推理版本，不能证明学生具备产品迁移能力。

## 五、内容取舍规则

- 单纯增加 ERP 菜单、字段或报表而没有触发工作台能力升级，移入产品挑战线。
- 单纯讲工具、协议或框架而没有回到 ERP 增量验证，移入补充阅读。
- L05～L15 若本讲不产生新 ERP 功能，必须完成对既有增量的真实缺陷修复，并说明权威状态前后变化。
- 每个产品增量至少有正常路径、失败路径和失败后不变状态；参考仓库已有实现不能替代学生亲手交付。

## 六、前沿层级在双增量中的位置

稳定基础 B 可以进入跟跑线；当前增强 E 只用于提高交付可信度；观察项 W 只教替换和评价方法。采用任何前沿工具都不能替代 ERP 产品状态、工作台机器证据或具名人审。
