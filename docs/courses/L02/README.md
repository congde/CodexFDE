# L02｜把仓库规则写进 `AGENTS.md`

重新打开一次 Codex 对话，怎样让它继续遵守项目约定？本讲把“能改哪里、做完要查什么、谁来验收”写成一份规则文件，再用实际请求检查规则是否起作用。

项目的代码和配套文件放在同一个目录，由 Git 记录版本，这样的项目称为仓库。`AGENTS.md` 是放在仓库根目录的规则文件；根目录就是这个项目最外层的文件夹。

| 起点 | 本讲新增 | 交给 L03 |
|---|---|---|
| 能保存任务与证据的工作台 V0.1 | 写明目录职责、禁止事项、验证命令和完成条件的仓库规则 | 有版本和实际对照结果的长期约定；业务账保持原状 |

1. [辅导资料](辅导资料.md)：用状态文案案例，判断哪些规则应长期保留、怎样避免拒绝合法维护。
2. [实践操作手册](实践操作手册.md)：先存修改前回答 N0，再改规则，在全新任务取得 N1 并做合法对照。
3. [SUBMISSION 提交索引](SUBMISSION.md)：关联规则前后版本、原回答、程序检查与自己的结论。

**贯穿本讲的对照：**“记录齐全就写已验收”应被纠正；“保留待审核、缩短文案”应被允许。两种请求一起测，才能判断规则是否缺失或过宽。

个人材料放在自己的 `lesson-02-submission/`；已有记录继续追加，示例与课程参考结果不代替本人证据。

按需材料：

- [write-agents/SKILL.md](write-agents/SKILL.md) 是第 4 步采用的规则写作练习，保留其配套目录。
- `assets/` 为正文配图及来源记录，随正文查看。
- [reference/参考说明](reference/参考说明.md) 提供深层参考与历史索引，完成主线后按需查看。
- [唯一课堂课件](L02-把仓库规则写进AGENTS.md-流程实例版.pptx) 随课堂使用，操作以当前手册为准；历史版本已归档。
