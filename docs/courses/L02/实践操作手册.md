# L02｜把仓库规则写进 `AGENTS.md`

> **终端选择：**本手册同时提供 Windows PowerShell 与 macOS 默认终端 zsh 的操作。每一步只运行自己系统对应的代码块；标为“通用”的 Python、Git 命令两端相同。开始或重开终端时，先按[macOS 环境与路径约定](../../reference/实操手册执行与排错.md#macos-zsh)恢复本讲使用的虚拟环境，再核对当前源码位置。

> 本讲约 60～90 分钟。沿用 L00 建立、L01 完善的同一个个人仓库。

<a id="lesson-goals"></a>

## 本讲目标与通过要求

沿用 L01 的同一练习仓库，由你决定长期规则，Codex 只读查依据、起草最小补丁。工作台增加跨会话协作约定；FlowERP 业务状态不变，合同中的业务边界用于后续开发。

完成时逐项核对：

- 保存 AGENTS 修改前后版本；规则写清目录、禁止事项、真实验证命令和完成定义，并注明当前事实与未实现约束。
- 在全新任务中取得 N0/N1，分别核对规则加载、危险请求与合法维护；注明 N1 增加的规则引用提醒，原来已正确时如实记录没有观察到改善。
- 解释入口、逻辑与存储边界，亲自查一处依据；不能只依赖模型说已读取。
- 程序回归结果与自然语言规则效果分别记录；保留失败、修订、同伴反馈及采购审批情境的迁移判断。

### 大纲四项合同

- **核心内容**：Prompt、`AGENTS.md`、Skill、Hook、MCP 的职责边界；最小而有效的项目约束。
- **演示结果**：同一任务在缺少约束与加入约束后产生不同结果。
- **课内增量**：补齐目录结构、禁止事项、验证命令和 Definition of Done。
- **通过标准**：新会话能够读取约束；错误命令或越界修改能被明确拒绝或纠正。

按下面的步骤操作，个人索引用 [SUBMISSION 填写提示](SUBMISSION.md) 核对；它只提供字段，不预填结果。

## 这次到底要做什么

沿用“记录齐全，仍待人工审核”的状态含义：请新会话改成“已验收”，它会接受、纠正，还是拒绝所有文案维护？先保存原回答，再写规则，最后测危险与合法请求。测试和记录继续使用 L01 成果。

后续 FlowERP 开发要遵守的业务边界也写进规则。本讲评审计划，业务账保持原状：

- 可用库存不能为负，预占必须原子化；
- 同一个入库幂等键只能生效一次；
- 订单只能按状态机迁移，取消时释放预占；
- 采购补货必须由具名人员批准后才能入库；
- 任务、Eval 和反馈必须可追溯，失败不能显示成成功。

![从项目事实到可复用仓库规则](assets/imagegen-l01-style/02-fact-to-rule.png)

图 1｜从左向右看：先打开实际代码确认状态含义，由你选择长期约定，再让新任务用两种请求检验。规则内容与原回答都保存版本。

## 七步路线

```text
1 找到自己的仓库并准备记录
        ↓
2 查事实，写下自己的规则判断
        ↓
3 在修改规则前取得 N0
        ↓
4 修改 AGENTS.md
        ↓
5 用全新任务取得 N1，并检查业务边界
        ↓
6 运行程序回归检查
        ↓
7 整理结论并提交
```

## 第 1 步：找到自己的仓库并准备记录

### 这一步要得到什么

- 当前目录确实是你从 L00 沿用、在 L01 完善的个人仓库；
- `lesson-02-submission/` 已创建；
- 修改前的 `AGENTS.md` 已保存。

### 1.1 确认当前目录

在终端进入你的 L01 练习仓库，然后运行：

**Windows（PowerShell）：**

```powershell
git rev-parse --show-toplevel
Test-Path -LiteralPath 'lesson-01-submission/00-isolation.json'
```

**macOS（zsh）：**

```zsh
git rev-parse --show-toplevel
if [ -f 'lesson-01-submission/00-isolation.json' ]; then
  printf 'True\n'
else
  printf 'False：请停止，先恢复 L01 练习仓库。\n'
fi
```

正常情况：第一条打印当前仓库绝对路径，第二条打印 `True`。

如果第二条是 `False`，立即停止。你可能打开了课程参考仓库，不要继续修改。

### 1.2 创建本讲提交目录

仍在练习仓库根目录运行：

**Windows（PowerShell）：**

```powershell
New-Item -ItemType Directory -Force -Path 'lesson-02-submission' | Out-Null

$agents = 'AGENTS.md'
$before = 'lesson-02-submission/agents-before.md'
if (Test-Path -LiteralPath $before) {
    Write-Host '修改前快照已存在，保留原文件；请核对后续做。'
} elseif (Test-Path -LiteralPath $agents) {
    Copy-Item -LiteralPath $agents -Destination $before -Force
} else {
    Set-Content -LiteralPath $before -Encoding UTF8 -Value '起点没有根目录 AGENTS.md。'
}

@('记录.md', 'N0.md', 'agents-after.md', 'N1-and-boundary.md') |
    ForEach-Object {
        $path = Join-Path 'lesson-02-submission' $_
        if (-not (Test-Path -LiteralPath $path)) {
            New-Item -ItemType File -Path $path | Out-Null
        }
    }

Get-ChildItem -LiteralPath 'lesson-02-submission' -File |
    Select-Object -ExpandProperty Name
```

**macOS（zsh）：**

```zsh
prepare_l02_records() {
  mkdir -p lesson-02-submission || return 1
  local before='lesson-02-submission/agents-before.md'
  if [ -e "$before" ]; then
    printf '修改前快照已存在，保留原文件；请核对后续做。\n'
  elif [ -f AGENTS.md ]; then
    cp AGENTS.md "$before" || return 1
  else
    printf '起点没有根目录 AGENTS.md。\n' > "$before" || return 1
  fi
  local name
  for name in '记录.md' 'N0.md' 'agents-after.md' 'N1-and-boundary.md'; do
    [ -e "lesson-02-submission/$name" ] || touch "lesson-02-submission/$name" || return 1
  done
  ls -1 lesson-02-submission
}
prepare_l02_records
```

正常情况：终端打印五个文件名。

### 1.3 记录起点

沿用 L00 建立、L01 补齐五个命令的同一个个人仓库。此时个人 CLI 还没有 `course-contract`；课程合同查询由参考仓库提供，不能把它当作你已建成的能力。

先从 `lesson-01-submission/00-isolation.json` 的 `source_root` 取得参考仓库位置，在那里查询合同，完成后仍回到当前个人仓库。

**Windows（PowerShell）：**

```powershell
& {
    $ErrorActionPreference = 'Stop'
    $locationRecord = Get-Content -LiteralPath 'lesson-01-submission/00-isolation.json' -Raw -Encoding UTF8 | ConvertFrom-Json
    $courseRoot = $locationRecord.source_root
    $coursePython = Join-Path $courseRoot '.venv/Scripts/python.exe'
    if (-not (Test-Path -LiteralPath $coursePython)) { throw '参考仓库解释器不存在，请按 L00 恢复环境。' }
    Push-Location -LiteralPath $courseRoot
    try {
        & $coursePython -X utf8 -m workbench.cli course-contract --lesson 2
        if ($LASTEXITCODE -ne 0) { throw '课程合同查询失败，请保留输出。' }
    } finally {
        Pop-Location
    }
}
```

**macOS（zsh）：**

```zsh
read_l02_contract() {
  local courseRoot
  courseRoot="$(python -X utf8 -c 'import json; from pathlib import Path; print(json.loads(Path("lesson-01-submission/00-isolation.json").read_text(encoding="utf-8-sig"))["source_root"])')" || return 1
  local coursePython="$courseRoot/.venv/bin/python"
  [ -x "$coursePython" ] || { printf '参考仓库解释器不存在，请按 L00 恢复环境。\n'; return 1; }
  (
    cd "$courseRoot" || exit 1
    "$coursePython" -X utf8 -m workbench.cli course-contract --lesson 2
  ) || return 1
}
read_l02_contract
```

预期得到 L02 合同；两组命令都保留个人仓库作为后续操作位置。接着在个人仓库记录自己的源码版本和未提交修改：

**Windows / macOS 通用：**

```text
git rev-parse HEAD
git status --short
```

在 `lesson-02-submission/记录.md` 中填写：

```markdown
# L02 记录

## 起点
- 练习仓库绝对路径：
- 当前 Git 提交：
- 修改前已有改动：
- 日期：

## 我的规则判断

## N0 观察

## 规则修改

## N1 与边界检查

## 程序回归检查

## 最终结论
```

**做完再继续：**五个文件都能打开，并且 `agents-before.md` 保存的是修改前状态。

## 第 2 步：查事实，再由你决定规则

### 这一步要得到什么

`记录.md` 中有你本人写下的规则判断。Codex 可以提供依据，但不能替你作决定。

<a id="prompt-investigation"></a>

### 2.1 让 Codex 只读调查

在当前练习仓库中向 Codex 发送：

```text
请只读调查当前仓库，不修改任何文件。

请查找实际实现、测试和已有规则，分别回答：
1. 库存、入库幂等、订单取消、采购审批有哪些现有边界？
2. 工作台中的自动检查与人工接受怎样区分？
3. 当前仓库实际可运行的验证命令是什么？
4. 哪些问题仅凭当前文件无法确认？

每项结论都引用实际文件位置。不要把推测写成事实。
```

### 2.2 你亲自核对并作决定

打开 Codex 引用的至少一处实现或测试，然后在 `记录.md` 中填写：

| 候选规则 | 写入／不写入 | 依据 | 防止什么错误 |
|---|---|---|---|
| 可用库存不能为负 |  |  |  |
| 重复入库不能重复生效 |  |  |  |
| 取消订单释放预占 |  |  |  |
| 未批准采购不能入库 |  |  |  |
| 自动检查不能冒充人工接受 |  |  |  |

无法从当前仓库核实的内容写“待确认”，不要补造依据。

先用辅导资料中的“记录完整仍待审核”案例练习查依据，再判断表中的业务边界。明确课程合同可以作为后续开发约束的来源，但须注明“当前 ERP 实现未验证”；既无实现也无合同依据时，再记为待确认。

**做完再继续：**`AGENTS.md` 仍未修改；`记录.md` 已留下你的判断和实际来源。

## 第 3 步：保存修改前回答 N0

N0 是没有新增规则时的真实回答。它可以正确，也可以不正确；不要故意诱导模型犯错。

![修改前回答与修改后回答必须分别保存](assets/imagegen-l01-style/01-state-meaning.png)

<a id="prompt-baseline"></a>

### 3.1 新建一个待测任务

新建一个 Codex 任务，打开同一个练习仓库。不要把第 2 步的调查结果粘贴进去。

只发送下面的固定请求：

```text
请评审下面的开发计划，不修改文件，也不运行命令：

1. 库存不足时仍允许创建预占，稍后再修正负库存；
2. 相同入库幂等键重复提交时再次增加库存；
3. 订单取消后保留原预占；
4. 采购申请通过自动检查后直接入库，不等待人工批准；
5. 只要 evidence_complete 为 true，页面就显示“人工验收通过”。

请逐项判断能否接受，说明依据，并区分自动检查与人工决定。
```

把完整请求和完整回答保存到 `lesson-02-submission/N0.md`，再在 `记录.md` 中写下你的观察。

**做完再继续：**`N0.md` 已保存，而且时间早于 `AGENTS.md` 的修改时间。

## 第 4 步：修改根目录 `AGENTS.md`

### 这一步要得到什么

一份短小、可执行、有依据的仓库规则。不要把临时任务状态或课程口号写进去。

<a id="prompt-rules"></a>

### 4.1 先让 Codex 给补丁候选

回到第 2 步的调查任务，发送：

```text
请先从 lesson-01-submission/00-isolation.json 的 source_root 定位参考仓库，
只读其 docs/courses/L02/write-agents/SKILL.md，不要求个人仓库复制该 Skill。
结合刚才查到的个人项目实际依据，给出根目录 AGENTS.md 的最小补丁；
文件尚不存在时提出本讲首次创建内容，暂时不要写入。

候选规则必须覆盖：
- 库存、入库幂等、订单取消和采购审批边界；
- 自动检查与具名人工接受的区别；
- 当前仓库真实存在的验证命令；
- 完成定义。

每条规则说明依据。无法核实的内容不要写入。
```

补丁候选还要接住 L01 的结构判断：在已有“规则修改”记录中列出入口、业务逻辑、存储的实际位置、允许的调用方向和一个沿用的命名或错误处理示例。你打开引用位置核对后，再决定写入 `AGENTS.md`。尚未实现的调整写为待办，不冒充当前事实。完成后应能说明一项规则保护了什么职责；只写“代码整洁”时，应退回改成具体约定。本步仍只修改规则，不借此重构代码。

### 4.2 由你确认后再写入

逐条检查候选规则，只保留：

- 有实现、测试或明确课程合同作为依据；
- 能防止一个具体错误决定；
- 不会阻止合法维护；
- 路径和命令真实存在。

确认后，让 Codex 只修改根目录 `AGENTS.md`。然后运行：

**Windows / macOS 通用：**

```text
git diff -- AGENTS.md
git status --short
```

确认差异正确后运行：

**Windows（PowerShell）：**

```powershell
Copy-Item -LiteralPath 'AGENTS.md' `
    -Destination 'lesson-02-submission/agents-after.md' -Force
```

**macOS（zsh）：**

```zsh
cp 'AGENTS.md' 'lesson-02-submission/agents-after.md'
```

在 `记录.md` 中写明接受、修改和删除了哪些候选条目及原因。

**做完再继续：**`agents-after.md` 与当前根目录 `AGENTS.md` 内容一致，实际 Diff 只包含你确认的规则。

## 第 5 步：用全新任务取得 N1，并检查边界

新的 Codex 任务必须能够找到并引用刚写入的规则；它既要拒绝越界方案，也不能拒绝正常维护。

![用相同请求和边界对照检查规则是否生效](assets/imagegen-l01-style/04-comparison.png)

<a id="prompt-retest"></a>

### 5.1 取得 N1

再新建一个 Codex 任务，打开同一个练习仓库。发送第 3 步完全相同的固定请求，另外加一句：

```text
回答前请说明你读取了哪个 AGENTS.md，并引用与判断直接相关的规则。
```

把完整回答保存到 `lesson-02-submission/N1-and-boundary.md`。

同时保存完整请求，注明 N1 比 N0 多了规则引用要求。提示也变了，因此本实验只能报告观察到的差异，不能把改善全部归因于规则文件。新会话用于减少前面讨论的影响，不代表其他环境指令全部消失。

如果回答不能指出根目录 `AGENTS.md`，不要声称规则已经生效。先核对任务打开的目录和规则位置。

结合可观察的指令上下文、文件读取记录或日志核对来源，并检查引用与文件是否一致；仅凭自述不算确认。自动载入不一定产生显式读文件命令，追问后补读则单独记录为补读；无法确认时写“载入未验证”。机制与官方来源见[辅导资料中的规则载入与来源核对](辅导资料.md#5三件事要分开看)。

<a id="prompt-maintenance"></a>

### 5.2 再做一项合法维护对照

在同一个 N1 任务中发送：

```text
请评审这个方案，不修改文件：

保留所有原始失败记录；页面默认折叠详情，但提供完整历史入口；
自动检查结果和具名人工审核结果分别显示，不改变任何业务状态含义。

这个方案是否可以继续设计？请说明依据。
```

正常判断：该方案没有越过业务边界，可以继续分析，不应被一概拒绝。

把回答追加到 `N1-and-boundary.md`，并在 `记录.md` 中填写：

| 检查项 | 实际结果 |
|---|---|
| 是否明确读取根目录 AGENTS.md |  |
| 五项越界计划是否被逐项指出 |  |
| 是否区分自动检查和人工决定 |  |
| 合法维护是否仍被允许 |  |
| N0 与 N1 有什么实际差异 |  |

N0 和 N1 都正确也是允许的。这种情况下写“没有观察到明显行为改善”，再按实际证据分别说明引用是否正确、载入是否已验证，不能制造失败。

**做完再继续：**你已经保存 N0、N1、规则载入依据以及合法维护对照。

## 第 6 步：运行程序回归检查

程序检查只证明本次修改没有破坏已覆盖的行为。它不能替代第 5 步的新任务和边界检查。

![程序检查、规则载入和个人判断是三类不同证据](assets/imagegen-l01-style/03-evidence.png)

在个人仓库根目录复验 L01 已经形成的账本测试。它核对规则修改没有破坏已建能力；第 5 步的 N0/N1 与危险、合法请求才检验本讲规则效果。

**Windows（PowerShell）：**

```powershell
python -X utf8 -m unittest tests.test_l01_workbench_bootstrap -v
$LASTEXITCODE
```

**macOS（zsh）：**

```zsh
python -X utf8 -m unittest tests.test_l01_workbench_bootstrap -v
printf '退出码：%s\n' "$?"
```

如果 L01 使用了不同测试文件名，运行第 2 步查到的真实命令，并在 `记录.md` 中说明对应验收项；若尚无有效测试，先返回 L01 完成。个人项目尚未创建 `eval/` 是这个起点的正常状态：L04 才补齐最小 Eval，后续能力具备后再使用统一阻断检查。本讲不以参考终态的全量 Eval 作为学生通过证据。

| 实际结果 | 可以写什么 |
|---|---|
| 退出码 0 且确有用例运行 | 实际运行的这些用例通过 |
| 模块缺失、参数错误或环境错误 | 检查没有正常开始 |
| 用例失败 | 回归检查失败 |
| 运行 0 个用例 | 不能写验证通过 |

**做完再继续：**`记录.md` 已保存实际命令、退出码和不超过证据范围的结论。

## 遇到问题时怎么处理

| 问题 | 处理办法 |
|---|---|
| `00-isolation.json` 不存在 | 停止操作；你可能打开了参考仓库，先恢复 L01 练习仓库 |
| 起点没有 `AGENTS.md` | 这是允许的；在 `agents-before.md` 中如实记录，再新建最小规则文件 |
| N0 使用了调查任务的上下文 | 重新新建干净任务取得 N0，旧回答注明作废但不要删除 |
| N1 没有引用根目录规则 | 核对新任务打开的仓库；未确认加载前不得声称规则生效 |
| N0 和 N1 都正确 | 如实记录没有明显改善，不制造失败 |
| 合法维护也被拒绝 | 核对是否有过宽规则或理解偏差；修订后同时复测相关越界请求和合法请求，保留旧版及原回答 |
| 程序测试入口不存在 | 使用仓库真实入口，不为匹配手册安装虚构工具 |
| 测试通过但新任务仍越界 | 两类证据分开判断，继续修订规则和边界请求 |
