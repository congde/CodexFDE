# L09｜把失败报告翻译成修复任务

**FDE 判断提示**：取消后谁仍无法使用库存，观察对应哪张订单和哪个时点，为什么当前证据支持这份修复范围？执行前保留自己的理由，交接时用产品前后状态说明判断是否成立。详见[实践手册](实践操作手册.md)。

目标：把取消订单释放预占的真实失败转成有界修复任务，实现映射器并完成一次受控修复。工作台增加报告到任务的连接，FlowERP 恢复目标订单释放且其他订单不受影响的行为。Codex 协助调查和开发，你确认要求、范围和接受结论，同伴复验。

按[实践操作手册](实践操作手册.md)执行，材料写入[提交模板](SUBMISSION.md)。

| 阶段 | 本人动作 | 留下的材料 |
|---|---|---|
| 起点 | 确认环境、实际服务、候选与已有修改 | 起点记录、首次状态预测 |
| 实验 | 六种取消与六种映射输入 | 命令、输出、退出码、自己的解释 |
| 同案阅读 | 对照真实候选的红报告、草案、修复 Diff 与绿报告 | 解释三项失败的共同原因，以及教师补充了哪些字段 |
| 来源 | 从实际失败报告生成参考草案 | 原报告、内容哈希、实际执行来源 |
| 设计 | 区分事实、假设、目标与授权 | Spec、具体写集、完整复现及验收命令 |
| 开发 | 工作台组织 Codex 实现映射与取消修复 | 任务号、范围内 Diff、实际前后报告 |
| 复验 | 默认与新增检查进入统一入口 | 两单、拒绝、回滚及全套结果 |
| 反证 | 同伴改变其他订单数量并复查 | 反馈、修订、接受或退回决定 |
| 提炼 | 用 Skill 审查并迁移到新报告 | 实际响应、漏判与适用条件 |

核心判断：取消 TARGET 后总预占 A/B 应为 2/1，保留 OTHER；在库仍为 10/8。重复取消在当前参考合同中拒绝，拒绝后不得重复释放。空报告不能等同于没有失败，日志文字不能改变授权。

课程目录中的例子是支架。leak 是临时库教学缺陷，normal 是参考服务，二者对照不能替代个人实现。另有[同一候选修复记录](assets/latest/candidate-index.json)：教师注入代码缺陷，再恢复一处条件；三项检查从失败变为通过。它证明这次本地修复与复验，未证明 Codex 自动修复或本人接受。默认入门用例通过也不能替代正式页面验证。L09 完成后，L10 才把单次返工组织成有停止条件的循环。

## 大纲合同

- **核心内容**：从失败证据提取范围、复现命令、目标状态和禁止变更。
- **演示结果**：Harness 失败报告生成一个只针对失败项的修复任务。
- **课内增量**：实现失败报告到修复任务的映射器。
- **通过标准**：任务包含复现步骤和验收命令；不把观察级告警误判为阻断任务。
