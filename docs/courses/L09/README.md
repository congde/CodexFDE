# L09｜把失败报告翻译成修复任务

取消一张订单后，留给它的货还没有释放。只说“修库存”容易误伤另一张订单。本讲先查失败报告，再写清要修哪件事、允许改哪些文件，确认后才请 Codex 修复。

TARGET 是本次要取消的订单，OTHER 是需要保留的另一张订单。把报告和已确认要求整理成修复草案的程序，叫失败映射器；草案仍须你确认。

先建设个人失败映射器，把本轮报告与已确认的目标、文件范围和复验命令组成草案。你确认草案后，工作台才委托 Codex 修复：只释放 TARGET，保留 OTHER，在库不变。

![报告经过调查和范围确认形成修复任务](assets/reading-figures-v2/key-example.png)

图中间是本讲新增的连接：**报告描述事实，确认后的任务规定动作。** 完成后留下映射器版本、来源报告、草案、确认版任务和同案复验；L10 接着决定失败后是否允许再来一轮。

**操作路线：** 固定取消要求与候选 → 建设映射器和检查 → 保存个人红报告并生成草案 → 本人确认业务修复任务 → 限定范围修复 → 用原检查复验与接受。映射器建设和业务修复各用一份 Spec、一个任务编号；两者在同一候选中接续。

按这条顺序完成，不需要先浏览所有附件：

1. [辅导资料](辅导资料.md)：理解本次现场问题、要求和判断依据。
2. [实践操作手册](实践操作手册.md)：从自己的来源准备候选，按步骤运行、修复和复验；目标、合同及 Codex 提示词都在对应步骤内。
3. [SUBMISSION：个人证据索引](SUBMISSION.md)：从首次判断开始关联已有记录，提交实际失败、Diff、复验与具名决定；未做项如实标待完成。

[唯一当前课件](L09-把失败报告翻译成修复任务.pptx)：采用既有 30 页图文案例课堂版；旧根入口版本归档，既有末页检查缺口待复核。本轮未重验 PPT 内容，命令与完成标准按当前手册。

附件随手册使用：[examples](examples/) 保留脚本与 Skill，[assets](assets/README.md) 保留配图和来源。需要深入机制或历史版本时查[参考说明](reference/参考说明.md)，归档稿不构成另一条必做路线。

先按手册完成个人任务，末尾的参考观察遇到疑问再打开。范围不清先调查；报告无效先修输入；生成草案后仍要本人确认。
