# 工作台具体设计

这份文件是课程最小参考骨架的说明，不代表学生已经完成设计或验收。个人从空目录建设时，在同一路径保存自己的目标、取舍、确认范围与实际检查。

## 当前结构

`main.py` 是根入口，转发到 `workbench.cli.main`。没有参数时启动 `serve-workbench`；成熟项目后续再由桌面启动逻辑接管，不在此阶段导入未建设模块。

`workbench/cli.py` 接收启动参数，调用 `runtime_paths.service_runtime` 求出运行目录，再调用 `workbench_server.serve`。新项目默认运行目录是源码根目录下的 `.runtime/workbench`。显式运行目录会改变计划数据位置，换端口只改变访问地址。

浏览器读取 `workbench_web/index.html`、`app.js` 和 `styles.css`。JavaScript 请求 `/api/health`，由 `WorkbenchApp.health()` 返回运行位置与计划中的 `workbench.db` 路径。此阶段不创建运行目录或数据库，也不读写已有数据库。

## 目录如何继续增长

| 目录 | 当前状态 | 后续用途 |
|---|---|---|
| `workbench/` | 启动、路径与 HTTP 已提供 | L01 账本、L03 Spec、L04 受控交付 |
| `workbench_web/` | 页面与运行检查已提供 | 接入真实任务、执行与审核状态 |
| `tests/` | 当前 HTTP 参考检查已提供 | 当前行为与后续能力的正常、失败检查 |
| `agent/` | 仅包位置 | 有界返工与显式状态图 |
| `eval/` | 仅包位置 | 统一检查和报告 |
| `docs/` | 设计与导航 | 个人设计、使用和边界说明 |
| `scripts/` | 仅保存目录 | 后续维护与复验工具 |
| `deploy/` | 仅保存目录 | 后续部署和冷启动材料 |
| `harness_web/` | 可选预留 | 可选完整驾驶舱 |

`AGENTS.md` 目前只定位项目；正式规则由本人在 L02 实验形成。没有提供 `bootstrap.py`、`spec.py`、`harness.py`、`loop.py` 或 `graph.py` 的空实现，后续课程在需要时再建设。

## 当前检查边界

首页、静态文件和 `/api/health` 可以响应；未知路径返回 404，写入不提供。页面点击“重新检查”后，应以本次结果显示状态；服务停止时显示错误并清除旧路径确认。可运行 `python -X utf8 -m unittest tests.test_workbench_server -v` 核对参考后端。参考检查不包含学生本人的设计、运行或人审结果，需由本人运行并保存事实。
