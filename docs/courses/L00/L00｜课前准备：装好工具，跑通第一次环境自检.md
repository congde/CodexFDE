# L00｜课前准备：装好工具，跑通第一次环境自检

**这份手册完成可用的课程环境和真实自检记录。** 课程已提供工作台项目壳，环境就绪后可进入 L01。建议另外创建一个新工作台项目，按[参考选做文档](./从0开始搭建个人AI研发工作台.md)与 Codex 从 0 设计、搭建并复验；选做后沿该项目继续 L01。FlowERP 在 L04 首次接入。

本手册主线是：**装好工具 → 克隆参考仓库 → 创建并安装 `.venv` → 打开课程工作区 → 检查导入与核验文件 → 保存记录。** 环境就绪后选择使用课程提供的壳，或选做从 0 搭建；后续功能都在选定的同一项目中逐步补齐。

开始时可以用记事本或 macOS“文本编辑”的纯文本模式记录工具版本与错误。克隆仓库后，将[提交模板](../labs/L00/SUBMISSION.md)另存为仓库内的 `lesson-00-submission/L00-环境自检.md`，转入临时记录，边做边填写真实结果。

## 开始前：选对操作位置

终端执行命令，VS Code 查看文件和写记录，Codex 对话框接收自然语言任务。**本手册第 5 步是只读环境核验；选做搭建时，才让 Codex 在你确认的新项目目录和范围内写代码。** 先核验环境，再进入建设，不混用两个阶段的提示词。

- **Windows：**打开 PowerShell，使用 Windows 命令块。
- **macOS：**按 `Command+空格`搜索“终端”，使用 zsh 命令块。可运行 `zsh --version`查看版本；当前用 bash 时，先运行 `zsh`进入 zsh。

只复制代码框中的命令，不复制代码标签或终端行首的 `%`、`$`。命令逐行执行，核对预期后再继续；退出码那一行紧接被检查的命令执行。路径有空格或中文时，用英文双引号包住。停止服务按 `Ctrl+C`（Mac 为 `Control+C`）。

## 1. 装好四个工具

已经安装的工具，先检查版本，不必重复安装。下载安装和 Codex 登录需要网络；本讲不要求 Homebrew、Node.js、Docker 或本地大模型。

### Python：统一使用 3.11.x

**Windows，终端命令：**

```powershell
py -3.11 --version
```

找不到时，按 [Python 官方 Windows 说明](https://docs.python.org/3/using/windows.html)安装 Python Install Manager，重开 PowerShell，再运行：

```powershell
pymanager install 3.11
py -3.11 --version
```

**macOS，终端命令：**

```zsh
python3.11 --version
```

找不到时，从 [Python 3.11.9 发布页](https://www.python.org/downloads/release/python-3119/)下载 **macOS 64-bit universal2 installer**，安装后重开终端再检查。这里指定 `python3.11`，避免 `python3` 指向其他版本。

**完成判断：**看到 `Python 3.11.x`，把完整版本写入记录。

### Git：能在终端执行

**两种系统通用，终端命令：**

```text
git --version
```

找不到时，Windows 安装 [Git for Windows](https://git-scm.com/install/windows)；Mac 按 [Git 官方 macOS 说明](https://git-scm.com/install/mac)安装，也可能由系统提示安装 Apple 命令行工具。安装后重开终端。

**完成判断：**看到 `git version ...`，记录版本。

### VS Code：能打开文件，选 Python 解释器

从 [VS Code 官方下载页](https://code.visualstudio.com/Download)安装稳定版。Mac 可选 Universal 包，将 `Visual Studio Code.app` 放入“应用程序”后打开。

在 VS Code 左侧“扩展”中搜索 `ms-python.python`，确认发布者为 Microsoft，再安装。

**Mac 还要配置终端入口：**按 `Command+Shift+P`，运行 `Shell Command: Install 'code' command in PATH`，然后重开终端。操作依据：[VS Code 官方 macOS 说明](https://code.visualstudio.com/docs/setup/mac)。

**两种系统通用，终端命令：**

```text
code --version
```

**完成判断：**记录实际版本。若 `code` 暂不可用但应用能打开，可先用菜单继续：Windows 从“帮助 → 关于”、Mac 从“Code → About Visual Studio Code”查看版本，并记下这项问题。

### Codex：准备 CLI 和可用的桌面入口

按 [OpenAI 官方桌面说明](https://learn.chatgpt.com/docs/app)安装应用，用自己的 ChatGPT 账号登录并选择 Codex；再按 [CLI 安装说明](https://learn.chatgpt.com/docs/codex/cli)安装终端入口。

**Mac 没有 CLI 时，在 zsh 运行：**

```zsh
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

按安装器输出处理 PATH，并重开终端。

**两种系统通用，终端命令：**

```text
codex --version
```

**完成判断：**CLI 能显示版本。登录与实际提问在本手册第 5 步验证。

官方 Mac 桌面下载当前标注 Apple Silicon。Intel Mac 或系统版本不兼容时，记录“桌面入口不适用”及原因，使用 CLI 完成同一实践，保留相同的人工核验要求。安装说明核对日期：2026-10-04。

## 2. 克隆课程参考仓库，开始留记录

下面将参考仓库放在用户目录的 `work/CodexFDE`。**已有课程仓库时，不重复克隆、不覆盖它：直接进入原仓库，运行后面的路径核对。** 首次准备按自己的系统整段执行：

**Windows PowerShell：**

```powershell
& {
    $ErrorActionPreference = 'Stop'
    $courseFolder = Join-Path $env:USERPROFILE 'work\CodexFDE'
    if (Test-Path -LiteralPath $courseFolder) { throw '目录已存在，请进入原课程仓库，或为首次克隆选择新目录。' }
    New-Item -ItemType Directory -Force (Split-Path -Parent $courseFolder) | Out-Null
    git clone https://github.com/congde/CodexFDE.git $courseFolder
    if ($LASTEXITCODE -ne 0) { throw '克隆失败，先保留并排查上方错误。' }
    Set-Location -LiteralPath $courseFolder
}
```

**macOS zsh：**

```zsh
prepare_course_reference() {
  local courseFolder="$HOME/work/CodexFDE"
  [ ! -e "$courseFolder" ] || { printf '目录已存在，请进入原课程仓库，或为首次克隆选择新目录。\n'; return 1; }
  mkdir -p "$HOME/work" || return 1
  git clone https://github.com/congde/CodexFDE.git "$courseFolder" || return 1
  cd "$courseFolder"
}
prepare_course_reference
```

接着在**参考仓库根目录**核对位置。Windows 先运行 `Get-Location`，Mac 先运行 `pwd`，然后两端通用：

```text
git rev-parse --show-toplevel
git remote get-url origin
```

第一条应显示你刚进入的课程仓库绝对路径，第二条应指向 `congde/CodexFDE`。不是课程仓库时先纠正目录或来源；克隆失败时停在本步，不让 Codex 生成替代课程文件。

在 VS Code 用“文件 → 打开文件夹”打开这个仓库。新建文件夹 `lesson-00-submission`，将[空白模板](../labs/L00/SUBMISSION.md)全文复制到其中的 `L00-环境自检.md`。先填工具版本、仓库路径和上面的 Git 输出。记录留在本机，按开营通知提交，不把个人记录提交到公共课程仓库。

**本步完成：**Git 能识别课程仓库；记录已保存，仓库来源和绝对路径可以查回。

## 3. 创建课程 `.venv`，安装并检查导入

继续在**参考仓库根目录的终端**逐行执行。已有可用的课程 `.venv` 时跳过创建一行，先核对 Python 版本和路径，再安装。任一行失败就停下，不继续复制后面的命令。

**Windows PowerShell：**

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -m pip install -e .
$LASTEXITCODE
.\.venv\Scripts\python.exe -X utf8 -c "import sys, workbench, eval; print('Python:', sys.version); print('解释器:', sys.executable); print('workbench:', workbench.__file__); print('eval:', eval.__file__); print('imports-ok')"
$LASTEXITCODE
```

**macOS zsh：**

```zsh
python3.11 -m venv .venv
./.venv/bin/python --version
./.venv/bin/python -m pip install -e .
echo $?
./.venv/bin/python -X utf8 -c "import sys, workbench, eval; print('Python:', sys.version); print('解释器:', sys.executable); print('workbench:', workbench.__file__); print('eval:', eval.__file__); print('imports-ok')"
echo $?
```

`pip install -e .` 把当前仓库安装到它自己的环境中，后续修改源码时不必每次重装。首次安装可能需要网络取得构建工具；课程程序使用 Python 标准库。

**预期结果：**Python 为 3.11.x；解释器在当前仓库的 `.venv`；`workbench` 和 `eval` 都来自当前参考仓库；最后显示 `imports-ok`，安装与导入检查的退出码都为 `0`。把实际命令、输出和退出码填入记录。导入成功只证明环境能读取课程包，自己的工作台尚未开始建设。

## 4. 打开课程工作区，选择同一个解释器

在参考仓库根目录执行两端通用命令：

```text
code docs/courses/FlowERP-AI研发工作台.code-workspace
```

`code` 暂不可用时，在 VS Code 选择“文件 → 从文件打开工作区”，打开上述 `.code-workspace` 文件。文件列表应包含课程仓库里的 `docs`、`workbench`、`eval`。

按 Windows 的 `Ctrl+Shift+P` 或 Mac 的 `Command+Shift+P`，运行 `Python: Select Interpreter`。选择本仓库 `.venv` 的解释器；列表没有时，选择输入解释器路径：Windows 为 `<课程仓库>\.venv\Scripts\python.exe`，Mac 为 `<课程仓库>/.venv/bin/python`。`<课程仓库>` 替换为第 2 步记下的绝对路径。

打开 VS Code 新终端，先核对当前目录仍是参考仓库根目录，再用第 3 步的完整 `.venv` 导入命令检查一次。记录所选解释器。工作区中的状态、Eval、服务任务留给对应讲次，不用于判断 L00 已完成。

**本步完成：**工作区打开的是同一课程仓库，所选解释器与终端实际调用的 `.venv` 一致。

## 5. 请 Codex 给依据，由自己只读核验

在参考仓库根目录的终端运行两端通用命令：

```text
codex -C .
```

首次使用按提示完成登录。出现 Codex 输入区后，把下面内容作为**对话消息**发送：

```text
我正在完成 L00 环境准备。本次只读，不创建或修改文件，不启动服务，不运行产品演示。
先报告你正在读取的仓库绝对路径。
请分别读取 pyproject.toml 和 docs/courses/FlowERP-AI研发工作台.code-workspace：
1. 找出 Python 版本要求、运行时依赖声明，以及 workbench、eval 的包发现范围；
2. 找出课程工作区的仓库位置和 Python 解释器设置。
每个结论给出实际文件、行号及支持它的原文。区分文件声明与本机实际检查；不要把参考实现说成我已建成的工作台。
```

先核对 Codex 报告的路径，再亲自打开它引用的**两个文件**，找到给出的具体行。检查原文是否支持结论，并与第 3 步实际版本、解释器和模块路径对照。文件只声明 Python 最低版本时，不能据此声称本机已经使用 3.11。

把每项结论、文件位置、支持内容和“吻合／不吻合／未确认”写进记录。路径或行号不对时，要求 Codex 重新只读定位；仍看不懂时保留“未确认”，请它只解释这些行，不代填通过。

**本步完成：**Codex 可登录并回答；至少两个引用文件已经由本人打开核对，结论边界有记录。

## 6. 保存记录，选择项目起点

补完 `lesson-00-submission/L00-环境自检.md`，保存后关闭再打开一次。按下面的标准填写状态：

| 状态 | 判断依据 |
|---|---|
| 环境就绪 | 工具可用；Git 可识别仓库；本仓库 `.venv` 安装与导入成功；工作区解释器一致；两个文件已人工核验；记录能重新打开 |
| 需要辅导 | 环境大体可用，但某项核验、路径理解或操作未完成，写明停在哪一步 |
| 环境受阻 | 安装、登录或解释器导致无法继续，保存真实错误与尝试 |

`serve`、`demo` 或 `course-status` 的输出不能替代这些准备证据。“环境就绪”说明可以进入 L01 或选做搭建，不据此认定账本、受控交付或 ERP 业务已经通过验收。

带上**参考仓库绝对路径、`.venv` 解释器路径、自检记录和未解决问题**，选择一个项目起点。未完成准备项先补齐。

- **使用现成壳**：进入 [L01 的课程壳入口](../L01/实践操作手册.md#provided-shell)，按手册将课程提供的 `starter/` 生成到空的个人目录，再开始本讲实践。准备工具不会复制成熟参考项目的完整能力。
- **参考选做**：建议另建新工作台项目，按[从 0 搭建文档](./从0开始搭建个人AI研发工作台.md)与 Codex 确认架构、分步实现，亲自复验首页、健康接口、失败提示与重启。保存设计、实际输出和修订，再从 [L01 的已有壳入口](../L01/实践操作手册.md#continue-shell)继续该项目。

两条路径都须完成 L01 的本人 Spec、有效红灯、实现、复验与自举。页面壳和壳测试通过只证明起点可用。旧实验成果保留，不覆盖原代码和数据。

## 遇到问题再看

### 先定位错误

| 现象 | 最小检查与下一步 |
|---|---|
| `py -3.11` / `python3.11` 找不到 | 确认 3.11 已安装，重开终端，再查版本 |
| 提示目标目录已存在 | 已有课程仓库则进入它核对来源；首次克隆则换一个目录，不覆盖旧文件 |
| `.venv` 的 Python 找不到 | 核对当前目录和记录中的仓库路径，再检查环境是否创建成功 |
| `pip install -e .` 找不到项目 | 回到有 `pyproject.toml` 的参考仓库根目录，再运行原命令 |
| `import workbench, eval` 失败或来源不对 | 保存输出，核对解释器与仓库路径，再检查安装；不要复制包到其他目录 |
| 工作区选择了系统 Python | 回到第 4 步，选择同一参考仓库的 `.venv` 解释器 |
| Codex 引用不存在的文件或行号 | 要求重新只读定位；自己打开两个实际文件后才写核验结论 |
| Mac 的 `code` 找不到 | 用 VS Code“文件 → 打开文件夹”，按第 1 步配置命令入口 |
| `codex` 找不到或登录失败 | 核对安装器输出与 PATH，Mac 可运行 `rehash`、`command -v codex`；保留错误 |
| PowerShell 显示 `>>`，Mac 显示 `quote>` / `dquote>` | 按 `Ctrl+C` / `Control+C`取消，重新复制完整命令 |
