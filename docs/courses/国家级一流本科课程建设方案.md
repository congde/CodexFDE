# 《Codex + FDE 全链路 AI 交付实战》国家级一流本科课程建设方案

> 建设口径：以“国家级一流本科课程”作为目标，优先按“线上线下混合式一流课程”设计。本文是课程建设与证据采集母版，不等同于已经具备申报资格或已经通过认定。

## 一、先确认申报资格，而不是先包装材料

教育部现行口径要求申报课程是普通本科高校纳入人才培养方案、设置学分的本科课程。线上线下混合式课程还应基于慕课或 SPOC 等线上资源，合理分配线上线下学时，开展真实教学活动并保留可追溯的在线学习记录。课程原则上应经过至少两个教学周期的建设完善，形成真实教学成效和示范应用，并承诺认定后持续建设或共享五年。

本项目当前只能证明课程内容、实践环境、评价工具和证据结构已经开始形成。以下材料必须由申报学校基于真实教学补齐，仓库不得代填或推断：

| 硬门槛 | 当前状态 | 申报前必须取得的真实证据 |
|---|---|---|
| 纳入普通本科人才培养方案并设置学分 | 待校方确认 | 培养方案、课程编码、学分学时、开课单位、教务系统截图 |
| 明确申报类型 | 建议混合式，未定 | 学校推荐意见、线上/线下学时分配、平台与教学组织说明 |
| 至少两个教学周期 | 未提供 | 两期教学日历、选课名单、成绩分布、过程记录、迭代说明 |
| 课程负责人和团队资格 | 未提供 | 正式聘用证明、近五年授课情况、师德师风与政治审查材料 |
| 课程思政真实成效 | 设计中 | 教案、学生作品、观察量表、反思记录和评价数据 |
| 教学改革效果 | 未提供 | 改革前后对照、目标达成度、学生反馈、同行评价和典型作品 |
| 线上学习可追溯 | 仓库不包含平台数据 | 视频学习、测验、讨论、作业、答疑和学习分析记录 |
| 示范推广与共享 | 待建设 | 校内外应用、教师培训、资源访问、同行采用和五年建设计划 |
| 政治、学术、知识产权和安全审查 | 待校方执行 | 审查意见、版权台账、开源许可、数据脱敏和平台安全材料 |

任何一项外部证据缺失时，只能写“待建设”或“待校方确认”，不得用模拟数据补齐申报材料，也不得用课程文案或 Agent 自述替代真实教学证据。

## 二、课程定位

### 2.0 唯一项目主线

本课程的主线是一个有明确先后关系的建造过程：**先在 L01～L04 构建类似 DeepSeek Harness 的个人研发自动化工作台 V0，再从 L05 起由这套工作台持续构建电商 FlowERP**。最终作品是“工作台驱动的电商 ERP 持续交付系统”，而不是孤立工作台或 ERP 功能集合。

```text
FlowERP 新需求或真实失败
→ 当前工作台尝试交付
→ 暴露一个可重复的工程问题并升级工作台
→ 用升级后的工作台完成或修复 ERP 产品增量
→ 保留学生学习证据和改进数据
```

三条线的主次关系固定如下：

| 层次 | 课程职责 | 每讲必须回答的问题 |
|---|---|---|
| 方法主线：工作台建设 | L01～L04 形成 V0；后续随 ERP 交付升级 Spec、Eval、Harness、Loop、Graph、API、Web 和反馈闭环 | 本讲工作台新增或验证了哪项可复用能力？ |
| 产品主线：FlowERP 开发 | 从主数据、库存、订单、采购到操作界面持续形成可运行增量 | 本讲 ERP 的权威产品状态发生了什么变化？ |
| 学习：学生成长证据 | 记录判断、作品、失败、修订、同伴评价和目标达成 | 什么证据证明学生本人能够迁移这项能力？ |

内容取舍遵守三条红线：

1. L01～L04 必须形成能消费 Spec、受控执行和运行最小 Eval 的 Workbench V0；L05～L15 不得连续两讲让 ERP 状态不变；L16 必须现场交付一个此前未实现的小需求。
2. 不能把 16 讲写成 FlowERP 功能开发目录；ERP 增量必须用于触发、验证或反证对应工作台能力。
3. 不能把工作台讲成脱离产品的工具清单；每项能力都要在当讲或下一讲的 ERP 增量中接受验证。
4. 不能用“参考系统已经实现”替代“学生已经学会”；每讲必须保留学生首次判断、失败、修订和独立复验。

### 2.0.1 大纲与前沿的双重校准

`docs/courses/16讲主线与前沿校准矩阵.md` 逐讲记录“大纲唯一任务—现场问题—工作台增量—学生证据—当前实践—不越界条件”。它是教学治理索引，不是新的事实源。前沿内容按稳定基础、当前增强、观察项三级进入课程：稳定基础可进入跟跑线；平台特定或变化较快的增强用于对照和挑战；尚在演进的标准与工具只教评价方法，不进入基础通过线。

每期开课前复核官方来源、协议字段和仓库真实实现。更新时优先保持课程目标、输入输出和证据标准稳定，再替换产品配置或演示方式；不得因新模型、新框架或新功能热度改变 16 讲主线。

`docs/courses/16讲行动密度审计与优化记录.md` 进一步检查每讲是否包含学生亲手构造、主动失败、因果隔离、陌生人复验、能力迁移和 FlowERP 停止边界。该文件属于教学设计审计，不是学生数据；只有真实开课后形成的过程记录才能证明行动任务有效。

`docs/courses/16讲系统化精修蓝图.md` 进一步把 16 讲统一投影为“入口冲突—学生动作—ERP/工作台双出口—主动失败—个人证据—下一讲交接”。它只用于发现串讲、换题和证据断裂，不是第二份课程合同；与大纲或 `workbench/course_mainline.py` 冲突时必须回到上位合同修订。

### 2.1 建议纳入的人才培养场景

- 建议课程性质：软件工程、计算机科学与技术、人工智能、信息管理等专业的高年级专业选修课或新工科项目制课程。
- 建议先修课程：程序设计、软件工程基础、数据库基础、Git 与命令行基本操作。
- 建议教学形态：线上微课与诊断测验 + 线下项目研讨和失败实验 + 课后仓库实践 + 每周项目诊所。
- 建议项目载体：先构建个人研发自动化工作台，再通过它持续建设 FlowERP；两者共同组成结业作品，FlowERP 必须保留逐讲产品增量和工作台交付证据。
- 建议申报特色：面向生成式 AI 时代的软件工程质量与责任，把 Spec、Eval、Harness、Loop、Graph 和人机协同落实为可运行、可复验、可追责的工程活动。

最终课程名称、课程类别、学分学时和适用专业必须服从学校人才培养方案，不能仅由仓库决定。

### 2.2 学情与教学痛点

课程面向“会写代码但缺少完整交付训练”的学习者。入课诊断应真实测量，而不是根据年龄或专业标签推断：

| 典型起点 | 对应教学问题 | 课程干预 |
|---|---|---|
| 能生成代码，但把模型自述当完成 | 缺少验收意识 | 用 Spec—Diff—Test—Summary 证据链约束结论 |
| 会写单测，但不会设计业务反例 | 测试与真实风险脱节 | 从损失、不变量和失败后状态反推 Eval |
| 会调用 Agent，但不会限制范围与停止条件 | 自动化容易越权或失控 | 写集、预算、Repair Task、Loop 和 Graph 守卫 |
| 能完成个人作业，但不会交接和答辩 | 工程结果不可复验 | API/Web 状态、摘要、反馈、冷启动与同伴质询 |
| 关注效率，但忽视数据、审批和责任边界 | 价值判断缺位 | 将工程诚信、安全、职责分离和可追责融入真实决策 |

开课前用环境检查、仓库阅读和基线任务形成学情数据；教学中根据错误类型分层支持，不以统一答案掩盖起点差异。

## 三、课程目标：价值、知识、能力相统一

| 编号 | 结课时学生能够完成的可观察行为 | 目标维度 | 主要证据 |
|---|---|---|---|
| CLO-1 | 分析陌生仓库，指出结构、约束、验证入口与高风险边界，并在压力下拒绝伪造成功或越权改账 | 价值 + 分析 | 接手报告、`AGENTS.md`、越界请求判决 |
| CLO-2 | 将模糊业务需求转化为包含正常、失败和边界条件的可执行 Spec，并完成受约束的最小变更 | 知识 + 设计 | Spec、用例矩阵、最小 Diff、独立复验 |
| CLO-3 | 针对真实业务风险设计反例 Eval，使用 Harness、Hook 和 CI 形成可重复质量证据 | 评价 + 创造 | 红绿记录、Harness JSON、Hook/CI 证据 |
| CLO-4 | 把失败压缩为有边界的修复任务，并控制自动返工在轮次、时间、Token 和无进展条件下诚实停止 | 分析 + 控制 | Repair Task、Loop History、停止原因 |
| CLO-5 | 判断任务是否适合并行，设计可追溯的子任务合同和显式状态图，保留具名人工审核责任 | 协作 + 责任 | 读写集、子任务证据、Graph Trace |
| CLO-6 | 从干净环境运行、解释和答辩一套可查询、可反馈、可回滚的 AI 交付工作台 | 综合 + 创造 | API/Web、摘要、反馈、冷启动和答辩包 |

课程目标达成必须同时满足“做出来、讲清楚、守边界”。复制参考答案但不能解释失败原因、权威状态和责任边界，不视为达成。

### 3.1 课程目标—毕业要求—评价任务对齐

仓库只能定义课程内部的产出关系，不能代替学校确定专业毕业要求指标点。开课单位应在下表“校方指标点”列填入经专业负责人和教务部门确认的编号，并保留审批版本；未确认前统一标为“待校方映射”。

| CLO | 建议承载的毕业能力 | 校方指标点 | 核心学习活动 | 直接评价任务 | 达成底线 |
|---|---|---|---|---|---|
| CLO-1 | 复杂工程问题分析、职业规范 | 待校方映射 | 陌生仓库接手、规则法庭、越界请求判决 | L01 接手报告、L02 规则补丁、L16 风险答辩 | 能引用真实入口并对越权请求给出合法替代 |
| CLO-2 | 需求分析、系统设计与实现 | 待校方映射 | 需求证据审查、Spec 交叉复述、最小 Diff | L03 Spec、L04 库存导出、综合作品 | 正常/失败/边界可执行，改动不超授权写集 |
| CLO-3 | 验证、实验与工程工具 | 待校方映射 | 失败优先实验、Harness 判决、CI 法证 | L05～L08 红绿与报告证据 | 阻断结论、退出码和权威业务状态一致 |
| CLO-4 | 问题诊断、系统控制与持续改进 | 待校方映射 | 失败压缩、收敛/未收敛对照 | L09 Repair Task、L10 Loop History | 有复现、预算、停止条件且不把耗尽写成成功 |
| CLO-5 | 团队协作、项目责任与伦理 | 待校方映射 | 读写集冲突分析、采购审批法庭 | L11 子任务合同、L12 Graph/HITL | 结论可追溯，冲突不并行，审核具名且不可由 Agent 替代 |
| CLO-6 | 综合设计、沟通、终身学习 | 待校方映射 | API/Web 对账、反馈晋级、陌生环境答辩 | L13～L16 证据包 | 可运行、可解释、可复验，并说明风险与下一轮改进 |

对齐审查采用反向设计：先确认 CLO 的可观察行为和直接证据，再决定线上资源与线下活动。不能因为已经录制某段视频或已有某项代码，就倒推一个无法评价的课程目标。

### 3.2 入课诊断与分层支持

入课诊断不计能力高低标签，只用于调整支架。诊断包至少包含四项：在干净环境运行一次命令；阅读陌生仓库并指出验证入口；把一句模糊需求写成一个正常与一个失败用例；解释一次失败后哪些业务状态必须不变。

| 诊断结果 | 支持方式 | 不降低的共同标准 | 进阶任务 |
|---|---|---|---|
| 环境/命令薄弱 | 提供录屏、命令卡、结对排障时段和已知错误索引 | 必须本人完成冷启动并保留输出 | 比较 Windows/macOS/Linux 差异并补充故障条目 |
| 测试设计薄弱 | 提供“业务损失—不变量—反例”脚手架与示例对照 | 必须独立构造至少一个失败路径 | 设计共享错误假设或变异测试 |
| 业务建模薄弱 | 提供 FlowERP 状态词典、事件时间线和状态机空表 | 不得绕过库存、幂等、订单和采购审批规则 | 识别跨模块不变量和并发风险 |
| 已具备基础能力 | 减少步骤提示，改用黑盒任务和陌生仓库 | 证据与诚信标准完全相同 | 做迁移、性能/成本比较或同伴法证 |

任何支架都必须在 L16 前撤除。需要无障碍支持的学生可使用字幕、可复制命令、键盘可操作页面和替代呈现方式；评价的是同一学习成果，不把视觉效果、打字速度或公开表达风格误当作工程能力。

## 四、“两性一度”如何落到教学活动

### 高阶性

学生不是按步骤复刻功能，而是持续完成分析、评价与创造任务：从矛盾需求中建立 Spec；从业务损失构造反例；在冲突证据中作质量判断；设计有停止条件的自动化；对并行、状态迁移和人工责任作工程决策；最终接受陌生评审者的反证。

### 创新性

创新不等于使用热门工具。课程将生成式 AI 与软件工程、FDE 现场方法、业务状态机、证据链和形成性评价结合；同一套真实仓库既是学习对象，也是学习过程的 Harness。线上资源负责概念诊断和演示，线下课堂负责争议判断、故障实验、同伴评审和答辩，避免“视频搬到线上、讲授原样留在线下”的形式化混合。

### 挑战度

挑战来自开放但有边界的真实任务，而非机械增加代码量。学生必须处理正确失败、共享错误假设、观察项误分级、无进展循环、并行写冲突、匿名审核、状态不一致和冷启动隐式依赖。每项任务都有最低通过线、优秀线和诚实退出条件；失败证据可获得过程分，伪造成功实行一票退回。

## 五、课程思政：嵌入工程决策，不另贴标签

| 育人主题 | 真实教学载体 | 可观察行为 | 评价证据 |
|---|---|---|---|
| 工程诚信 | 测试失败、报告缺失、剩余风险 | 不删失败、不伪造退出码、不夸大完成范围 | 交付摘要与证据索引 |
| 规则意识与责任边界 | 库存事务、采购审批、人工 Gate | 不绕过审批，不用提示词替代权限，不让 Agent 自批 | 越界判决、Graph 审核记录 |
| 数据安全与法治意识 | 密钥扫描、最小权限、反馈数据 | 不提交凭据，最小化采集，说明来源、授权和保留边界 | CI、权限审查、反馈记录 |
| 协作与职业责任 | Subagents、同伴评审、交接答辩 | 明确分工、引用证据、处理冲突、对最终结论负责 | 子任务合同、同伴复核、答辩 |
| 服务国家数字化与产业升级 | FlowERP、AI 工程化、新工科实践 | 用可靠交付解决真实组织问题，而非追逐工具展示 | 项目作品、行业评价、迁移报告 |

课程思政评价以学生行为和作品为依据，禁止在每讲末尾机械添加口号。

## 六、线上线下混合式教学闭环

| 阶段 | 学生活动 | 教师活动 | 数据与证据 |
|---|---|---|---|
| 线上课前 | 观看 30 分钟内精讲、完成诊断题、提交首次判断 | 发布冲突案例，分析错误分布 | 视频、测验、首次判断、疑难点 |
| 线下课中 | 小组决策、代码/状态解剖、故障实验、同伴反证 | 追问证据，组织分层支持，记录关键误区 | 课堂产物、命令、退出码、互评记录 |
| 课后实践 | 在个人仓库完成最小增量和独立复验 | 对失败类型给反馈，不代替学生修复 | Git Diff、报告、反思、二次提交 |
| 每周诊所 | 携带可复现问题参加真实分诊 | 聚类共性问题，发布勘误和补充资源 | 问题单、修复前后证据、资源迭代 |
| 结课答辩 | 陌生环境冷启动、随机失败、风险答辩 | 按统一量规评价并抽查证据 | 现场记录、答辩评分、作品索引 |

线上线下学时及成绩比例由学校最终审批；本方案只规定二者必须承担不同且互补的认知任务。

## 七、评价方案与目标达成

建议采用“过程 60% + 综合项目 40%”，学校可在不破坏目标—活动—评价一致性的前提下调整比例：

| 评价项目 | 建议权重 | 评价对象 | 主要对应成果 |
|---|---:|---|---|
| 课前诊断与首次判断 | 5% | 是否完成真实思考，不按答案正确率简单给满分 | CLO-1 |
| 16 讲形成性任务 | 35% | 每讲独有产物、失败记录、复验和反思 | CLO-1～CLO-6 |
| 四周 Gate 与项目诊所 | 20% | V0～V3 阶段作品、问题分诊和改进证据 | CLO-2～CLO-6 |
| 结课综合作品 | 30% | 可运行工作台、Spec、Diff、Eval、状态与反馈闭环 | CLO-2～CLO-6 |
| 冷启动答辩与同伴质询 | 10% | 解释、反证、责任边界和风险表达 | CLO-1、CLO-5、CLO-6 |

硬性规则：未运行规定命令、阻断级 Eval 未通过却宣称通过、删除失败证据、提交密钥、匿名替代具名审核或无法说明作品来源，相关任务直接退回。退回不等于不给学习机会，学生可在规定周期内依据原失败证据修订并重新提交。

课程目标达成度必须由真实评分项计算。每期至少报告：各 CLO 达成率、关键错误分布、首次与二次提交变化、不同起点学生的增值、未达成原因及下一期具体调整。不得只用满意度或最终平均分证明教学效果。

### 7.1 通用分析量规：判断、实现、证据、责任

每项任务先执行硬门槛，再按四维量规评分。页面美观、代码行数和术语数量不单独计分。

| 维度 | 4 卓越 | 3 达成 | 2 部分达成 | 1 未达成 |
|---|---|---|---|---|
| 判断与合同（25%） | 能比较方案、说明取舍并把隐含风险转为可反驳合同 | 目标、非目标、边界和验收项完整 | 有目标但边界或失败语义含糊 | 直接实现，无法说明需求价值或验收口径 |
| 实现与业务正确性（30%） | 最小实现且处理并发/异常，能证明失败后不变状态 | 正常与失败路径正确，未超写集 | 主路径可用但边界或状态一致性不足 | 违反业务不变量、绕过审批或结果不可运行 |
| 验证与证据（30%） | 证据可由陌生人复现，并主动反证共享错误假设 | 输入、预期、实际、退出码/状态和身份齐全 | 只有局部日志或最终截图，复现依赖口头补充 | 模型自述代替运行、删失败或把红灯写成成功 |
| 协作与责任（15%） | 能处理冲突、引用他人证据并清晰保留最终责任 | 分工、来源、人审和剩余风险可追溯 | 有分工但结论来源或责任人不清 | 匿名审批、越权、抄袭或无法说明作品来源 |

硬门槛触发时先退回修订，不用平均分抵消：提交密钥或敏感数据；阻断 Eval 失败却宣称通过；伪造/删除失败证据；采购未经具名审批入库；无法说明 AI、同伴和本人贡献；L16 使用预制答案冒充现场交付。

### 7.2 CLO 达成度计算与判定

每个评分项必须在开课前绑定一至两个主要 CLO，避免一份总成绩机械映射全部目标。建议采用下式计算个人目标达成度：

```text
个人 CLO-k 达成度 = Σ(该 CLO 直接评价项得分率 × 评价项权重) / Σ评价项权重
课程 CLO-k 达成率 = 达到校方阈值的学生数 / 该 CLO 有效参评学生数
增值 = 末次同构任务得分率 - 入课诊断同构任务得分率
```

建设期可暂用 `个人达成度 ≥ 0.70` 作为预警线，但这不是教育部统一阈值；正式阈值、补考/缺交处理和样本过小规则必须由学校评价制度确认。直接证据承担主要判定，学生满意度、访谈和自评只用于解释原因，不能替代作品、运行和答辩证据。

每期至少输出一张匿名化目标分析表：样本数、均值、中位数、达标人数、首次/二次提交变化、前三类错误、不同诊断起点的增值以及下一期动作。人数过少时只做个案轨迹与描述统计，不声称具有普遍教学效果。

### 7.3 两次提交与评价主体

所有核心任务执行“首次判断/首次作品 → 同伴或 Harness 反证 → 教师反馈 → 二次提交”闭环。评分保留两个版本：首次版本用于分析真实误区，二次版本用于评价学习后表现；不得用覆盖文件抹去学习过程。

| 证据 | 主要评价者 | 评价责任 |
|---|---|---|
| 机器报告、退出码、状态快照 | Harness + 学生复核 | 证明可重复事实，不解释全部原因 |
| Spec、Diff、风险说明 | 同伴盲评 + 教师抽查 | 发现歧义、越界和共享错误假设 |
| Graph 人审、采购批准 | 具名责任人 | 承担授权判断，Agent 不得代签 |
| 综合作品与冷启动 | 教师 + 外部/跨组评审 | 核验独立完成、迁移与答辩能力 |

### 7.4 AI 使用与作品真实性

课程允许并要求使用 Codex，但必须披露：模型/工具用途、关键输入、采纳与拒绝的建议、本人修改、验证命令和剩余风险。评价重点不是“是否用了 AI”，而是学生能否对需求判断、授权边界、业务状态、证据和最终结论负责。

真实性采用四种交叉核验：Git 与任务事件链；随机抽取一个失败现场复现；替换参数或换一个同构小需求；口头解释关键 Diff 和不变量。组队产物必须附个人贡献索引；无法把个人行为映射到证据时，该 CLO 暂不判定达成，进入补充答辩，而不是凭小组总分推断个人能力。

### 7.5 评价工具校准

开课前由至少两名评价者对 3 份匿名样例独立评分，记录分歧维度并修订锚点。教学中抽取不少于核心作品的 10% 进行双评；若关键维度相差超过一个等级，进行复核并记录原因。该比例是课程建设建议，不是国家认定统一要求，学校可根据班额调整但必须保留一致性检查。

## 九、每讲统一教学设计母版

每讲详细讲义必须回答以下问题，但不得把表格机械复制成相同课堂：

1. 本讲对应哪个 CLO，预期学生完成什么可观察行为；
2. 如何体现高阶性、创新性和挑战度；
3. 课前、课中、课后分别由学生做什么，教师如何提供支架；
4. 课程思政通过哪个真实工程决策自然发生；
5. 形成性评价收什么证据，谁来评价，如何允许修订；
6. 本讲数据如何进入下一轮教学改进；
7. 哪些结论来自真实教学，哪些仍是建设计划或待补证据。


该目录只定义证据类别，不应提交学生个人敏感信息、密钥、运行数据库或未经授权的作品。仓库中不创建伪造的申报证据样本。

### 10.1 证据成熟度与质量门

课程材料统一使用四级状态，避免把“写进方案”表述为“已有成效”：

| 状态 | 含义 | 可以使用的表述 |
|---|---|---|
| D：已设计 | 目标、活动、量规或模板已经形成，尚无真实教学数据 | “已完成教学设计”“计划采集” |
| P：已试教 | 有一次真实试教/小规模运行记录，尚未形成跨周期证据 | “试教发现……”“初步观察到……” |
| V：已验证 | 至少两个真实教学周期使用同一口径，证据可追溯并完成改进闭环 | “两个教学周期数据显示……” |
| A：申报就绪 | V 级证据齐全，并经学校资格、政治、学术、质量、版权和安全审核 | “经学校审核确认……” |

当前仓库最多证明部分内容达到 D 级，参考实现测试通过也只证明技术基线，不证明 P/V/A。各质量门的当前事实、责任人与补证动作见 [`国家级一流本科课程申报级质量门.md`](./国家级一流本科课程申报级质量门.md)。

### 10.2 两个教学周期的持续改进闭环

每个教学周期必须形成“问题—证据—动作—再测量”的闭环，而不只是修订讲义：

1. 开课前冻结课程版本、代码标签、CLO—任务映射、量规和诊断题；
2. 课中保留首次判断、失败类型、二次提交、同伴反馈和支持措施；
3. 期末计算 CLO 达成、增值和关键错误，形成具名课程组会议纪要；
4. 只选择有证据支持的改进动作，注明负责人、完成日期和受影响讲次；
5. 下一周期用同构指标复测，判断改动是否有效；无改善时保留负结果并重新诊断。

两个周期不能使用模拟学生、参考仓库重复运行或教师自评替代。跨期比较如更换题目、量规、班型或平台，必须记录口径变化，不能直接宣称提升。
