# L14｜让交付状态在 Web 面板可见

采购页面断网后，旧卡片还能当作最新状态吗？本讲让页面说明查询失败、保留原单据供恢复，并让工作台页面展示同一修复任务的进度、报告和待验收状态。

Web 面板就是网页界面；页面通过 L13 的查询入口（API）读取实际记录。读取失败时，应说明最新状态未知，恢复后再查原对象。

![工作台页面通过任务 API 读取后台事实，组织提交进展结果和人工验收](assets/reading-figures-v3/00-overview.png)

先沿上方四步看人的操作，再沿下方找每条页面信息的来源：页面查询 API，API 读取后台记录。页面显示进度，不在浏览器里自行创造完成结论。图为教学示意。

[L13](../L13/README.md) 负责记录可查，本讲负责使用者能据此判断；[L15](../L15/README.md) 从真实使用困难出发，选择下一项小改进。

## 按这条路线学习

1. [辅导资料](辅导资料.md)：以采购查询断网为例，理解信息层级、迟到响应、旧动作失效和结果下载。
2. [实践操作手册](实践操作手册.md#lesson-goals)：在隔离工作台提交需求，进入实际候选修复，再对同一采购对象做页面、接口、数据库和规则核对。
3. [提交模板](SUBMISSION.md)：保留查询失败与恢复、产物身份、键盘与窄屏走查、同伴决定。

**本讲动作线：** 确认页面误判 → 工作台组织修复 → 原 Task 查进度与报告 → 查询失败时保留对象、停用旧动作 → 恢复后重查原单 → 实际采购与同伴复验。
