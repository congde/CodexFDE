# L15｜个人记忆集格式

回到[实践手册第 7 步](../实践操作手册.md#7-把一次经验登记为可治理-memory)。你提供真实经验、来源与审核决定，让 Codex 整理文件；你核对内容和边界。文件只保存个人练习材料，不直接写入生产工作台。

## Codex 怎样整理

沿用 [memory_rag_lab.py](../examples/memory_rag_lab.py) 已支持的 `codexfde.l15.memory-fixture/v1` 格式。顶层包含 `schema`、`memories` 和 `queries`。每条记忆使用下列结构；括号内容须由本次真实材料替换，不能照抄为证据：

```json
{
  "schema": "codexfde.l15.memory-fixture/v1",
  "memories": [
    {
      "memory_id": "〈个人记忆编号〉",
      "version": 1,
      "project": "FlowERP",
      "status": "candidate",
      "title": "〈经验标题〉",
      "content": "〈基于真实修复得出的经验〉",
      "applies_when": "〈可以沿用的条件〉",
      "not_when": "〈需要重新确认的条件〉",
      "tags": ["〈相关关键词〉"],
      "source": {
        "initiative_id": "〈来源事项编号〉",
        "task_id": "〈第 5 步实际修复 Task ID〉",
        "evidence_refs": ["〈可读取的原始证据绝对路径〉"],
        "evidence_sha256": ["〈对应原始文件的实际 SHA-256〉"],
        "reviewed_by": null,
        "reviewed_at": null
      }
    }
  ],
  "queries": [
    {
      "query_id": "Q-PERSONAL-01",
      "project": "FlowERP",
      "query": "〈下一事项的真实问题〉",
      "relevant": ["〈本人在运行前判断有关的 memory_id〉"]
    }
  ]
}
```

`version` 使用这条经验的实际版本。先保存 `candidate`；实际责任人核对来源、适用边界和隐私后，记录真实审核者与时间，再将这一版改为 `active`。审核尚未完成时保持 `candidate`，正常查询会把它排除。新版审核通过并取代旧版后，把旧版状态改为 `superseded`；撤回时改为 `revoked`，保留原文与理由。脚本只按状态筛选，不会因版本号增加而自动停用旧版。`source` 中的审核信息、证据指纹以及替代/撤回理由由人与 Codex 核对；教学脚本不会认证审核者或核验这些源文件。

`queries` 至少保留一条个人查询，运行前由你确认 `relevant`。对确无合格经验的新问题，填空列表 `[]`；不要看结果后倒填预期。可另外保存撤回条目与跨项目反例，保留真实来源或注明是故障实验构造，不能冒充实际使用经验。

## 怎样使用

保存到自己的练习目录，记录文件绝对路径。查询和评测都显式传 `--fixture`；不传时脚本读取课程的 [memory_rag_fixture.json](../examples/memory_rag_fixture.json)，不会读取这份个人文件。

查询返回的 `memory_ref` 采用 `memory_id@v版本`，例如你的编号后接 `@v1`。回查它的 `source.task_id`、原始证据与适用条件，确认来自第 5～6 步的实际修复，再决定是否用于后一事项。命中只说明检索找到了材料；后续仍须独立实现、复验与具名审核。
