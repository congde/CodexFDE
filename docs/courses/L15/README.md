# L15｜生成交付摘要并采集真实反馈

**本讲完成两件相连的事：根据真实反馈交付一项小改进，再把已审核的经验用于另一项新需求。**工作台组织摘要、反馈、经验检索与人的决定；FlowERP 的实际结果检验这些做法是否有用。

贯穿案例是库存空 CSV 缺少列名，修复后提炼经验，供销售导出借鉴。案例用于理解方法；实践从自己的 L14 任务继续，选择当前尚未解决的真实问题。

## 按这条路线学习

| 顺序 | 打开什么 | 这一段解决什么 |
|---|---|---|
| 1 | [辅导资料](辅导资料.md) | 理解反馈怎样变成明确需求，经验怎样检索、采用与重新验证 |
| 2 | [实践操作手册](实践操作手册.md#lesson-goals)第 1～6 步 | 从原任务导出摘要，调查反馈，完成事项 A 的小修复与独立复验 |
| 3 | 手册第 7～10 步 | 保存 A 的个人经验，在事项 B 检索、决定采用并交付，再回收效果 |
| 4 | [提交模板](SUBMISSION.md) | 随操作保留首次判断、失败、修订、具名决定与迁移证据 |

开始前准备自己的 L14 Task ID、原工作台运行目录和独立 FlowERP 项目。变量与路径按手册填写；遇到解释器、目录或退出码问题，先查[执行与排错说明](../../reference/实操手册执行与排错.md)。

**完成判断：**能从 B 的新结果回查采用决定、记忆版本及 A 的真实来源；A 和 B 都有各自的需求、检查与人的决定。只生成摘要、保存经验或得到一次检索命中，仍需继续完成后续步骤。
