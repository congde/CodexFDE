# L12｜用 Graph 显式表达状态、回退和人工审核

**FDE 判断提示**：这次采购入库等待的是哪种批准，由谁负责，为什么等待或打回是当前合理结果？执行前保留自己的理由，交接时用产品前后状态说明判断是否成立。详见[实践手册](实践操作手册.md)。

Codex 协助实现状态图、测试和修订；学生确定转移与失败语义；交付审核人接受软件候选，业务审批人批准采购单据。FlowERP 增量为审批后入库；采购状态与库存可能不一致，推动工作台建设显式转移、恢复、对账和具名人审。

按[实践手册](实践操作手册.md)完成，在[提交模板](SUBMISSION.md)保留：

1. 两套状态与审核对象、首次业务预期和转移设计。
2. 控制实验与真实采购实验的输出、五表阶段快照，区分教学报告和实际业务失败。
3. 个人 Graph 的真实动作、输入输出、允许边、保存与恢复机制。
4. 等待、恢复、具名批准、打回、预算停止及异常材料。
5. 未审批拒绝、正常入库、同键重放、部分写入和键冲突复验。
6. 候选、报告与审核依据的对应，以及同伴回查。
7. 状态移交 Skill 的真实反例响应和发布流程迁移。

## 自查

| 判断 | 足够的证据 | 不足的证据 |
|---|---|---|
| 状态图执行了开发 | 实际受限执行、Diff 与后置 Eval | 轨迹写了 develop |
| 人审有效 | 真实决定者、对象、报告与时间 | 非空姓名字符串 |
| 采购完成入库 | 业务批准、received、+7 流水与 17／2／15 | 单据标签变化 |
| 异常可接续 | 原错误、最后可靠状态与待办 | 吞掉异常后返回成功 |
| 恢复不重复写入 | 相同业务身份的重试与前后状态 | 仅发现文件存在 |
| 工作台跨事项复用 | 来源、召回、版本采用、Eval、人审和失败治理 | 状态或资产登记 |

本讲对应 CLO-5。比较首次设计、反例后的修订、实际移交与同伴反馈，不用参考仓库或模型自述替代学生达成。用外部框架替换最小 Graph 属于挑战，输入、输出和验收仍保持一致。

## 正式合同

- **核心内容**：共享状态、条件分支、审核打回、异常路径和人工介入；原生 Subagents 与外部编排框架的边界。
- **演示结果**：开发 → 测试 → 审核；审核失败回到开发，关键决策等待人工确认。
- **课内增量**：用最小 Python 状态图实现移交、回退、状态保存和审核结论。
- **验收命令**：`python -X utf8 -m agent.graph --max-rounds 3`
- **通过标准**：状态变化可追踪；审核结果来自 Eval；循环有上限；异常不会被静默忽略。
