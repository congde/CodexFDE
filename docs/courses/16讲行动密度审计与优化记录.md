# 16 讲行动密度审计与优化记录

> 审计日期：2026-08-19。本文记录课程设计是否具备足够的学生实作密度，不是学生学习数据，也不证明课程已经取得教学成效。课程合同仍以 `docs/课程大纲-Codex-FDE行动营-个人研发自动化工作台.md` 为准。

## 一、付费行动课的六条硬门

每讲必须同时满足以下条件，否则即使正文完整、参考仓库可运行，也只能算资料课或演示课：

1. **学生亲手构造**：至少产生一个本讲独有的代码、配置、合同、状态、报告或法证对象，不能只填写听课笔记；
2. **主动制造失败**：失败由学生或同伴在隔离环境触发，保留首次判断、失败事实和修订前后；
3. **因果边界清楚**：能说明哪个改动改变了哪个证据，禁止同时修改问题、实现和裁判后宣称成功；
4. **陌生人可复验**：至少有一次同伴反证、盲测、换进程、换环境或作者退场；
5. **能力能够迁移**：至少指出通用工作台能力与 FlowERP 特定适配，必要时用第二需求/仓库/报告验证；
6. **双增量真实发生**：L01～L04 建成 Workbench V0；L05 起 ERP 必须形成可观察增量或真实修复，同时主要评价工作台能力、因果证据和学生判断，不能只数 ERP 功能；**FlowERP 不抢主线**。

“观看讲师运行”“复制参考答案”“最终全绿截图”“Agent 自述完成”“已有仓库实现”均不能独立满足任何一条硬门。

## 二、逐讲行动密度合同

| 讲次 | 学员必须亲手构造 | 必须触发的失败/反证 | 工作台沉淀 | FlowERP 产品状态 | 迁移或陌生人证据 |
|---|---|---|---|---|---|
| L01 | 环境指纹、命令证据账、四段式接手报告 | 未运行命令被写成已验证，或运行成功被夸大为发布完成 | 仓库接手协议与完成等级判定 | 建立基线快照和产品能力地图，业务账不变 | 同伴冷复现；个人仓库差异报告 |
| L02 | 根/就近规则补丁、DoD、四张对抗卡 | 过宽规则误伤合法任务；局部规则放宽上层底线 | 分层项目规则与跨会话验证 | 固化主数据/库存/订单/采购边界，业务账不变 | 非 FlowERP 仓库规则正反验证 |
| L03 | Spec Schema、解析器、来源记录、用例矩阵 | 缺字段结构失败；结构完整但语义错误 | 可执行 Spec 与评审协议 | 库存导出合同签字，L04 实现 | 跨组盲复述；第二需求差异表 |
| L04 | 能力信封、受控执行、边界测试、Diff 审查 | 白名单外写入或无关重构被阻断/退回 | 最小权限执行入口、最小 Eval 与结果采集 | 交付库存导出首个增量 | 非执行者复验；第二 Spec 授权设计 |
| L05 | 缺陷夹具、业务/工程 Eval、红绿记录 | 同一缺陷稳定红两次；断言放水攻击 | 失败优先 Eval 协议与失败签名 | 交付幂等入库 | 第二规则的先红设计；同伴攻击裁判 |
| L06 | Harness、报告 Schema、退出码、消费者 | observing、blocking、error、报告写入失败 | 统一机器判决与消费者合同 | 交付可用库存口径 | 非 FlowERP 命名报告/第二项目兼容验证 |
| L07 | Hook 配置/处理器、事件夹具、信任审计 | 协议污染、重入、畸形输入或超时 | 生命周期护栏与协议控制 | 交付销售订单创建 | 非 ERP 风险的触发点选择 |
| L08 | 门禁 Spec、Workflow、Evidence Envelope、A/B/C Run | `report=block` 但 Job 假绿；失败失明 | 可信远程门禁、身份与失败归档 | 交付整单原子预占 | 非 FlowERP 报告夹具；同伴法证 |
| L09 | Repair Task Schema/映射器、时效与来源校验 | observing 误纳、过期报告、日志提示注入 | 失败事实到最小修复授权的映射 | 修复订单取消释放预占 | 非 ERP 报告迁移；陌生修复者盲复述 |
| L10 | Loop 控制器、失败签名、预算、History | 无进展、振荡、新回归、超时、用量未知/耗尽 | 有界循环、停止语义和安全交接 | 修复订单状态迁移 | 为不应自动修复任务写禁止启动判决 |
| L11 | 读写集/冲突图、子任务合同、并行原始输出 | 无引用结论、重复发现、分歧或写冲突 | 调度判断、上下文隔离和净收益度量 | 并行分析、串行集成采购申请 | 单 Agent 基线；个人项目冲突图 |
| L12 | 状态/边/守卫、Graph、checkpoint、Trace | 匿名、重复、非法边、上限与崩溃恢复 | 可恢复编排和具名 HITL | 交付采购审批后入库 | 换人换进程审核；第二流程过度设计判断 |
| L13 | Task API、持久化、错误合同、并发测试 | 双领取/双审核、非法迁移、重启丢失 | 通用任务资源和原子状态迁移 | API 提交并完成补货交付 | 第二类长任务的身份/幂等/冲突合同 |
| L14 | 状态合同、真实 UI、轮询/错误/可访问性、四方对账 | 断网旧绿灯、未知状态、字段漂移 | 可信状态投影与证据下钻 | 交付 ERP 操作页和任务证据下钻 | 陌生人走查；第二长任务字段适配 |
| L15 | 摘要导出、反馈状态机、审核与隐私测试 | 原文覆盖、不可追溯摘要、反馈直达 blocking | 摘要/反馈治理和改进候选入口 | 独立 Task 交付反馈驱动改进 | 第二反馈源；独立后序验证计划 |
| L16 | 空环境启动、证据索引、恢复/回滚、五分钟答辩 | 隐式依赖、正确失败、口头补步骤、旧数据污染 | 可启动、可质疑、可恢复、可交接的完整工作台 | 现场抽取并交付一个新小需求 | 作者退场、随机抽题、陌生评审者独立复现 |

## 三、讲师备课验收

每讲录制或开课前，讲师逐项签字：

- [ ] 学员起点不是完整答案，且失败夹具可稳定复现；
- [ ] 线上 30 分钟只建立问题框架、关键示范和安全边界，完整工单在线下完成；
- [ ] 学员独有产物与上一讲、下一讲输入清楚，不以通用反思充数；
- [ ] 本讲 ERP 权威状态有明确前后变化或受保护不变状态，且该变化用于触发/验证对应工作台能力；
- [ ] 形成性评价保留首次判断、失败、修订和同伴意见；
- [ ] 迁移任务能检出硬编码 FlowERP 字段、角色、路径或业务术语；
- [ ] 没有真实远程、并发、重启、人审或用户反馈条件时，相关结果标“待补”，不使用模拟证据补齐。

每期教学后才可填入真实完成率、错误分布、修订增值和迁移表现；本设计审计不得冒充上述教学效果。
