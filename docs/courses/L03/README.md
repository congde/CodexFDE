# L03｜把模糊需求变成可验收 Spec

“导出一张库存表”还缺哪些说明，别人才能做对？本讲先商量表里写什么、数字怎么算、出错怎么办，再把约定整理成固定格式，让工作台能读出每一部分。

这份本次任务的要求说明叫 Spec。读取并检查它格式的程序叫解析器；本讲只检查说明是否完整、结构是否正确，库存导出功能到 L04 才实现。

| 起点 | 本讲新增 | 交给 L04 |
|---|---|---|
| L01 的记录能力和 L02 的长期规则 | 六段 Spec 模板、检查章节与内容的解析器 | 本人确认的库存导出 `FDE_SPEC.md`、设计依据和实际结构检查结果 |

1. [辅导资料](辅导资料.md)：沿两仓库存例，理解业务口径、局部分工和六段合同。
2. [实践操作手册](实践操作手册.md)：先保存首次判断，访谈并修订合同，再抽取模板、实现解析器、用三份输入复验。
3. [SUBMISSION 提交索引](SUBMISSION.md)：关联初稿、同伴歧义、修订稿与检查；用同一确认版交接。

**本讲的推进：** L01 为一个任务手工写清要求；今天把这套做法抽成可复用模板，并让工作台准确读出六段原文。库存导出代码由 L04 按确认合同实现。

个人材料放在自己的 `lesson-03-submission/`；已有记录继续追加，示例与课程参考结果不代替本人证据。

按需材料：

- `examples/` 保存 Spec 对照样例与按需审查 Skill，按手册进度使用。
- `assets/` 为正文配图及来源记录，随正文查看。
- [reference/参考说明](reference/参考说明.md) 提供深层参考与历史索引，完成主线后按需查看。
- [唯一课堂课件](L03-把模糊需求变成可验收Spec-课堂重建版-架构与设计思想.pptx) 随课堂使用，操作以当前手册为准；历史版本已归档。
