# 前 5 讲出版级样章审校表

> 用途：把 L01～L05 从“完整课程设计文件”改造成“学生可以连续阅读并当场行动的教材样章”。课程合同不变，旧有量规、教师活动和技术索引保留在折叠附录中。

## 一、正文与附录必须分开

学生正文只保留六类内容：真实场景、人物决定、案例展品、调查动作、证据解释、结果回到故事。CLO、学时、持续改进指标、讲师门槛、评分细表、完整参考索引全部进入附录。

如果一段话主要回答“教师为什么这样设计”，它属于附录；如果主要回答“学生现在看见什么、要决定什么、怎样取得证据”，它属于正文。

## 二、每篇样章的阅读节奏

1. **冷开场**：用具体时间、地点和损失开始，不解释术语。
2. **第一次签字**：学生在信息不完整时给出批准、拒绝或补证决定。
3. **展品调查**：页面、日志、命令、Diff 或数据库状态逐项出现，每个展品同时写明证明边界。
4. **错误路线**：至少展示一个当时看起来合理、最终会伤害交付的选择。
5. **概念命名**：学生先感受到问题后，才引入 Spec、Eval、Harness 等名称。
6. **第二次签字**：学生依据新证据修订判断，保留修订理由。
7. **现场结果**：明确 FlowERP 产品状态、工作台能力和仍未解决的矛盾。

## 三、反清单规则

- 连续出现三个以上名词时，改写成一次行动和后果。
- 连续出现五个以上步骤时，先说明谁在什么压力下执行，以及失败会损失什么。
- 表格只用于比较证据、状态或方案，不承担连续叙事。
- 命令前必须说明为什么现在运行，命令后必须说明结果改变了什么判断。
- 代码片段只展示决定业务结果的最小部分；其余通过文件链接和定位命令进入附录。
- 每个技术名词首次出现时，必须对应一个故事中的损失、责任人和可观察信号。
- “理解、掌握、熟悉、了解”不能作为学生正文的主要动词。

## 四、样章最低门槛

| 检查项 | 发布门槛 |
|---|---|
| 连续人物 | 林默和至少一名业务/质量角色发生目标冲突 |
| 两次判断 | 操作前首次决定 + 证据后修订决定 |
| 真实展品 | 至少一张项目图和一段真实命令、日志或代码 |
| 错误路线 | 至少一个“看似合理但会伤害交付”的方案 |
| 证明边界 | 每项展品说明能证明什么、不能证明什么 |
| 现场闭环 | 写清产品状态、工作台增量、下一讲未决问题 |
| 附录降噪 | 教师治理与大段索引默认折叠 |

## 五、前 5 讲的编辑焦点

| 讲次 | 学生应该记住的一个场面 | 技术只有在何时出现 |
|---:|---|---|
| L01 | 十点客户会前，拒绝给绿色页面签收 | 当学生需要区分四种“完成”并取得仓库证据时 |
| L02 | 运营要求十分钟直接改审批状态 | 当一次会话判断无法保护下一次会话时 |
| L03 | 三个部门对“可用库存”各有一套口径 | 当猜测即将被写成永久验收规则时 |
| L04 | Agent 提议顺手建设通用报表框架 | 当学生必须控制仓库钥匙和变更半径时 |
| L05 | 网络重试让同一批货入账两次 | 当正常测试无法证明重放安全时 |

## 六、审校顺序

先让一名不熟悉项目的人只读学生正文，记录他在哪里停止、哪里需要翻附录、哪里在答案揭示前已经被技术名词暗示。再让第二名复验者执行命令并核对证据。最后才检查课程合同、CLO 和评分量规是否完整。

如果学生必须先理解整套工作台架构才能开始第一项动作，样章仍然不合格；如果学生做完动作却说不清为什么改变判断，同样不合格。
