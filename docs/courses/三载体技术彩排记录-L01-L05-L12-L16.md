# 三载体技术彩排记录｜L01、L05、L12、L16

> 记录日期：2026-09-01
> 记录性质：课程团队的桌面技术彩排，不是真实学生试讲，不计入学生学习证据、CLO 达成率或教学效果。学生首次/二次提交、求助点、典型误判与增值数据均须在真实开课后另行采集。

## 一、彩排范围与判定标准

本轮覆盖四种代表场景：L01 陌生系统接手、L05 失败优先 Eval、L12 Graph 与人工责任、L16 冷启动现场交付。每讲依次核对：

1. 独立 PPTX 是否在方法答案出现前收取第一次签字；
2. Markdown 是否能独立解释事故、方法、失败路径和第二次签字；
3. VS Code 统一任务入口是否给出与机器合同一致的结果和退出码；
4. 技术失败是否被诚实阻断，且没有被旧绿灯或教师口头解释伪装成通过；
5. 哪些结论已经由仓库证据验证，哪些必须等待真实学生参与。

## 二、发现并修复的问题

### 1. L01 第一次签字出现过晚

初版 L01 把第一次签字放在第 11 页，学生会先看到证据和方法再作答，违反“PPT 第一次签字 → Markdown 查证 → VS Code 行动 → Markdown 第二次签字”的顺序。现已将第一次签字提前到第 4 页，形成“事故现场 → 冲突 → 第一次签字 → 查证”的节奏。

### 2. 16 讲签字问题过于通用

初版问题不能充分形成逐讲分歧，部分提示语还会提前暴露判断方向。现已为每讲设置三道专属裁决题，并把辅助提示统一改为“当前判断与证据需求、反证条件与不变状态、最大风险与责任边界”。16 张第一次签字页内容互不重复。

### 3. 课程合同仍保留“四页上限”旧表述

正式发布物已经是 16 个独立 PPTX，每讲 11～15 页，但母稿仍写着“16 讲 × 4 页，共 64 页”。现已把四个条目重新定义为核心决策节点，而非页数合同；正式课件每讲页数不设统一上限，以讲清冲突、方法、证据和行动为准。

## 三、四讲技术彩排结果

| 讲次 | PPT 决策顺序 | Markdown 独立解释 | VS Code / 机器入口 | 技术结论 |
|---|---|---|---|---|
| L01 | 第 4 页第一次签字；第 12 页切换 VS Code 并提示第二次签字 | 学员正文提供四层完成状态、只读调查、AI 报告复核和第二次签字 | `course-contract --lesson 1` 与 `course-spec --lesson 1` 退出码 0；`course-eval --lesson 1` 退出码 2，并明确“没有可复用代码 Eval” | 非代码接手课不能用终态代码 Eval 冒充个人验收活动，阻断符合合同 |
| L05 | 第 3 页第一次签字；第 13 页行动交接 | 学员正文提供两次稳定红灯、幂等反例、最小修复和 Failure-first Record | 合同、Spec、单例 Eval 均退出码 0；`receiving_is_idempotent` 1/1 通过；verify-only 明示“不计实现证据” | 统一入口可复验终态能力，但真实学生仍须保存自己基线上的红→绿 |
| L12 | 第 4 页第一次签字；第 13 页行动交接 | 学员正文区分 Graph、ERP、证据与具名审核状态，并提供打回、匿名失败和崩溃恢复路径 | 合同、Spec、两项 Eval 均退出码 0；`purchase_requires_approval` 与 `receiving_is_idempotent` 2/2 通过；Task 停在 `review` | 全绿不会自动批准采购，具名人工责任仍保留 |
| L16 | 第 2 页第一次签字；第 15 页行动交接 | 学员正文要求现场抽题、动态 case、会话红基线、发布证据索引和第二次签字 | 合同入口退出码 0；缺少 `--eval-case` 时 Spec、Eval、verify-only 均退出码 2 | 未现场抽题时必须拒绝生成“结业成功”；本轮没有用虚构需求绕过门闩 |

## 五、真实开课必须补采的数据

以下项目在本轮只能标记为“待真实开课采集”，不得由教师彩排、仓库测试或模拟数据补齐：

- 学生在第一次签字时是否真的形成分歧；
- 学生在看答案前写下的选择、依据和最大风险；
- 陌生学生能否不依赖讲师口头补充完成 VS Code 任务；
- 学生在哪一步求助、误判、绕过失败或误读权威状态；
- 第二次签字是否引用了新证据，以及判断改变的原因；
- 首次/二次提交变化、CLO 达成率、不同起点学生增值和典型误区。

建议真实试讲时为每位学生分配匿名编号，保留首次与二次版本，记录时间点、求助类型、失败证据 ID 和签字依据；涉及学生作品、截图和日志时先取得授权并去除个人敏感信息。

## 六、下一轮试讲动作

1. 由未参与课件制作的教师或助教按任务卡主持 L01、L05、L12、L16；制作人只观察，不补充隐含步骤。
2. 每讲先收齐第一次签字，再开放 Markdown；未收齐前不展示方法解释页。
3. L16 现场抽取仓库基线中尚未实现的小需求，并现场命名新增 Eval；没有动态 case 和会话红基线时直接判为未开始。
4. 课后将真实问题回写到讲义、任务卡、PPT 或工作台，但保留原始失败记录和修改前版本。
