# L10｜建立有停止条件的修复 Loop

**FDE 判断提示**：订单状态问题影响哪项发货操作，继续一轮能获得什么新证据，什么条件下应交回人处理？执行前保留自己的理由，交接时用产品前后状态说明判断是否成立。详见[实践手册](实践操作手册.md)。

本讲交付有停止条件的修复 Loop，并用 FlowERP 合法发货与非法状态拒绝检验它。人决定目标、范围与预算，Codex 修复，Harness 独立复验，同伴核对停止依据。

按照[手册](实践操作手册.md)执行，在[提交模板](SUBMISSION.md)记录：

| 阶段 | 关键动作 | 证据 |
|---|---|---|
| 预测 | 说明轮数含义、发货前后数量、停止规则 | 首次设计 |
| 控制实验 | 12 类输入观察真实 Loop | 合成来源、轨迹、实际解释 |
| 业务实验 | 合法与三种拒绝，反证全部拒绝 | 实际临时库报告 |
| 同案实验 | 三条真实候选轨迹：修复、不改动、末轮修复 | 逐轮报告、实际 Diff、循环内外计数 |
| 实现 | 工作台组织状态修复与 Loop 建设 | 本人 Spec、任务号、范围、Diff |
| 执行 | 真实收敛与未收敛轨迹 | 前失败、实际执行、后检查、停止原因 |
| 复核 | 区分旧报告、待复验与真剩余失败 | 同伴反馈、修订、接受决定 |
| 提炼 | 使用审查 Skill 并迁移方法 | 实际响应与后续采用 |

控制替身不是真实 Codex，合成用量不是真实消耗。默认 Loop 不调用 Codex；末轮修改可能待复验；三轮到头不等于业务通过。合法发货还要保留 OTHER，不能用拒绝全部动作制造绿灯。

## 大纲合同

- **核心内容**：最大轮数、达标即停、无进展检测、时间与 Token 预算、安全退出。
- **演示结果**：修复循环成功收敛一次，并展示一次未收敛退出。
- **课内增量**：串联“执行 → Eval → 生成修复任务 → 再执行”。
- **验收命令**：`python -X utf8 -m agent.loop --max-rounds 3`
- **通过标准**：最多三轮；达标即停止；无进展或预算耗尽时输出剩余失败，不宣称成功。

[同案实验](examples/candidate_loop_lab.py)由预设补丁修改复制的服务，调用真实 Harness 与 Loop；它补足代码与报告的对应关系，但没有调用 Codex，也不提供真实 Token 证据。
