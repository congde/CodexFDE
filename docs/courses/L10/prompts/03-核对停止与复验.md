# 复核实际 Loop 轨迹

从原报告、候选和每轮执行材料重新计算检查次数与修复次数。核对停止时哪份版本已经验证，哪些修改尚待复验。不能仅根据状态字段接受结论。

检查同名失败原因是否变化、A/B/A 是否反复、预算是否曾越界、用量是否来自真实事件。检查异常后原报告、已发生修改与未完成动作是否可查。控制替身与真实模型调用分开标注。

复验合法发货与 OTHER 保护，补查重复或取消后发货的拒绝状态。指出真实证据支持的接受范围与缺口，不生成他人签字，不把未收敛改写为成功。

先按时间重建检查、执行与循环外审计。识别报告对应的代码内容，核对执行器实际命令；参数名、占位 Token 和外部绿灯均不能替代真实模型调用或内部收敛。错误版本的重复发货用例若在首次发货阶段失败，应明确尚未检验重复拒绝。
