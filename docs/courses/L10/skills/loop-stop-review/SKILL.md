# 审查循环停止结论

读取任务约定、候选身份、各次原始报告、执行输出、改动和资源记录。先区分真实模型执行、预设补丁子进程、控制替身与起点已绿；合成用量不能用于实际预算证明。

按约定重建检查次数与执行次数。确认报告有效且覆盖独立要求；空列表不证明通过。定位停止前最后一次检查对应的候选，若随后仍有修改，保留待复验，不将旧失败当成新状态。

核对停止原因与顺序。失败名称相同可能原因变化，名称交替也可能循环退步。预算剩余归零不证明没有超额；缺失用量和时间范围不明时说明核算缺口。

检查异常后已有改动、最后已知报告和未完成动作能否查回，以及各写入者是否覆盖历史。提示词约束或 workspace-write 不自动等于逐文件写集。

业务上同时检查合法路径和拒绝后状态。对“全部拒绝使反例通过”的方案指出正常用途损失。输出具体证据、缺口与下一步建议，不代替负责人接受，不自动继续执行或扩大预算。

需要验证审查行为时使用[四个反例](references/review-cases.md)，保留实际响应与本人修订。

对配套[候选轨迹](../../assets/latest/candidate-last-repair/index.json)，把循环外审计单独计数。`use_codex=True` 不能独立证明调用了 Codex，应核对注入的执行器及子进程命令；协议占位用量不是实际 Token。根据原报告和 Diff 判断产品状态，不因 Loop 状态名称而重写发生顺序。
