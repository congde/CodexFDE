# L04｜委托 Codex 执行一次最小变更

写好了要求，怎样请 Codex 做出来，又能查清它实际改了什么？本讲先给工作台补上安排执行和检查的能力，交给另一位复验者确认，再用它完成 L03 约定的库存导出。

手册把两件事记为任务单（Ticket）A 和 B：A 建工具，B 用工具做导出。允许修改的文件叫写集，实际修改的对照叫 Diff；软件检查叫 Eval，检查之后仍由人决定接受。

| 起点 | 本讲新增 | 交给 L05 |
|---|---|---|
| 任务记录、长期规则、确认版 Spec 与解析器 | 工作台 V0：受控调用、写集检查、最小 Eval、结果摘要与审核入口 | 已独立接受的 V0，以及由它交付、另有复验与人审依据的库存导出 |

1. [辅导资料](辅导资料.md)：看懂两张任务单的分工，以及目录、允许文件、报告版本怎样限制执行。
2. [实践操作手册](实践操作手册.md)：第 1～4 步建设并接受 A；第 5～7 步才通过 A 执行、复验和审核 B。
3. [SUBMISSION 提交索引](SUBMISSION.md)：沿 A → B → 实际候选 → 报告 → 具名决定核对交接。

**两张任务单：** Ticket A 建工作台，由你直接监督 Codex；A 被非执行者接受后，Ticket B 由工作台组织人与 Codex 交付 FlowERP。B 有自己的检查与接受决定。

个人材料放在自己的 `lesson-04-submission/`；已有记录继续追加，示例与课程参考结果不代替本人证据。

按需材料：

- `scripts/` 保留库存交付检查脚本；`examples/` 保存按需交接 Skill，按手册调用。
- `assets/` 为正文配图及来源记录，随正文查看。
- [reference/参考说明](reference/参考说明.md) 提供深层参考与历史索引，完成主线后按需查看。
- [唯一课堂课件](L04-委托Codex执行一次最小变更.pptx) 随课堂使用，操作以当前手册为准；历史版本已归档。
