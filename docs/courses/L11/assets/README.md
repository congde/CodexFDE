# L11 图示与实际运行证据

`diagrams/` 保留四幅机制图。它们解释业务状态、依赖、整合与成本；箭头不是活动记录，分钟数是教学算例。

`latest/integration/` 是[同版整合实验](../examples/integration_lab.py)的一次实际运行记录。实验复制入门 ERP 服务与真实 Harness，在采购申请后注入提前入库，再移除该动作；原仓库服务未修改。三个顺序进程分别验证：

| 目录 | 实际结果 | 支持的判断 |
|---|---|---|
| 01-partial-v1 | 原采购检查 1/1 通过 | 当前字段和部分非法输入检查通过 |
| 02-complete-v1 | 独立检查 5/6 通过 | 同一 V1 正常申请会把库存从 10 增至 17 |
| 03-integrated-v2 | 原检查与独立检查 7/7 通过 | 移除提前入库后，正常申请不改变库存；五种拒绝后五表不变 |

每次 `process.json` 保存实际命令、退出码、服务与检查文件 SHA-256；`report.json` 保存完整报告。后两次 `states/` 保存逐用例的五表前后状态。固定夹具直接写入既有 PR-OTHER；被检验的目标动作调用真实 `propose_purchase`。测试内容在三次运行中不变；原检查的函数正文从当前仓库提取，隔离环境只移除课程能力门闩，不据此声称课程构造已完成。

`injected.diff` 与 `restored.diff` 分别保存教师注入及恢复。公开材料不包含运行数据库和整份候选副本；按新运行目录可以重新构造。

三张 HTML/PNG 截图由上述真实记录排版：`partial-green` 解释同版不同覆盖，`integrated-green` 解释实际修复，`trace-claims` 说明如何回查。它们不是原生工作台或子代理界面。实验顺序运行，没有原生子代理、模型修复、真实 Token、并行提效或具名接受证据；原生协作仍按实践手册保存独立活动记录。
