## 1 首次判断与业务合同

本讲 FDE 问题：采购申请涉及哪些业务与研发职责，哪两项工作确实独立，为什么本次值得并行？

- 问题来源及影响对象（实际观察／同伴试用／教学设置）：教学设置。采购申请会影响采购业务人员、库存数据的使用者，以及负责业务实现、测试、风险审查和最终整合的研发角色。
- 本人的范围选择、暂缓项和理由；业务口径由谁确认：选择让子代理甲补独立测试、子代理乙只读检查业务风险；两者使用同一份固定输入，且不读取对方正在变化的产物。暂缓业务代码修改和最终接受决定，待两项结果返回后由主 Agent 串行整合、统一复验，并由实际负责人确认业务口径。并行不预设更快，后续记录任务划分、执行和合并的实际耗时。

后文已有的失败、修订、复验和迁移记录承接此判断，不重复填写。

保存实验前答案，修订另写，不覆盖：

- 采购申请成功以后哪些数据变化，哪些不变？首次判断：新增并保存采购申请；商品库存、库存流水、订单和订单明细不应变化。
- 主 Agent 修改业务实现时，测试与风险任务能否独立进行？首次判断：不能一边修改共同输入一边并行读取。先固定业务实现；测试任务只写独立测试文件，风险任务只读固定实现，主 Agent 等两者完成后再修改业务代码。
- 两个局部结果都通过，为什么仍要整合后检查？首次判断：局部结果可能覆盖范围不同、输入版本不同或遗漏隐藏的共享资源；必须在同一整合版本上统一复验。
- PR-TARGET 的身份、重复请求、单位与失败语义如何约定？首次判断：以 Spec 和后续业务实验为准；在核对前不自行补造重复请求、数量单位和异常返回语义。
