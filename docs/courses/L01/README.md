# L01｜以终为始：一次可验证的 AI 交付怎样完成？

**昨天 Codex 做了什么，今天还能查清吗？**本讲从这个困难出发，建设能保存需求、任务和检查记录的工作台 V0.1，再用它记录自己的建设。

| 起点 | 本讲新增 | 交给 L02 |
|---|---|---|
| L00 准备好的环境与个人工作台壳：已有首页、健康检查与壳测试，五个账本操作尚未建设 | 在同一项目签署需求、形成测试，开发初始化、项目登记、任务账、命令证据账和状态查询 | 可重启查回的工作台及自身建设记录；原启动入口保留，FlowERP 尚未接入 |

**先选定个人项目：**已有工作台壳，按手册 [A 路径接续](实践操作手册.md#continue-shell)；尚无个人项目，按 [B 路径使用课程已提供的壳](实践操作手册.md#provided-shell)，建立初始版本后继续。从零搭建是 [L00 参考选做](../L00/从0开始搭建个人AI研发工作台.md)，无需先完成它才能学本讲。

1. [辅导资料](辅导资料.md)：跟着“隔天接手”案例，理解需要保存什么、怎样检查保存可靠。
2. [实践操作手册](实践操作手册.md)：在选定的个人项目中完成访谈、红灯、实现、复验和自举；每步都有对应提示词与排错。
3. [SUBMISSION 提交索引](SUBMISSION.md)：引用自己的决定、版本、失败和复验，交接给下一讲。

**贯穿本讲的检查：**创建任务 → 退出程序 → 改动外部需求文件 → 新进程查回原需求和失败记录。先确认测试能抓住缺失能力，再实现并复验。

个人材料放在自己的 `lesson-01-submission/`；已有记录继续追加，示例与课程参考结果不代替本人证据。

按需材料：

- [WORKBENCH_SPEC.md](WORKBENCH_SPEC.md) 是未签署教学样稿。个人合同在自己的隔离区形成并由本人签署。
- `tools/` 是手册调用的证据采集与导入工具，保留原路径。
- macOS 使用手册相应代码块；重开终端从原隔离记录恢复，不重建练习区。
- `assets/` 为正文配图及来源记录，随正文查看。
- [reference/参考说明](reference/参考说明.md) 提供深层参考与历史索引，完成主线后按需查看。
- [唯一课堂课件](L01-以终为始-极客时间实操演示版.pptx) 随课堂使用，操作以当前手册为准；历史版本已归档。
