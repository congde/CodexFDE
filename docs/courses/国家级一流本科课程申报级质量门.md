# 国家级一流本科课程申报级质量门

> 核验日期：2026-08-31。本文件是建设台账，不是申报资格证明、认定结论或教学成效报告。正式申报必须以当批次教育部通知、申报工作网模板和学校要求为准。

## 一、结论先行

当前项目已经具备较完整的**课程设计基线和技术实践环境**，但尚未达到可诚实声称“国家级一流本科课程申报就绪”的状态。主要缺口不在 Markdown 数量，而在学校资格、真实开课、两个教学周期、个人学习成果、改革效果、同行应用和审查材料。

申报准备按四级状态管理：

- `D 已设计`：课程合同、活动、量规、模板或技术基线已形成；
- `P 已试教`：存在一次真实教学运行和原始记录；
- `V 已验证`：至少两个真实教学周期按同一口径完成测量—改进—再测量；
- `A 申报就绪`：验证证据齐全，并经学校完成资格、政治、学术、质量、版权和安全审核。

技术测试通过只能支撑 D 级技术基线，不能自动提升为 P/V/A。

## 二、六道申报质量门

| Gate | 放行问题 | 当前可验证状态 | 必须补齐的证据 | 责任主体 | 当前判定 |
|---|---|---|---|---|---|
| G0 资格与类型 | 是否进入本科培养方案、设置学分并符合当批次申报类型 | 仓库无法证明 | 培养方案、课程编码、学分学时、开课单位、学校推荐与类型确认 | 学校/学院 | 红：待校方确认 |
| G1 课程设计 | 目标、内容、活动、评价是否一致，是否体现“两性一度” | 大纲、建设方案、讲义、任务卡和可执行合同已形成 | 校内专家审查、毕业要求映射、正式教学大纲审批 | 课程组/专业负责人 | 黄：D 级 |
| G2 教学运行 | 混合式教学是否真实发生，学生是否经历判断—失败—修订—迁移 | 仅有设计与参考实现，不等于学生经历 | 两期教学日历、平台记录、课堂观察、作业版本、诊所记录 | 主讲教师/平台管理员 | 红：未提供 |
| G3 学习成效 | 学生是否达成 CLO，改革是否带来增值 | 已定义 CLO、量规和计算规则，尚无真实数据 | 匿名成绩、CLO 计算、首次/二次提交、分层增值、未达成分析 | 课程组/评价者 | 红：未提供 |
| G4 示范与持续改进 | 是否形成可复用资源、同行采用和跨周期改进 | 仓库资源可共享，尚无真实采用证据 | 两周期改进闭环、同行评价、校内外采用、教师培训、五年计划 | 课程负责人/学院 | 红：待建设 |
| G5 诚信、审查与安全 | 政治、学术、版权、隐私、AI 使用和工程伦理是否受控 | 已有规则与证据模板，未完成学校审查 | 政治审查、学术审查、版权清单、学生授权、数据脱敏和平台安全报告 | 学校/课程组 | 红：待执行 |

只有 G0～G5 全部由相应责任主体签字放行，才能标记 A；课程组不能自行替学校放行。

## 三、课程设计质量检查

### G1-A 课程合同一致性

- [ ] 大纲是 16 讲标题、核心内容、演示结果、课内增量和通过标准的唯一事实源；
- [ ] 每讲同时写明 FlowERP 产品状态、工程问题、工作台能力、主要 CLO 和个人学习证据；
- [ ] L01～L04 形成 Workbench V0，L05～L15 不连续两讲保持 ERP 不变，L16 现场交付未实现小需求；
- [ ] 机器合同、详细讲义和任务卡与大纲一致；
- [ ] 稳定基础、当前增强和观察项分层，平台新功能不随意改写课程目标。

### G1-B 教学与评价一致性

- [ ] 每个 CLO 有直接评价任务、评分维度和达成规则；
- [ ] 线上精讲不超过 30 分钟，线下承担故障实验、反证、修订和迁移；
- [ ] 每讲保留首次判断、失败、反馈和二次提交；
- [ ] 有分层支架、支架撤除与无障碍替代方案；
- [ ] 课程思政由工程诚信、审批、数据安全和协作责任的真实行为评价。

### G1-C 技术与业务真实性

- [ ] FlowERP 权威状态来自 API/数据库/业务服务，不由静态页面或模型自述替代；
- [ ] 库存非负、幂等入库、订单状态、取消释放和采购审批都有正反用例；
- [ ] Eval 报告、退出码和任务状态一致，失败不能伪装成成功；
- [ ] 工作台和 FlowERP 边界清楚，前者不是 ERP 菜单，后者不是冻结演示壳；
- [ ] 开课前 `course-status --require-baselines` 通过，否则明确标注渐进基线待建设。

## 四、每个教学周期的证据清单

### 开课前

- 冻结课程版本、代码标签、环境矩阵、CLO—任务映射和量规；
- 保存入课诊断题、评分锚点和评价者校准记录；
- 完成数据最小化、学生授权、版权与安全说明；
- 检查 16 个起始基线和所有阻断 Eval，不用终态绿灯替代逐讲红→绿。

### 教学中

- 平台导出真实学习记录，不只保存视频发布截图；
- 每讲抽样保存首次判断、失败输出、修订 Diff、二次提交和反馈；
- 记录学生使用的支架、关键误区及其与诊断起点的关系；
- 具名记录同伴/教师评价，组队任务建立个人贡献索引；
- 密钥、数据库和学生敏感信息不进入公开仓库。

### 结课后

- 计算各 CLO 的有效样本、达成度、达成率和增值；
- 对核心作品抽样双评，报告分歧与复核结果；
- 形成“问题—证据—动作—负责人—下期复测”清单；
- 保存失败或无改善结论，不只选择正向案例；
- 由学校决定材料保存期限、访问权限和申报使用范围。

## 五、证据登记最小字段

| 字段 | 说明 |
|---|---|
| `evidence_id` | 跨报告稳定引用，不以截图文件名充当唯一身份 |
| `course_version` / `code_ref` | 对应课程版本和代码提交/标签 |
| `cohort` / `lesson` / `clo` | 教学周期、讲次和目标映射 |
| `student_key` | 匿名化标识，真实身份映射由学校安全保存 |
| `attempt` | 首次、二次或补充答辩，禁止覆盖历史 |
| `input` / `expected` / `actual` | 可复现输入、预期与实际结果 |
| `command` / `exit_code` / `state_ref` | 运行证据和权威状态引用 |
| `assessor` / `rubric_version` | 评价者与量规版本 |
| `ai_contribution` / `student_contribution` | AI 与学生贡献披露 |
| `feedback` / `revision_ref` | 反馈及修订版本引用 |
| `consent` / `visibility` / `retention` | 授权、可见范围和保存期限 |

## 六、一票否决与禁止替代

出现以下任一项时，不得写成申报成效或学生达成：

1. 用模拟学生、教师自演、参考仓库测试或 Agent 自述替代真实教学记录；
2. 只展示最终优秀作品，删除首次失败、退回或未达成样本；
3. 用满意度、平均分或代码量单独证明教学质量；
4. 将小组作品总分自动视为每个学生个人 CLO 达成；
5. 未经授权公开学生身份、作品、对话、密钥或业务数据；
6. 在学校尚未确认资格、审查和推荐时宣称“已具备申报资格”或“国家级精品课程”。
