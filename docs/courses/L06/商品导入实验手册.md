## 第 1 步：准备自己的候选目录

<!-- step-guide-1 -->
> **一句话说明：**先创建本讲隔离候选和会话记录，后面的失败、修复与复验都在这一个候选中完成。

在同一个 PowerShell 窗口依次执行各节。先运行下面的完整代码；提示输入时，粘贴自己的 L05 session.json 完整路径，不加引号。

```powershell
$ErrorActionPreference = 'Stop'
$control = (Get-Location).Path
$py = Join-Path $control '.venv\Scripts\python.exe'
if (-not (Test-Path -LiteralPath $py)) {
    throw '请在已安装项目的仓库根目录运行'
}
$tool = Join-Path $control 'docs/courses/L06/examples/import_practice.py'
$l05Session = Read-Host '请输入自己的 L05 session.json 完整路径'
$run = Join-Path $control ('.runtime/l06-import-' + [guid]::NewGuid().ToString('N'))
& $py -B -X utf8 $tool prepare --run $run --l05-session $l05Session
if ($LASTEXITCODE -ne 0) { throw '准备失败，请先阅读错误原因' }
$session = Join-Path $run 'session.json'
$meta = Get-Content -LiteralPath $session -Raw -Encoding UTF8 | ConvertFrom-Json
$candidate = $meta.candidate
$reports = Join-Path $run 'reports'
Write-Output "保存会话：$session"
Write-Output "只修改候选：$candidate"
```

准备成功会输出候选目录与 L05 来源。保存 session.json 的位置。工具从 L05 的 submission.json 找到原候选，按 frozen-checks.json 核对三个原文件，再复制到新的隔离目录。L05 原目录应保留可读取；校验不符时先查明原因，不能生成假的冻结文件绕过检查。

下面描述准备成功后应有的材料，当前版本需先解决上述卡点。课程支架提供错误入口、错误汇总器、业务检查和九项独立合同。baseline.json 记录准备后的文件清单，before 目录保存两个待修改文件的原文，session.json 保存路径与来源。这些文件由准备工具实际生成，不是让你手填的结果。

| 文件或记录 | 用途 | 修改范围 |
|---|---|---|
| eval/l06_runner.py | 执行与汇总 | 允许修改 |
| flowerp/import_batch.py | 整批导入入口 | 允许修改 |
| eval/l06_import_checks.py | 六项原业务检查 | 保持原样 |
| tests/test_l06_runner.py | 九项 Harness 合同 | 保持原样 |
| L05 三个原文件及其余候选文件 | 原回归与服务基础 | 保持原样 |

这里的“隔离”是单独目录与临时数据库，不是容器或安全沙箱。不要让 Codex 修改控制仓库、检查、基线或报告。

## 2 写下首次判断并建立连续命令

<!-- step-guide-2 -->
> **一句话说明：**先写下你认为 Harness 应怎样汇总结果，再把后续命令按执行顺序记录下来。

运行前先记录三句话：第三行无效时商品主表应怎样变化；部分写入应属于哪个等级；如果分项失败而程序退出 0，你先修哪里。把判断记在工作台同一事项或本讲 SUBMISSION.md 的个人副本中，保留首次版本。

定义以下函数，后续命令会核对实际退出码，避免把“命令运行结束”当成正确结果。

```powershell
function Invoke-L06Import {
    param([string]$Action, [string]$Name, [int]$Expected, [int]$Rows = 3)
    $report = Join-Path $reports ($Name + '.json')
    $arguments = @($tool, $Action, '--session', $session, '--report', $report)
    if ($Action -eq 'run') { $arguments += @('--rows', "$Rows") }
    & $py -B -X utf8 @arguments
    $actualExit = $LASTEXITCODE
    if ($actualExit -ne $Expected) {
        throw "预期退出 $Expected，实际 $actualExit；请阅读本次输出"
    }
}
```

run 运行六项业务检查，生成 JSON 与同名 .receipt.json。contract 运行九项独立合同，只生成 .receipt.json，其中保留实际命令、输出与出口；它不伪造业务 JSON。review 只复核已有业务报告及其来源。每次新运行使用新名字，不能覆盖旧失败。

## 3 观察原始失败和假绿灯

<!-- step-guide-3 -->
> **一句话说明：**保留第一次真实失败，并观察为什么内部检查失败时外层仍可能返回假绿灯。

![内部失败被错误汇总成外层绿灯](assets/diagrams/05-false-green.png)

```powershell
Invoke-L06Import contract '01-contract-red' 1
Invoke-L06Import run '02-false-green' 0
Invoke-L06Import review '02-false-green' 1
$falsePath = Join-Path $reports '02-false-green.json'
$falseReport = Get-Content -LiteralPath $falsePath -Raw -Encoding UTF8 | ConvertFrom-Json
$falseReport.results | Format-Table name, level, passed
$falseReport.summary | Format-List
$falseReport.results | Where-Object name -eq 'invalid_batch_no_write' | Format-List *
```

预期九项合同中七项通过、两项失败，分别指出阻断失败和阻断异常没有改变最终出口。业务六项则是四项通过、一项阻断失败、一项观察失败。无效批次显示没有拒绝且新增了两件商品，但错误摘要仍是 pass，实际退出 0。review 应退出 1，并指出汇总与分项不一致。

这就是假绿灯：底层检查已经发现错误，汇总器却给出错误结论。若失败原因是找不到模块、权限不足或数据库无法创建，先修环境；这些异常不能替代预期的业务反例。

个人练习六项包括自己的 L05 收货和范围两项回归。PPT 参考演示只有五项，因为它将 L05 参考回归登记为一项。九项合同测试专门验证 Harness，不能与业务登记数混算。

## 4 先修 Harness 的汇总

<!-- step-guide-4 -->
> **一句话说明：**先修 Harness 的汇总规则，让阻断检查失败时整个命令也明确失败。

![Harness 应依据所有阻断结果决定最终退出码](assets/diagrams/02-result-decision.png)

将第 1 节输出的候选目录告诉 Codex，并给出下面的修改要求。要求它先解释差异，再仅修改该候选中的 eval/l06_runner.py。

> 阅读当前汇总器与原合同。根据实际 results 计算 blocking_failed 和 observing_failed；只要存在阻断失败，就输出 block 并返回非零退出码。保留分项证据、异常、耗时和现有参数校验。不要改业务入口、原检查、等级、基线或报告。说明一个阻断失败为什么不能被多数通过抵消。

修改完成后执行：

```powershell
Invoke-L06Import contract '03-contract-green' 0
Invoke-L06Import run '04-business-block' 1
Invoke-L06Import review '04-business-block' 0
```

预期合同九项全部通过；业务仍为四项通过、一项阻断、一项观察，摘要变成 block，实际退出 1。review 退出 0 表示报告与实际来源一致，报告支持的业务决定仍是返工。若此时业务已经全绿，检查是否提前修改了业务或削弱了断言。

## 5 再修整批导入入口

<!-- step-guide-5 -->
> **一句话说明：**再修整批导入：所有行都合法才一起写入，任一行失败时整批数据保持不变。

![库存导入正常路径与失败后不变状态](assets/diagrams/01-stock-oracle.png)

让 Codex 阅读候选中 flowerp/import_batch.py 与服务的 validate_csv、commit，再执行下面的要求。

> 只修改候选的 flowerp/import_batch.py。将完整 CSV 一次性交给 validate_csv，再对该任务调用 commit；无效任务保留真实业务拒绝，不得逐行提交、跳过坏行或吞掉异常。复用现有服务，不改原检查。解释为什么商品主表不能部分写入，而预检查产生暂存记录是允许的。

修改完成后执行：

```powershell
Invoke-L06Import run '05-business-green' 0
Invoke-L06Import review '05-business-green' 0
Invoke-L06Import contract '06-final-contract' 0
$greenPath = Join-Path $reports '05-business-green.json'
$greenReport = Get-Content -LiteralPath $greenPath -Raw -Encoding UTF8 | ConvertFrom-Json
$greenReport.results | Format-Table name, level, passed
$greenReport.summary | Format-List
```

预期五项通过、零项阻断、一项观察，decision 为 pass，退出 0；九项合同仍全部通过。无效批次必须被拒绝，商品主表完整状态保持不变。观察项是明确设置的课堂“选读帮助补图”，不是检查了真实外部网站，也不意味着所有问题都已解决。

业务检查分别建立临时数据库并执行真实服务。正常路径比较商品内容；失败路径比较操作前后完整商品主表；预检查只允许写暂存数据。不要只根据终端颜色推断数据库状态。

## 6 换七行数据并核对报告来源

<!-- step-guide-6 -->
> **一句话说明：**换成七行新数据重新运行，确认报告确实来自当前候选和当前输入，而不是旧报告。

![当前候选、当前输入与当前报告必须形成同一条证据链](assets/diagrams/03-current-evidence.png)

保持实现和原检查不变，把输入规模改为七行，最后一行仍缺名称。

```powershell
Invoke-L06Import run '07-transfer-seven' 0 7
Invoke-L06Import review '07-transfer-seven' 0
Invoke-L06Import review '04-business-block' 1
& $py -B -X utf8 $tool verify --session $session
if ($LASTEXITCODE -ne 0) { throw '候选修改越界，请检查文件清单' }
```

七行实验仍应五项通过、一项观察；有效批次写入七件商品，无效批次不改变商品主表。旧红报告应被拒绝，因为它对应修复前的入口文件。拒绝原因应是报告不属于当前候选版本，而不是删掉了旧文件。

verify 应显示 frozen_unchanged 为 true，changed 只含两个允许修改的文件。记录器将命令目录、候选哈希、报告哈希和实际出口放入回执；review 再次比较。这是本地一致性核对，不能替代具名审核，也不是防恶意篡改的签名系统。

## 7 检查差异并交给复验者

<!-- step-guide-7 -->
> **一句话说明：**复验者检查实际差异、失败报告和新报告，再决定接受或打回。

下面命令显示两个实现文件与准备时的实际差异。Git 的退出 1 在此表示存在差异，退出大于 1 才是执行错误。

```powershell
foreach ($relative in @('eval/l06_runner.py', 'flowerp/import_batch.py')) {
    $beforeFile = Join-Path (Join-Path $run 'before') $relative
    $afterFile = Join-Path $candidate $relative
    git diff --no-index -- $beforeFile $afterFile
    if ($LASTEXITCODE -gt 1) { throw '无法比较文件，请检查 Git 与路径' }
}
```

请复验者使用同一候选、同一 session 和原检查，重新执行第 2 节函数，再用新名字运行合同、三行与七行检查及 review。保留其命令、实际结果和具名意见。没有复验者时写“待独立复验”，不要由 Codex 代填姓名或接受结论。

交接至少包含：首次判断、session 位置、两处实际差异、01 与 02 原失败、04 可信红报告、05 最终报告、06 合同回执、07 迁移报告、观察项安排和未覆盖风险。并发、中途存储故障、已有编码冲突等并未由当前绿灯证明。

## 8 中断后继续和常见错误

<!-- step-guide-8 -->
> **一句话说明：**模拟一次中断，再从原会话和原候选继续，证明证据链没有因为重启而丢失。

重新打开窗口后，先回到仓库根目录，再运行下面代码。输入本讲保存的 session.json，随后重新执行第 2 节函数定义。继续使用新的报告名字，不要重新 prepare。

```powershell
$ErrorActionPreference = 'Stop'
$control = (Get-Location).Path
$py = Join-Path $control '.venv\Scripts\python.exe'
$tool = Join-Path $control 'docs/courses/L06/examples/import_practice.py'
$session = Read-Host '请输入本讲保存的 session.json 完整路径'
$meta = Get-Content -LiteralPath $session -Raw -Encoding UTF8 | ConvertFrom-Json
$run = $meta.run
$candidate = $meta.candidate
$reports = Join-Path $run 'reports'
& $py -B -X utf8 $tool verify --session $session
if ($LASTEXITCODE -ne 0) { throw '先解决候选校验问题，再继续运行' }
```

| 现象 | 下一步 |
|---|---|
| L05 路径缺失或原检查哈希不符 | 恢复自己的原候选与冻结记录，核对真实来源 |
| Use a new report path | 使用新的报告名字，保留旧失败 |
| Frozen files changed 或 unexpected files | 检查越界差异，保留记录后恢复原检查，不重写基线 |
| 退出码与本节预期不同 | 阅读当次回执的 stdout、stderr 和业务 error，区分环境与规则失败 |
| Report does not describe current candidate files | 使用当前候选重新运行，再复核新报告 |
| PermissionError 或整体超过 120 秒 | 保留控制台错误，检查目录权限与挂起过程；超时可能没有完整报告与回执 |

完成本讲时，你应能画出 Harness 的输入、执行对象、记录与停止规则；解释为什么可信红报告通过复核仍不能交付；证明两个缺陷分别被原检查发现并修复；说明七行迁移之后还缺哪些验证。自动检查通过后，具名复验与业务接受仍按实际状态记录。
