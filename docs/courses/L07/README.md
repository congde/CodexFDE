# L07｜用 Codex Hooks 建立本地护栏

上午检查通过，下午又改了代码，还能用上午的报告宣布完成吗？本讲让 Codex 准备结束时调用检查，并用订单金额的错误验证这次检查确实发生了。

某个事件发生时调用指定程序的接线机制，叫 Hook。这里的 Stop 是 Codex 准备结束的一种事件；Hook 调用 L06 的检查运行器（Harness），并送回它的结果。

你把已有 Harness 接到 Codex 的 Stop 事件，先保留金额错误，证明真实事件会送回失败；再让 Codex 修订单并取得新版本的通过记录。客户产品形成金额正确、非法输入无残留、创建时不预占的草稿订单。

![Stop 调用 Harness，Harness 运行原检查，Eval 判断订单结果](assets/reading-figures-v2/key-example.png)

“Hook 怎么加到 Codex”直接看[手册第 6 节完整链路](实践操作手册.md#6-把-hook-接入-codex取得真实失败与恢复证据)：同一候选 → 审查 → 安装 → 在 CLI 用 `/hooks` 信任 → 正常 Stop → 红灯 → 修复与新一轮通过。Windows 和 macOS 分别提供代码块。
