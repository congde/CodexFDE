## 开篇词

<a id="L00"></a>

### tag：L00-开篇-不能替你承担工程责任

**本节要解决什么问题**：在你动手之前，先分清"AI 能做什么"和"你得承担什么"。很多学员第一周就摔在同一个坑里——以为把需求丢给 Codex 就完事了，结果代码能跑但没人敢上线。

**核心边界**：Codex 帮你编码、自测、重构，FDE 帮你把一次性 Demo 变成能持续进化的流水线，但代码质量、安全合规与交付责任始终在你身上。这不是负担，而是你身价的来源：会按按钮的人一抓一大把，能对 AI 产出负责、敢让它放手干的人才是稀缺的。

**这一讲不教操作**，只建立三件事的共识：

1. 工具边界：AI 提升的是"产出速度"，不是"交付正确性"。
2. 责任边界：验收、合规、上线与否的决定权不能交给 AI。
3. 思维转变：从"我会用 AI"到"我能对 AI 的产出负责"。

**给高薪一线程序员的提醒**：你的价签由"单位时间能交付多少"决定。AI 时代最值得慌的，不是被 AI 取代，而是身边的人用 AI 一个人顶三个人，你还停在单线程。后面 16 讲就是给你补上这条差距的。

## 导读

<a id="guide"></a>

### tag：L00-导读-先看一套完整成品

**本节要解决什么问题**：在讲任何工具之前，先让你"看见 4 周后的自己"。空谈方法论很难坚持，但先看一遍能跑起来的成品，你就知道每讲在为什么服务。

**成果演示**：本节用约 15 分钟完整演示行动营最终成品——一套已上线、能自动接需求、自动写代码、自动 Eval 质检、多 Agent 协作、云端持续运营的**个人 AI 开发流水线**。同样是高薪一线程序员，别人一个一个需求地交付，你能同时驱动架构、开发、测试、审核四支 AI 角色。

**你将要学到的能力地图（4 周路线）**：

- 第一周：Codex 开发范式 + FDE 认知（V0 单 Agent 最小交付骨架）
- 第二周：Codex 自动化引擎 + FDE 评估闭环（V1 全自动无人值守流水线）
- 第三周：多 Sub-Agents 协作架构（V2 AI 虚拟开发团队闭环）
- 第四周：FDE 产品化落地 + 全平台部署运营（V3 可对外交付的自研工具）

**本节不写代码**，用一个可运行的成品建立学习定锚。看完后，请记住这条贯穿全营的交付链路：

```text
接到需求 → 标准化 SPEC → 委托 Codex → 编码自测 → 自动化质检
→ 多 Agent 协作 → 成本安全治理 → 服务化部署 → 持续运营飞轮
```

## 第一周｜Codex 开发范式 + FDE 认知基础（V0）

本周目标：跳出"对话写代码"，建立 FDE 前置工程思维，搭建单 Codex 智能体最小可运行项目，手动跑通"需求 → 编码 → 校验"基础流程。本周独立交付：**智能文档生成器**。

### 第 01 讲

<a id="L01"></a>

### tag：L01-认清边界-人驱动AI-vs-FDE工程化

**本节要解决什么问题**：你已经在用对话式 AI 写零散代码，但为什么撑不起一个完整需求的交付？因为对话式用法缺了"工程思维"这一层。

**核心内容**：

- 传统工具（补全、对话问答）的局限：改几行、修一个 Bug 可以，承接完整需求就不行，因为缺规格、缺校验、缺迭代闭环。
- Codex 是**能力工具**，不是聊天窗口：它能把自然语言指令变成可执行结果，作用于办公、生活、生产、软件研发几乎一切场景。本栏聚焦软件开发这条交付链路。
- FDE（Forward-Deployed Engineering，前置部署工程）岗位的核心职责：深度嵌入业务、识别重复工程痛点、构建 Eval 评估集、形成"需求-编码-校验-反馈"自优化闭环。

**实战任务**：本地部署 Codex CLI + VS Code 插件，完成环境校准。具体步骤见交付物 `week-01/02-docs/environment-setup.md`。

**自检**：能让 Codex 读取本仓库的 `AGENTS.md` 并回答其中第 3 节编码约束的前 3 条，即环境打通。

---

### 第 02 讲

<a id="L02"></a>

### tag：L02-用AGENTS.md沉淀记忆与约束

**本节要解决什么问题**：AI 记不住你团队的规矩。每次对话都从零开始，写成什么算什么，没有一致性。`AGENTS.md` 就是给 Codex 立的"规矩"——项目全局记忆与约束。

**核心内容**：

- 项目全局记忆：Codex 首次进入仓库先读 `AGENTS.md`，之后所有编码行为受其约束。
- 编码约束注入：分层规范、技术栈限制、禁止写法（如禁止硬编码密钥）、仓库结构描述。
- 上下文隔离：不同模块/仓库用各自的约束，避免互相污染。

**实战任务**：为项目编写专属 `AGENTS.md`，定义分层规范、技术栈限制、禁止写法。可参考交付物 `week-01/04-agents/AGENTS.md`。

**给 Codex 的约束示例（禁止写法）**：

```text
禁止把密钥硬编码进源码（一律走环境变量）
禁止 print 调试残留
禁止吞掉异常（用 try/except 时须记录日志）
```

### 第 03 讲

<a id="L03"></a>

### tag：L03-把模糊需求变成可验收Spec

**本节要解决什么问题**：让 Codex 承接完整需求的前提，是需求本身可验收。模糊需求交给 AI，等于把返工成本交给运气。`FDE_SPEC.md` 就是把模糊需求变成可验收规格的模板。

**核心内容**：

- FDE 前置调研：动手前先搞清现状、重复痛点、约束边界。
- 模糊需求拆解三板斧：拆功能点、定验收标准、排优先级。
- SDD 软件设计文档模板：从需求概述到接口定义的一整套可验证结构。
- 可验证任务拆分：每个功能点都配"能用测试判定的验收标准"。

**实战任务**：把一条业务需求转化为标准化的 `FDE_SPEC.md`。模板见交付物 `week-01/02-docs/FDE_SPEC.md`。

**关键点**：验收标准必须"可验证"，用"POST /todos 返回 201、数据落库可查回"这类可测表述，而不是"界面友好、体验良好"。

### 第 04 讲

<a id="L04"></a>

### tag：L04-用Spec驱动Codex完成CRUD

**本节要解决什么问题**：前面写了规矩、写了 Spec，现在第一次让 Codex 基于 Spec 交付一个完整模块——从"改几行"进阶到"交付一个模块"。

**核心内容**：

- 单 Agent 任务执行：把 Spec 拆成可执行任务交给 Codex 一步步做。
- 内置测试生成：让 Codex 边写代码边生成自测。
- 基础 Bug 修复与 Git 变更自动生成：交付物直接以可提交的变更呈现。

**实战任务**：基于 `FDE_SPEC.md` 驱动 Codex 开发完整 CRUD 模块并手动校验。可运行示例见交付物 `week-01/01-code/crud/`（含 `model / service / handler` 分层与自测）。

**验证**：`python -m pytest test_crud.py -v` 全绿，即 V0 最小系统成立。

**第一周收获**：掌握 Codex 环境与记忆工程，能用标准化 Spec 驱动 AI 交付完整模块。带走独立成果：**智能文档生成器**（见 `week-01/03-skills/doc-gen/SKILL.md`）。

## 第二周｜Codex 自动化引擎 + FDE 评估闭环（V1）

本周目标：把手动流程全部自动化，搭建 FDE 第一级飞轮——自动采集问题、生成 Eval 评估集、Codex 自动修复迭代，让 AI 开始"放手干"。本周独立交付：**Git 提交质量门禁**。

### 第 05 讲

<a id="L05"></a>

### tag：L05-用Hooks搭起AI产出门禁

**本节要解决什么问题**：AI 产出不敢直接进 PR、上生产，返工成本吃掉全部收益。解决办法是在"产出"和"入库"之间加一道自动门禁——Hooks。

**核心内容**：

- 前置/后置钩子：在提交、合并之前/之后自动触发检查。
- 代码静态检测：语法、风格、未定义引用等可机检问题。
- 漏洞拦截：硬编码密钥、危险导入、缺末位换行等低质量信号。
- 低质量产出自动驳回：检查失败即拦下，不让坏代码进基线。

**实战任务**：为 Codex 新增代码审查 Hook。可运行示例见交付物 `week-02/01-code/hooks/pre_commit.py`。

**验证**：`python -m pytest test_pre_commit.py -q` 全绿；能拦截"硬编码 api_key""缺末位换行"两种情况即达标。

---

### 第 06 讲

<a id="L06"></a>

### tag：L06-用MCP打通外部数据源

**本节要解决什么问题**：Codex 默认只看到仓库里的文件，看不到仓库历史、GitHub API、数据库、接口文档这些外部数据。MCP（Model Context Protocol）就是让 Codex 与外部数据源打通的协议。

**核心内容**：

- MCP 是什么：智能体与外部工具/数据源的标准协议，让 Codex 能"调用工具、读数据"。
- 接入范围：Git/GitHub API、测试工具、数据库、接口文档。
- 服务编排：把数据读取逻辑封装成 MCP 工具，供 Codex 按需调用。

**实战任务**：搭建 MCP 服务，让 Codex 自动读取仓库历史、接口定义。示例见交付物 `week-02/01-code/mcp/server.py`（提供 `list_repo_files` 工具）。

**验证**：`python -m pytest test_mcp.py -q` 全绿；Codex 能调用工具读取仓库文件树即达标。

### 第 07 讲

<a id="L07"></a>

### tag：L07-给AI建立Eval考题库

**本节要解决什么问题**：代码质量不能被"感觉"定义，否则无法量化、无法迭代。Eval（评估集）就是给 AI 建的"考题库"——用输入-预期输出来量化 AI 产出质量。

**核心内容**：

- FDE 三级飞轮原理：采集问题 → 沉淀用例 → 自动修复，形成自优化循环。
- 失败模式识别：从历史 Bug 里提炼可复现的失败场景。
- 用例自动化沉淀：把"输入-预期输出"固化为可执行的评测用例。
- 双重用途：Eval 用例既是质检标准，也是后续迭代的验收基准。

**实战任务**：采集历史开发 Bug，批量生成 Eval 评估用例。示例见交付物 `week-02/05-harness/eval/`（`eval_runner.py` + `cases/crud.yaml`）。

**验证**：`python eval_runner.py --cases cases` 能输出通过率报告即达标。

### 第 08 讲

<a id="L08"></a>

### tag：L08-CICD无人值守批量开发

**本节要解决什么问题**：让 Codex 自己定时跑、批量重构、自动校验，你只看结果，不盯过程。CI/CD 把"手动触发"变成"定时自动"。

**核心内容**：

- GitHub Actions 配置与定时触发：cron 定时跑 Codex 重构任务。
- Git Worktree 基线隔离：在独立 working tree 里改代码，不动主基线。
- 批量重构回滚机制：失败自动回滚，不污染主分支。
- 为第 3 周多 Agent 做前置铺垫。

**实战任务**：配置每日定时任务，自动执行 Codex 重构 + Eval 校验。配置见交付物 `week-02/06-cicd/`。

**第二周收获**：掌握 Hooks / MCP / CI-CD 三大自动化组件，落地 FDE 第一级自优化飞轮。带走独立成果：**Git 提交质量门禁**（见 `week-02/03-skills/git-guard/SKILL.md`）。

### 第 09 讲

<a id="L09"></a>

### tag：L09-搭建Sub-Agents虚拟团队

**本节要解决什么问题**：一个人不吃不喝也写不完那么多需求。解决办法是把"一个人"拆成"一支 AI 团队"——让架构、开发、测试、审核四类角色分工协作。这是本专栏价值核心。

**核心内容**：

- Sub-Agents 五大协作模式：路由分发、串行编排、并行分治、竞争评审、监督仲裁。
- 角色权限最小隔离：每个角色只碰自己该碰的，互不越权。
- 四类角色划分：架构 Agent（设计）、开发 Agent（编码）、测试 Agent（补测）、审核 Agent（把关）。

**实战任务**：为项目划分 4 类 AI 角色，输出完整多角色配置 `AGENTS.yaml`。配置见交付物 `week-03/04-agents/AGENTS.yaml`。

**关键点**：角色隔离是安全底线——审核 Agent 不该直接改代码，测试 Agent 不该决定架构，否则"团队"会乱套。

### 第 10 讲

<a id="L10"></a>

### tag：L10-用LangGraph编排工作流

**本节要解决什么问题**：多 Agent 有了，但谁先做、做完了移交谁、卡住了怎么办，需要一套有状态的工作流来编排，否则角色之间无法有序协作。

**核心内容**：

- 条件分支：根据上一步结果决定走向（审核通过→交付；不通过→打回）。
- 任务移交（handoff）：角色间交接上下文，避免重复劳动。
- 状态持久化：工作流中间状态可保存、可恢复。
- 人机协同介入节点：关键处留人工确认口，不把决定权全交给 AI。

**实战任务**：用 LangGraph 串联完整链路：需求 → 架构 → 编码 → 自测 → 审核 → 打回重写。工作流见交付物 `week-03/01-code/langgraph/`。

### 第 11 讲

<a id="L11"></a>

### tag：L11-Eval驱动评审打回修正闭环

**本节要解决什么问题**：AI 写错不可怕，可怕的是没人把关、一遍遍写错。本节把"评审-打回-修正"做成自动闭环，用 Eval 通过率作为量化验收门槛。

**核心内容**：

- 审核 Agent 自动打分：对产出按维度评分。
- 低质量代码自动回传：不通过就回传开发 Agent 迭代。
- 多轮优化机制：最多 3 轮打回重写，防止无限循环烧钱。
- 量化门槛：以第 07 讲 Eval 通过率作为"何时达标、何时终止"的唯一标准。

**实战任务**：实现"审核不通过自动重生成，最多 3 轮迭代"，用 Eval 集判定是否达标。闭环见交付物 `week-03/05-harness/eval/`。

### 第 12 讲

<a id="L12"></a>

### tag：L12-生产级成本安全监控治理

**本节要解决什么问题**：多 Agent 一放大，Token 费用、调用频次、安全风险、失败告警全部放大。没有治理，AI 团队会跑"贵、漏、乱"。

**核心内容**：

- Token 预算管控：给每个 Agent 设费用上限，超预算即停。
- API 调用限流：控制并发，防止接口被打爆。
- 代码沙箱隔离：AI 执行环境与生产隔离，防止误操作扩散。
- 全链路日志告警 + 异常重试：失败可定位、可恢复。

**实战任务**：接入监控面板，配置调用成本上限与失败告警。治理模块见交付物 `week-03/01-code/governance/`。

**第三周收获**：精通多 Agent 并行开发架构与 LangGraph 工作流，具备成本、安全、监控治理能力。带走独立成果：**遗留代码现代化重构助手**（见 `week-03/03-skills/refactor/SKILL.md`）。

## 第四周｜FDE 产品化落地 + 全平台部署运营（V3）

本周目标：把流水线从本地代码升级为可长期运营的个人工具，落地 FDE 第三级飞轮——业务反馈驱动工具持续迭代。本周独立交付：**个人 AI 工程作品集门户**。

### 第 13 讲

<a id="L13"></a>

### tag：L13-Codex运行时封装与调度

**本节要解决什么问题**：前一阶段的流水线跑在"你的终端里"，关掉就没了、只有你能用。本节把它封装成可后台常驻的服务，能多仓库并行调度、带鉴权对外提供。

**核心内容**：

- Codex CLI 容器打包：把流水线装进容器，环境一致、随处可跑。
- Gateway 路由：统一入口，按请求路由到不同处理链。
- 多仓库并行调度 + 权限鉴权：多个项目同时跑，且只有授权者能调用。

**实战任务**：将多 Agent 流水线封装为独立后台服务。封装见交付物 `week-04/01-code/runtime/`。

---

### 第 14 讲

<a id="L14"></a>

### tag：L14-多渠道自动产出一键生成

**本节要解决什么问题**：代码写完了，但文档、接口说明、组件脚手架、周报还得手写，重复又耗时。本节把"多渠道产出"做成一键自动生成。

**核心内容**：

- 代码文档 / 接口文档自动格式化输出。
- 组件脚手架自动生成：新模块一键起框架。
- 开发周报自动汇总：从提交记录自动攒出周报。

**实战任务**：新增输出 Skill，自动生成项目文档与技术周报。输出模块见交付物 `week-04/01-code/output/`，Skill 见 `week-04/03-skills/output/SKILL.md`。

---

### 第 15 讲

<a id="L15"></a>

### tag：L15-给仓库配个问答Bot

**本节要解决什么问题**：团队问"这个接口怎么调、这个 Bug 在哪"都在打扰你。给仓库配一个问答 Bot，让它基于知识库和代码检索自动回答。

**核心内容**：

- 知识库构建：把文档、接口、规范沉淀成可检索的知识源。
- 代码检索：按语义定位相关代码。
- 需求咨询与 Bug 自动定位：回答"怎么做"，并帮定位"哪里错了"。

**实战任务**：基于现有流水线搭建内部代码问答机器人。Bot 见交付物 `week-04/01-code/bot/`。

---

### 第 16 讲

<a id="L16"></a>

### tag：L16-云端部署与反馈采集飞轮

**本节要解决什么问题**：本地能跑只是第一步，要成为"随时可调用的个人交付基础设施"，必须云端部署、持续运营，并让业务反馈反过来驱动工具迭代（FDE 第三级飞轮）。

**核心内容**：

- 云服务器容器部署：渲染、监控、告警齐全。
- 版本迭代：灰度发布、回滚。
- 业务反馈采集飞轮：采集实际使用反馈，回填 Eval 用例，驱动下一次迭代。

**实战任务**：全系统云端上线，配置 7×24 小时自动调度。部署配置见交付物 `week-04/06-deploy/`。

**第四周收获**：掌握 Codex 服务化部署与运营，完成一套完整的个人自研 AI 开发工具，成为你的"个人交付基础设施"。带走独立成果：**可对外访问的个人 AI 工程作品集门户**。结业交付累计 **4 个独立迷你项目 + 1 套主线流水线**，组成完整作品集。

### 结束语

<a id="L17"></a>

### tag：L17-结束语-学会委托下一次需求

**本节要解决什么问题**：行动营结业，但真正的考验是下一次拿到真实需求时，你还会不会退回到"打开聊天框随口问一句"。

**核心内容**：把 16 讲串成一条可复用工程链路——接到需求 → 写 SPEC → 委托 Codex → 自动质检 → 多 Agent 协作 → 服务化部署 → 持续运营飞轮。真正的过关，是下一次需求的第一反应是先写 SPEC、定验收、选 Agent、配流水线，而不是随口一问。

**给你的提醒**：对高薪一线程序员而言，每一次"随口问一句"都是时间被稀释、杠杆在漏气。学会委托，才是把"一个人"变成"一支 AI 团队"的最后一环。
