# Codex AI 工程交付行动营｜文档总览与学习入口

**用 Codex 搭建个人 AI 研发工作台，再通过工作台组织人与 AI 协同，持续开发 FlowERP。**

这套材料从零基础开始：你可以先不懂大模型，也没有软件研发经验。先看懂一件具体的事，再按步骤动手。软件研发在这里就是：把一个人的要求做成能运行的程序，再实际检查结果；交付则是把程序、使用说明和检查依据交给别人，供他使用与确认。

先分清你、AI 助手和两件软件分别做什么：**你** 说清问题、确认允许做什么，并判断结果；**Codex** 是 AI（人工智能）开发助手，协助读文件、想办法、写程序；**个人工作台** 是你逐讲建设的工具，保存要求和结果，组织下一步。**FlowERP** 是用来练习交付的库存、订单和采购软件，工作台做好后再通过它持续开发。

大模型让这类 AI 助手能根据你输入的文字生成回答和代码。回答可能出错，所以“AI 说完成”之后，还要按说好的方法运行、查看和确认。

## 零基础先走哪三步

1. 打开 [L00 课前准备](courses/L00/README.md)，认清对话框、终端和文件编辑器，再装好工具。
2. 在 L00 练一次“输入查看位置的命令 → 读出自己的文件夹路径 → 保存结果”，看到结果后继续环境准备。
3. 进入 [L01](courses/L01/README.md)，做一个记录工具，让今天的要求和结果明天还能查回。读一段、做一步、看结果，再继续。

想先看一个完整例子，可读[从“导出库存表”理解软件开发](reference/从业务需求到上线：理解Spec与个人研发工作台.md)。第一次学习先沿 L00、L01 走，设计细节在遇到问题时查阅。

## 工作台怎样逐讲增长

![先建工作台，再通过工作台交付 FlowERP](courses/assets/readme-guide-20261005/01-build-workbench-deliver-flowerp.png)

**沿“建设工具 → 用工具交付产品 → 结果推动工具改进”阅读。** L01～L03 直接监督 Codex 做记录工具、写协作规则，并让程序读懂需求说明（Spec）；L04 先补齐工作台的执行与检查能力，由另一位复验者接受这一版 Workbench V0，再由它首次交付 FlowERP 库存导出。后续交付中的重复收货、取消释放和采购审批问题，推动工作台补上检查、返工、分工与审核。

L00 准备工具和环境；项目壳是只有首页与基础检查的起点，后续功能由你与 Codex 一起增加；也可按[从 0 搭建参考选做](courses/L00/从0开始搭建个人AI研发工作台.md)另建新项目。沿选定的同一项目继续，个人建设与验收记录按本讲要求实际产生。

## 16 讲学习路线

每讲先打开 README，也就是本讲的阅读入口：**辅导资料解释为什么，实践手册说明怎么做，SUBMISSION 提交模板帮你列出自己的判断与实际结果。** 提交模板中的“证据”是能让别人核对的原始输出、文件和记录。

L01～L04 建工作台并完成首次交付；L05～L08 让检查可信；L09～L12 控制返工、分工与人审；L13～L16 让别人使用、接手并继续交付。每轮修改在隔离候选中进行：这是供本轮开发与检查使用的副本，不自动覆盖原项目。

## 怎样判断可以进入下一讲

1. **能复验，也就是再查一次**：重新运行同一检查，能找出自己的实际输出、退出码、失败后状态和修改记录。退出码是程序交回的结束数字，要与本步预期一起判断；Diff 是修改前后的对照，核对是否只改了允许的文件。工作台检查与 FlowERP 业务检查分别核对。
2. **有人接受**：提交模板指向当前候选、实际 Diff 和当前报告，由具名人员决定接受或退回。“具名”是记录实际审核人的姓名及依据。
3. **能独立迁移，也就是换个条件仍会做**：换一个输入或小需求，能够解释为什么这样处理，并完成相应调整。

缺项时回到本讲续做。参考实现不能替代你自己的复验、具名接受与独立迁移；绿色截图和 Codex 的完成声明也须回查依据。已有行为正确时如实记录，不伪造红灯，是否要求起始红灯按当讲合同判断。
