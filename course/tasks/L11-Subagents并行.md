# L11｜用 Codex 原生 Subagents 并行处理独立任务

- **核心内容**：可并行任务识别、上下文隔离、结果汇总、冲突风险与额外 Token 成本。
- **演示结果**：测试补全与风险审查并行执行，由主 Agent 汇总结论。
- **课内增量**：为两个无文件写入冲突的任务定义清晰输入、输出和验收标准。
- **通过标准**：子任务边界清晰；主 Agent 能追溯每个结论；有写入冲突的任务不强行并行。
- **挑战任务**：比较单 Agent 与 Subagents 在耗时、Token 和结果质量上的差异。

## 项目主线与评价证据

- **FlowERP 现场问题**：本讲由 FlowERP 真实交付暴露可重复工程问题，用于触发工作台能力验证。

- **ERP 产品增量**：完成采购申请的 Spec、Eval 和最小实现；采购申请不得直接入库。
- **工作台增量**：形成原生 Subagents 子任务合同、冲突分析、结果汇总和成本度量。
- **双线因果**：采购横跨库存、审批和审计，规格澄清、测试设计和风险审查可并行，最终代码集成必须由主 Agent 按冲突图串行裁决。
- **ERP 验收证据**：采购申请可创建但不能直接入库；子报告回指 Spec/Eval；主 Agent 串行集成后的 Diff 通过统一 Harness。
- **学生学习证据**：读写集、冲突图、子任务报告、主结论和单/多 Agent 对照。
- **形成性评价**：并行没有净收益也可得分，前提是证据真实、判断可解释。

## 付费行动课交付合同

本讲不是多开几个 Agent 看动画。学员必须亲手交付：任务依赖与读写集图；两个只读子任务合同；真实并行原始输出；主 Agent 引用回查和分歧消解；同任务单 Agent 基线；墙钟/Token/独立发现/汇总税对照；一个写冲突反例的串行判决；迁移到个人项目的冲突图。

以 Agent 数量评分、直接拼接摘要、并行写共享事实，或没有单 Agent 基线就宣称提效，均按未完成处理。

## 主次边界

- **FlowERP 产品状态**：并行只读产出服务于同一采购申请增量；共享接口和业务代码由主 Agent 串行集成并统一复验；
- **工作台主产物**是调度判断、子任务合同、上下文隔离、结果核验和成本度量；
- **迁移证明**必须在个人项目重新绘制冲突图，不能复用 FlowERP 的角色名称充数。

## 课前独立诊断

调用 Subagents 前提交且不得覆盖：

1. “修改不同文件”为什么仍可能存在接口或状态冲突？
2. 哪两项只读任务适合并行，输入版本和输出 Schema 分别是什么？
3. 并行更快但 Token 翻倍，怎样判断是否值得？

## 混合式学习流程

| 场域 | 学习任务 | 必须留下的证据 |
|---|---|---|
| 线上 30 分钟 | 建立读写集、冲突图、子任务合同和净收益模型 | 初始排程、冲突改判、收益预测 |
| 线下 70 分钟 | 并行两个只读审计，主 Agent 核验并与单 Agent 比较 | 原始输出、引用、分歧处理、成本对照 |
| 课后迁移 | 为个人项目绘制一张任务冲突图 | 串/并行决定及其证据 |

## AI 使用与证据边界

- 只有输入版本稳定、输出可合并、写集无冲突且外部副作用独立时才能并行；不满足则串行；
- 每个子任务都要写目标、可见范围、禁止动作、输出 Schema、验收和停止条件；
- 子 Agent 只获得最小上下文，不共享密钥、未决结论或无关个人数据；
- 主 Agent 必须回查文件引用、显式处理矛盾并承担最终判断，不能直接拼接摘要。

## 本讲主线

Loop 停在一个跨模块失败，测试覆盖审计和业务风险审计可以同时进行吗？学员先画读写集与冲突图，再并行两个只读调查，并把并行结果与单 Agent 基线比较。本讲教授调度判断，不以 Agent 数量作为成果。

## 大纲与前沿硬校准

- **必须完成**：并行两个无写入冲突、输入输出和验收明确的任务，由主 Agent 核验并与单 Agent 比较。
- **当前做法**：Subagents 优先承担搜索、测试、分诊等读密集任务；净收益扣除启动、重复、冲突与汇总税。
- **退回条件**：并行写共享事实、直接拼接子摘要、以 Agent 数量或绝对速度作为质量结论。见[校准矩阵](../../docs/courses/16讲主线与前沿校准矩阵.md)。

## 必须教会的知识

1. **读写集模型**：只有输入稳定、输出可合并且写集不冲突的任务才适合并行。
2. **子任务合同**：每个 Agent 都要有问题、可见范围、禁止动作、输出 Schema、验收和停止条件。
3. **上下文隔离**：只给完成子任务所需文件与证据，避免无关信息、秘密和其他 Agent 未定结论。
4. **主 Agent 责任**：核对引用、消解矛盾、决定是否扩展调查；不能把两个摘要直接拼成真相。
5. **净收益度量**：墙钟时间节省要扣除启动、重复发现、冲突和汇总成本。

## 课堂任务

```powershell
python -X utf8 -m workbench.cli course-contract --lesson 11
python -X utf8 -m workbench.cli course-spec --lesson 11
python -X utf8 -m workbench.cli course-submit --lesson 11 --execute-code
python -X utf8 -m workbench.cli course-eval --lesson 11
```

- 任务 A：只读 `tests/` 与 `eval/`，列出未覆盖业务不变量，引用文件位置。
- 任务 B：只读 `flowerp/` 与 `workbench/`，审计状态、幂等与权限风险，引用文件位置。
- 并行前标注两个任务的 read set、write set（均为空）和输出字段。
- 失败实验：设计两个同写一文件的任务，冲突图必须判定串行；不要真的制造覆盖式写入。
- 对照单 Agent 与并行的耗时、Token、有效独立发现和汇总成本。

## 独有产物与验收

提交冲突图、两个子任务合同、原始输出、主 Agent 证据核验和对照度量。没有文件引用、任务边界重叠、主 Agent 不复核，或并行更慢却仍宣称更优，均退回。

## 提交证据包与四级量规

证据包包含课前排程、读写集与冲突图、两个合同、原始子任务输出、主核验、分歧处理、单/多 Agent 墙钟与 Token 对照、复盘和迁移图。

| 维度 | 优秀 | 达成 | 发展中 | 未达成 |
|---|---|---|---|---|
| 独立性判断 | 能发现文件之外的接口、版本和外部状态冲突 | 读写集和输入版本清楚 | 只检查文件名 | 有冲突仍强行并行 |
| 子任务合同 | 两个任务最小、互补、可验收且安全停止 | 必要字段齐全 | 范围重叠或 Schema 模糊 | 无边界、泄露上下文或越权 |
| 主 Agent 核验 | 所有结论回查来源并显式解冲突 | 引用可追溯、结论唯一 | 只抽查部分来源 | 直接拼接或采信无证据结论 |
| 净收益判断 | 墙钟、Token、返工、合并税均量化 | 能诚实判断是否有净收益 | 只比较速度 | 数据不可核验却宣称更优 |

硬门槛：有写入冲突仍并行、泄露敏感上下文、主 Agent 不复核、伪造 Token 或速度数据，直接退回。

## 持续改进与迁移

记录冲突识别率、无引用结论率、重复工作率、并行净收益和首次/修订排程变化；没有真实运行数据时写“未知”。Agent 数量不能作为挑战度或教学成效指标。
