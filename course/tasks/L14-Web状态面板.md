# L14｜让交付状态在 Web 面板可见

- **核心内容**：面板信息层级、轮询或推送、失败重试、结果下载和密钥边界。
- **演示结果**：从 Web 提交需求并查看阶段状态、Eval 报告和产出文件。
- **课内增量**：完成只覆盖一个任务主路径的最小面板。
- **通过标准**：状态与后端一致；失败路径明确；结果可追踪；前端和仓库中没有密钥。
- **挑战任务**：增加任务队列或多仓库隔离，不作为跟跑线结业要求。

## 项目主线与评价证据

- **FlowERP 现场问题**：本讲由 FlowERP 真实交付暴露可重复工程问题，用于触发工作台能力验证。

- **ERP 产品增量**：增加商品/库存/订单/采购中的一个真实业务操作主路径，并关联对应交付任务的证据下钻。
- **工作台增量**：形成覆盖一个任务主路径的 Web 面板、轮询/重试和结果追踪。
- **双线因果**：用户既要操作 ERP，也要判断 AI 交付是否可信，迫使页面同时忠实投影业务状态和交付状态，而不混用两套权威源。
- **ERP 验收证据**：同一业务 ID 与 Task ID 在 DOM、API、SQLite 和 ERP 服务状态四方一致；断网、未知态和失败不保留旧绿灯。
- **学生学习证据**：DOM/API/SQLite/ERP 业务对象四方对账、失败态、断网态和无密钥检查。
- **形成性评价**：由同伴拿同一 Task ID 复验，不按页面美观度替代状态正确性。

## 付费行动课交付合同

本讲不是美化页面或加聊天框。学员必须亲手交付：状态文案/责任人/下一步映射；一个真实 Task 主路径 UI Diff；空、载入、阻断、网络失败、未知枚举和陈旧态；轮询停止与退避；安全渲染；键盘与状态消息检查；同一 Task ID/业务 ID 的 DOM/API/SQLite/ERP 业务对象对账；陌生人桌面/移动端走查修订。

使用静态 JSON、计时器假进度、断网保留旧绿灯，或以截图美观代替权威状态一致，均按未完成处理。

## 主次边界

- **FlowERP 产品状态**：交付一个真实业务页面主路径；页面必须从 ERP API 读取权威状态，并能按 Task ID 下钻工作台证据；
- **工作台主产物**是可信状态投影、证据下钻、错误恢复、可访问性与对账协议；
- **迁移证明**要把状态合同应用到第二种长任务，说明哪些字段可复用、哪些由项目适配。

## 课前独立诊断

让页面或 AI 解释状态前提交且不得覆盖：

1. 页面显示“已完成”时，还需要哪两个权威来源才能签收？
2. 断网后保留旧绿灯为什么比显示错误更危险？
3. 未知状态枚举应显示什么，能否猜成最接近的已知状态？

## AI 使用与证据边界

- AI 可生成界面候选和分析日志，但页面状态只能来自 API；禁止静态假数据、计时器假进度和模型猜测；
- 不在前端保存密钥、令牌、连接串或权威业务规则，不让浏览器重算库存与金额；
- 错误文本按不受信任输入安全渲染，未知、离线和陈旧数据必须显式显示；
- 截图只证明某一时刻的呈现，必须与同一 Task ID/业务 ID 的 Network、API、持久状态和 ERP 业务对象共同取证。

## 本讲主线

同一个 Task 在列表显示“已完成”，详情却显示“待启动”，证明漂亮页面也会说谎。学员用同一 Task ID 与业务 ID 对账 DOM、API、SQLite 和 ERP 业务对象，补齐空态、加载态、失败态和陈旧态。本讲教授可信状态投影，不决定反馈是否晋级。

## 大纲与前沿硬校准

- **必须完成**：一个 Task 主路径，展示阶段、失败、Eval 与产物；DOM/API/SQLite/ERP 业务对象同 ID 对账且前端无密钥。
- **当前做法**：空载错/未知/陈旧态、可访问状态消息和可审查动作是基础，Agentic UI 不等于加聊天框。
- **退回条件**：静态假数据、计时器假进度、前端重算权威结果或用页面美观代替状态一致。见[校准矩阵](../../docs/courses/16讲主线与前沿校准矩阵.md)。

## 必须教会的知识

1. **状态文案合同**：每个后端枚举只映射到一个准确文案、责任人和可执行下一步，不使用虚构百分比。
2. **四方对账**：DOM 是呈现，API 是接口事实，SQLite 是持久事实，ERP 业务对象是领域事实；四者通过同一 Task ID/业务 ID 与字段映射核对。
3. **完整交互状态**：空、载入、成功、业务阻断、网络错误、未知枚举和陈旧数据必须有不同表现。
4. **轮询新鲜度**：以服务端状态和时间为准，停止条件、退避和失联提示明确；断网不能保留旧绿灯冒充当前结果。
5. **前端边界**：不保存密钥，不在浏览器重算权威业务金额，安全渲染错误文本，支持键盘和移动端。

## 课堂任务

### 0. 先做信息压缩，再实现页面

提交一份内部对象→用户工作包映射。前台最多使用“事项、决策简报、交付合同、证据包、结果复盘”五个工作包；说明哪些字段默认显示、按需展开、仅异常出现或不进入前台。随后写出一条黄金路径：输入事项、风险建议、人工决定、交付证据、结果观察。

陌生人必须在不听作者讲解的情况下回答：现在要我决定什么、为什么被阻断、证据在哪里、谁负责下一步、怎样停止或恢复。记录首次卡点以及一次删除、合并或折叠菜单后的修订。本项作为产品化形成性证据；基础通过线仍以真实状态、失败路径、追踪和无密钥为准。

```powershell
python -X utf8 -m workbench.cli course-contract --lesson 14
python -X utf8 -m workbench.cli course-spec --lesson 14
python -X utf8 -m workbench.cli course-submit --lesson 14 --execute-code
python -X utf8 -m workbench.cli course-eval --lesson 14
```

- 页面：`web/index.html`；服务：`http://127.0.0.1:8000`。
- 创建真实需求，观察 queued → executing → evaluating → review；不得用定时器伪造状态。
- 展开 Spec、Eval evidence 和带 actor 的事件链，再具名接受或打回。
- 失败实验：断开服务、注入未知状态或字段类型漂移，页面必须显式报错且不显示旧成功。
- 用同一 Task ID 与业务 ID 核对 DOM 文案、API JSON、持久记录和 ERP 业务对象。

## 独有产物与验收

提交状态文案表、字段映射、四方对账记录、Network 证据以及桌面/移动端截图。固定 Eval 数量、吞错、静态假数据、前端含 API key 或 blocking 全绿后自动显示完成，均退回。

## 提交证据包与四级量规

证据包包含课前判断、文案合同、字段映射、真实 Task 走查、断网/未知/类型漂移、四方对账、Network、键盘/移动端、安全检查、同伴走查和修订前后版本。

| 维度 | 优秀 | 达成 | 发展中 | 未达成 |
|---|---|---|---|---|
| 状态真实性 | DOM/API/SQLite/ERP 业务对象关键字段一致且有新鲜度 | 关键状态与证据一致 | 少量字段或时间不清 | 静态假数据、旧绿灯或假进度 |
| 失败与恢复 | 空/载/错/离线/未知/陈旧均可行动 | 主要失败路径明确可重试 | 错态区分不足 | 吞错或失败显示成功 |
| 安全与可用 | 无秘密、渲染安全、键盘/移动端任务可完成 | 无阻断级安全或可访问性问题 | 存在非阻断问题 | 密钥入前端、XSS 风险或核心操作不可达 |
| 学生走查 | 陌生人发现的问题推动实质修订 | 至少一项有证据修订 | 只改样式 | 以美观截图代替状态证据 |

硬门槛：前端含密钥、页面伪造状态、吞掉 blocking 失败、API/持久状态不一致仍宣称完成，直接退回。
