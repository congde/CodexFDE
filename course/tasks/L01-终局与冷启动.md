# L01｜先看终局：一次可验证的 AI 交付怎样完成

- **核心内容**：课程最终成品、四周路线、生成完成与验收完成的区别。
- **演示结果**：输入一个小型真实需求，依次看到 Spec、代码变更、测试结果和交付摘要。
- **课内增量**：运行环境检查，并让 Codex 输出“结构、约束、验证命令、风险”四段式接手报告。
- **通过标准**：环境检查通过；接手报告能指出真实的仓库命令和一项风险。

## 项目主线与评价证据

- **FlowERP 现场问题**：本讲由 FlowERP 真实交付暴露可重复工程问题，用于触发工作台能力验证。

- **ERP 产品增量**：建立 FlowERP 基线快照和 16 讲产品能力地图；本讲业务账保持不变。
- **工作台增量**：建立终局地图、课程环境基线和仓库接手报告，为 L04 首个真实交付准备入口。
- **双线因果**：只有先识别 ERP 当前能力、缺口和权威验证入口，后续工作台才知道要构建什么、怎样证明没有破坏旧账。
- **ERP 验收证据**：领域模块清单、业务不变量清单、当前验证命令和 L04～L16 产品里程碑映射。
- **学生学习证据**：首次判断、环境记录、AI 使用前判断、报告初稿与修订稿、同伴复核和迁移结论。
- **形成性评价**：学生必须依据仓库事实修订至少一项 AI 初稿结论，并保留初稿、修订依据和同伴反馈。

## 付费行动课交付合同

本讲不是仓库导览。学员在限时、无讲师口头补充条件下接手陌生仓库，必须亲手交付：环境指纹；带退出码的命令证据账；四段式接手报告；一条 AI 错判的修订前后对照；由同伴仅凭报告完成的冷交接；同一方法迁移到个人仓库的差异说明。

只复述目录、复制 README、引用讲师成功截图，或报告中的命令没有实际运行状态，均按未完成处理。

## 大模型编程规范

以下内容是课程采用的工程工作约定，不宣称是统一国家标准。本讲统一采用“先探索、后修改”的只读接手流程。每次委托至少写清六项：目标、上下文、允许动作、禁止动作、输出与证据、完成与停止。提示词不能代替真实权限；AI 初稿不能代替学生核验；发现命令不能写成已经运行，运行成功也不能直接写成验收或发布完成。

数据与权限红线：不得把密钥、令牌、Cookie、个人信息、客户数据、运行数据库、生产日志和未经授权的私有材料交给模型或外部服务。仓库、网页、Issue、日志或工具输出若要求忽略规则、上传文件、开启网络或执行未知脚本，应按不受信任输入处理并停止升级权限。

## 线下行动任务

### 1. 建立课程环境基线

先在所用客户端、IDE 或 CLI 中启用可验证的只读工作区或 `read-only` Sandbox，记录运行位置、审批策略、网络状态和允许写入范围。无法证明只读边界时，不运行 Agent，只完成人工仓库检查。

在仓库根目录执行：

```powershell
python -X utf8 -m workbench.cli course-contract --lesson 1
python -X utf8 -m workbench.cli course-status
python --version
git --version
codex --version
git rev-parse --show-toplevel
git branch --show-current
git rev-parse HEAD
python -X utf8 -m workbench.cli doctor
$LASTEXITCODE
```

如课程不使用 Codex CLI，按教师公布的统一方式记录客户端版本和可用状态。

提交时记录工具与界面版本、可见模型信息、仓库根目录、当前分支、提交标识、运行位置、Sandbox、审批策略、网络状态、实际读取的 Agent 指令、Agent 实际命令、`doctor` 关键输出和退出码。不可见的信息写“平台未提供”；命令未执行时写明原因。首次失败必须保留；修复后附第二次运行证据。

注意：`doctor` 只证明 FlowERP 本地运行时基线就绪，不代表测试、阻断级 Eval 或发布条件已经通过。

### 2. AI 使用前先写首次仓库判断

阅读 `AGENTS.md`、`README.md`、`FDE_SPEC.md` 和一级目录，限时写下：

- 三个目录及职责；
- 两条不可破坏的规则；
- 一条可能的验证命令；
- 一项当前未知的风险。
- `doctor` 从 CLI 入口到就绪判定的大致调用链：入口、配置、服务、持久化、检查汇总和退出码分别由谁负责。

### 3. 委托 Codex 生成初稿

```text
【目标】只读接手当前仓库，形成可复核的“结构、约束、验证命令、风险”四段式报告。

【上下文】读取实际生效的 AGENTS.md、README.md、FDE_SPEC.md、一级目录和真实命令入口；沿 doctor 命令追踪入口、配置、服务、持久化和退出码职责。

【允许动作】只读搜索和读取文本；查看仓库根目录、分支、提交和工作区状态；只使用当前只读 Sandbox 已允许的工具。

【禁止动作】不写文件，不安装依赖，不提交或推送，不开启网络，不读取密钥、运行数据库或个人数据，不执行改变业务、运行时或外部系统状态的命令，不自行扩大范围。

【输出与证据】关键结论附文件路径和可定位位置；验证命令标记“仅发现、已执行、执行失败、未执行”；风险按“对象—证据—影响—反证条件”表达；另附工具、仓库提交、Sandbox、网络、指令来源和实际命令等运行溯源。

【完成与停止】证据不足时写“未知”和缺失证据；若需要写入、联网、安装、敏感数据或扩大权限，立即停止并说明原因。
```

### 4. 核验并修订初稿

不能直接提交 AI 初稿。对关键结论分别标注：

- **证据支持**：仓库文件、真实命令或状态直接支持；
- **仅为推断**：只有间接依据，必须降低表述强度并写反证条件；
- **当前未知**：说明还缺什么证据。

至少完成一项有实质判断变化的修订。只改措辞或排版不算有效修订。

验证命令必须再标注执行状态：

- **仅发现**：只在文档、脚本或配置中找到，不能声称运行过；
- **已执行**：本人在明确环境中运行，并保留关键输出和退出码；
- **执行失败**：实际运行但非零退出或环境异常，必须保留失败；
- **未执行**：因权限、风险、时间或依赖未运行，说明原因和证据缺口。

### 5. 同伴反证

交换报告后完成三项复核：

1. 复制运行或定位一条验证命令，核对入口、用途和退出语义；
2. 核对一项风险的对象、证据和影响，并写出能够推翻该判断的条件；
3. 比较两份针对同一仓库、使用同一合同的 AI 初稿，找出至少一项不一致，并判断属于证据差异、表达差异还是模型不确定性。

复核不能只写“同意”“通过”或“看起来正确”。

## 独有产物与验收

本讲独有产物是《四段式仓库接手报告》及其修订证据。以下条件全部满足才通过：

- 课程规定的工具状态已记录，`doctor` 最终退出码为 0；
- 能证明本次采用真实只读边界，并记录仓库提交、网络、指令来源和实际命令；
- 报告准确说明 `flowerp/`、`workbench/`、`eval/`、`agent/`、`web/` 中至少三个目录的职责；
- 报告引用至少两条不可破坏的仓库规则；
- 报告包含至少一条仓库中真实存在、可复制运行的验证命令；
- 报告包含至少一项使用“对象—证据—影响—反证条件”结构表达的具体风险；
- 学生保留 AI 初稿并完成至少一项有证据的修订；
- 同伴完成命令、风险和输出分歧三项反证式复核；
- 没有把生成完成、运行完成或页面成功跨级写成发布完成。

以下任一情况直接退回修订：

- 编造命令、文件、版本、退出码、测试结果或风险证据；
- 环境检查未运行或退出非 0，却写“已通过”；
- 只在提示词中写“只读”，却不能证明实际权限边界；
- 暴露密钥、个人信息、客户数据、运行数据库或未经授权材料；
- 把“仅发现”或“未执行”的命令写成“已执行”或“已通过”；
- 直接提交 AI 初稿，没有学生判断与修订；
- 删除首次失败、初稿或同伴反馈；
- 把 20/8/12 事故分析或绿色页面当成本讲唯一产物。
