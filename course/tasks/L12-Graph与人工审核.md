# L12｜用 Graph 显式表达状态、回退和人工审核

- **核心内容**：共享状态、条件分支、审核打回、异常路径和人工介入；原生 Subagents 与外部编排框架的边界。
- **演示结果**：开发 → 测试 → 审核；审核失败回到开发，关键决策等待人工确认。
- **课内增量**：用最小 Python 状态图实现移交、回退、状态保存和审核结论。
- **验收命令**：`python -X utf8 -m agent.graph --max-rounds 3`
- **通过标准**：状态变化可追踪；审核结果来自 Eval；循环有上限；异常不会被静默忽略。
- **挑战任务**：用 LangGraph 替换最小状态图，同时保持相同输入、输出与验收命令。

## 项目主线与评价证据

- **FlowERP 现场问题**：本讲由 FlowERP 真实交付暴露可重复工程问题，用于触发工作台能力验证。

- **ERP 产品增量**：交付采购申请—人工审批—审批后入库闭环；未审批采购不得入库。
- **工作台增量**：增加显式 Graph、持久状态、回退、异常路径和具名审核。
- **双线因果**：采购既需要交付过程人审，也需要 ERP 领域审批，迫使工作台显式保存暂停和责任，同时证明两套状态机不混用。
- **ERP 验收证据**：未审批、匿名、打回和重复审批均不入库；具名批准后只入库一次；Graph Trace 与采购审计记录分别可查。
- **学生学习证据**：状态图、守卫表、Trace、匿名阻断和跨进程恢复记录。
- **形成性评价**：学生互换审核请求进行状态机审判，再依据非法迁移修订设计。

## 付费行动课交付合同

本讲不是画一张流程图。学员必须亲手交付：状态/边/守卫表；最小 Python Graph Diff；持久 checkpoint；批准、打回、匿名、重复、非法边、达到上限和崩溃恢复轨迹；具名人审材料包；Graph 与领域状态机分离证明；迁移到另一流程后的过度设计判断。

聊天中写“等待审核”、模型替人批准、异常被吞，或把采购状态机和交付 Graph 合成一张图，均按未完成处理。

## 主次边界

- **FlowERP 产品状态**：完成采购审批与审批后入库；模型不得代替审批人，匿名、重复或非法审批必须保持库存不变；
- **工作台主产物**是可恢复 Graph、边守卫、Trace、checkpoint 和 HITL 控制；
- **迁移证明**要为第二流程论证是否需要 Graph，能判断不用 Graph 也属于高阶成果。

## 课前独立诊断

调用 AI 或运行 Graph 前提交且不得覆盖：

1. blocking Eval 全绿为什么仍不能自动批准采购或交付？
2. 聊天里写“等待审核”为什么不等于可恢复暂停？
3. 订单状态、Task 状态和 Agent Graph 状态怎样避免混用？

## AI 使用与证据边界

- AI 可以建议状态与边，学生必须为每条迁移写前置、证据、责任人、失败语义和幂等要求；
- Graph 不得替代库存、订单、采购的领域状态机，也不得让模型代替具名审核人；
- `awaiting_human_review` 必须持久化并可跨进程恢复，匿名、重复和非法决定保持状态不变；
- Trace 记录迁移事实而非完整聊天和敏感推理，不得静默吞掉异常。

## 本讲主线

多个阶段和一次人工打回已经不能靠一串 `if` 与聊天记录可靠恢复。学员为每条边写守卫，把 `develop → test → awaiting_human_review`、拒绝回退、批准完成和异常终止持久化。本讲建立状态语义，不封装 HTTP。

## 大纲与前沿硬校准

- **必须完成**：最小 Python Graph 实现状态保存、打回、异常路径和具名审核，并可跨进程恢复。
- **当前做法**：显式边守卫、durable checkpoint、安全重放和 HITL 是基础；外部框架替换只属挑战。
- **退回条件**：模型自批、聊天记录充当 checkpoint、混用 Agent/订单/采购状态机或提前封装 HTTP。见[校准矩阵](../../docs/courses/16讲主线与前沿校准矩阵.md)。

## 必须教会的知识

1. **状态、边、守卫**：节点不是步骤名称列表；每条迁移要有允许条件、拒绝语义和写入证据。
2. **Router 与 Graph**：Router 选择候选下一跳，Graph 依据守卫决定迁移是否合法。
3. **真实暂停**：进入 `awaiting_human_review` 后进程可退出，状态文件可跨进程恢复；提示一句“等审核”不算暂停。
4. **具名且一次性的决定**：approve/reject 必须记录 reviewer、时间、理由，并抵抗匿名与重复提交。
5. **两类状态机分离**：Agent 交付 Graph 不得替代订单和采购的领域状态机。

## 课堂任务

```powershell
python -X utf8 -m workbench.cli course-contract --lesson 12
python -X utf8 -m workbench.cli course-spec --lesson 12
python -X utf8 -m workbench.cli course-submit --lesson 12 --execute-code
python -X utf8 -m workbench.cli course-eval --lesson 12
python -X utf8 -m agent.graph --max-rounds 3 --reject-once
python -X utf8 -m agent.graph --require-human-review --state-file .runtime/delivery-review.json
python -X utf8 -m agent.graph --state-file .runtime/delivery-review.json --review-decision approve --reviewer reviewer-a
```

- 打回路径必须回到 develop，并增加 round 和 reason。
- 暂停路径退出码为 3，重启后从同一 checkpoint 恢复。
- 匿名审核、重复审核和非法边必须失败，状态不变。
- 最大轮数或异常进入明确终态，并保留剩余失败。

## 独有产物与验收

提交状态图、逐边守卫表、Graph Trace、checkpoint 和具名恢复记录。Trace 每步必须含 from/to/reason/round/actor。自动越过人审、把聊天全文当状态、或混用 ERP 订单状态，均退回。

## 提交证据包与四级量规

证据包包含课前责任判断、状态归属卡、状态图、边守卫表、三类 Trace、checkpoint、匿名/重复阻断、人审材料、同伴审判和迁移设计。

| 维度 | 优秀 | 达成 | 发展中 | 未达成 |
|---|---|---|---|---|
| 状态建模 | 业务、Task、Graph 状态边界清楚且边可证明 | 核心状态和合法边完整 | 节点完整但守卫不足 | 混用状态机或非法边可走 |
| 暂停恢复 | 跨进程具名恢复、重复决定幂等 | 可暂停、恢复、打回 | 只在同进程等待 | 提示词等待、状态丢失 |
| 证据与异常 | Trace、Eval、actor、reason 和异常完整 | 关键迁移可追溯 | 少量字段缺失 | 匿名批准、异常吞掉或伪造 Trace |
| 学生审判 | 能用反例改进一条边或守卫 | 至少一项有证据修订 | 只美化流程图 | 直接提交 AI 图示 |

硬门槛：自动越过人审、匿名审核成功、循环无上限、异常静默、混用 ERP 状态，直接退回。

## 持续改进与迁移

记录非法迁移识别率、匿名审核阻断率、跨进程恢复成功率、Trace 字段完整率和修订增值。迁移时必须先证明流程确需回退、暂停或恢复，避免为了术语使用 Graph。
