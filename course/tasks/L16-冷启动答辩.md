# L16｜冷启动发布与工程答辩

- **核心内容**：容器化、健康检查、回滚意识、演示叙事和技术债说明。
- **演示结果**：从干净环境启动系统，展示一次成功任务、一次失败打回、一次结果导出和一次反馈写入。
- **课内增量**：完成结业检查表与五分钟答辩稿。
- **最终验收命令**：

  ```bash
  python -X utf8 -m workbench.cli demo
  python -X utf8 -m eval.harness --suite blocking
  python -X utf8 -m agent.loop --max-rounds 3
  python -X utf8 -m agent.graph --max-rounds 3
  python -X utf8 -m workbench.feedback summary
  ```
- **通过标准**：需求能生成 Spec 和代码；阻断级 Eval 全部通过；Loop 收敛或如实安全退出；Graph 审核结论可追踪；摘要和反馈能够正确生成；干净环境可启动且仓库无密钥。
- **挑战任务**：部署到个人测试环境，提交健康检查、资源上限和回滚说明。

## 项目主线与评价证据

- **FlowERP 现场问题**：本讲由 FlowERP 真实交付暴露可重复工程问题，用于触发工作台能力验证。

- **ERP 产品增量**：由评审者从候选池抽取一个此前未实现的小需求，现场经工作台交付或诚实打回。
- **工作台增量**：完成容器化、健康检查、发布证据索引、结业检查表和答辩稿。
- **双线因果**：只有陌生环境中的新 ERP 需求仍能形成 Spec、Diff、Eval 和人审，才能证明工作台不是围绕固定答案搭出的演示壳。
- **ERP 验收证据**：评审者抽题、现场 Spec、允许写集、真实 Diff、正常/失败 Eval、ERP 状态对账、具名结论和剩余风险。
- **学生学习证据**：陌生环境冷启动、随机成功/失败、导出、反馈、回滚和技术债答辩。
- **形成性评价**：作者与评审者交叉答辩；口头补步骤和未声明风险进入修订清单。

## 付费行动课交付合同

本讲不是作者按固定剧本演示功能。学员必须亲手交付：空环境指纹；可复现启动与健康检查；发布证据索引；评审者从受控候选池抽取的新需求及其 Spec、Diff、正反 Eval；重启连续、反馈追溯和结果导出；备份恢复或回滚演练；五分钟答辩；未证明边界和技术债；作者退场后的陌生人操作记录。

借现场需求掩盖旧问题或扩大到候选池外、复用旧运行目录、作者口头补步骤、只展示 happy path，或把容器启动写成生产就绪，均按未完成处理。

## 主次边界

- **FlowERP 产品状态**：在复验既有不变量后，必须现场交付一个范围受控的新需求；若正确打回，需给出可复现失败与剩余授权；
- **工作台主产物**是可冷启动、可质疑、可恢复、可交接的完整研发自动化系统及证据索引；
- **迁移证明**由陌生评审者操作和随机追问完成，作者熟练度不能替代可交接性。

## 课前独立诊断与诚信声明

答辩前独立提交且不得覆盖：

1. 当前作品已经证明什么、尚未证明什么、最可能依赖哪项隐式环境？
2. “Docker 能启动”为什么不等于生产就绪？
3. 哪个恢复、回滚或安全指标尚无真实数据？

学生同时确认：不复用旧运行数据冒充冷启动，不伪造用户反馈、审核身份、Run 或教学成效，不提交密钥、个人敏感信息和未经授权作品。

## 混合式答辩流程

| 场域 | 学习任务 | 必须留下的证据 |
|---|---|---|
| 线上 30 分钟 | 只说明规则、随机抽查、证据索引和数据边界，不预演正式路径 | 风险预测、索引草图、诚信声明 |
| 线下 100 分钟 | 陌生人冷启动、随机正反路径、重启、恢复、反馈追溯和五分钟答辩 | 环境指纹、日志、索引、随机问答、具名结论 |
| 答辩后修订 | 对“带条件通过/退回”项按原证据复验 | 修订前后版本和复验入口 |

## AI 使用与证据边界

- AI 可以协助整理索引和排练表达，不能代替陌生评审者操作、随机抽查或具名判定；
- 正式答辩固定 commit 和环境指纹，使用空运行目录；旧 `.runtime`、旧数据库、缓存结果和预录视频不能替代现场证据；
- 任何自动化仍受既有 Sandbox、审批、人审和数据边界约束，答辩不会扩大权限；
- 不可验证的商用、性能、恢复时间、安全或教学效果指标必须写“未验证/待采集”。

## 本讲主线

作者退出操作位，由陌生评审者在空运行目录启动系统，先随机复验一次成功、一次正确失败、一次重启恢复和一次反馈追溯，再从受控候选池抽取此前未实现的小需求。学员必须用工作台现场交付或诚实打回，而不是靠旧会话、固定答案和口头补步骤。

## 大纲与前沿硬校准

- **必须完成**：干净环境随机完成成功、失败打回、导出、反馈、重启/恢复和五分钟答辩，证据可由陌生人回查。
- **当前做法**：可重复构建、环境指纹、健康/恢复/回滚是基础；Attestation/SBOM 只增强来源核验。
- **退回条件**：需求越过受控候选池、复用旧运行目录、固定剧本、把容器启动/签名写成生产就绪或伪造教学成效。见[校准矩阵](../../docs/courses/16讲主线与前沿校准矩阵.md)。

## 必须教会的知识

1. **冷启动合同**：固定版本、环境指纹、显式配置、初始化、健康检查和种子数据必须可按文档复现。
2. **持久与恢复**：重启后 Task、事件、审核和业务状态连续；备份要校验可读并完成恢复验证。
3. **发布证据索引**：从业务对象、Task、Harness、Graph Trace、reviewer、Feedback 相互回指，结论可被抽查。
4. **正确失败演示**：库存不足、未审批收货或服务失联必须保持合法不变状态，不能只展示 happy path。
5. **诚实边界**：可安装不等于可商用；同步 Worker、单仓模型、SQLite 并发和未实测恢复指标必须明示。

## 课堂任务

### 产品化思考随机答辩

评审者从 L01、L03、L12、L14、L15 的记录中随机抽一条。学生在三分钟内回答：首次判断、直接证据、被推翻点、最终产品减法、剩余风险和下次复查触发器，并现场定位对应记录。至少展示一次 `reject / quick path / merge / hide / remove / stop`，证明工作台进化不是只增加功能。

该项作为产品迁移形成性证据进入答辩档案；冷启动、随机新需求、正确失败、证据索引和具名评审仍是大纲基础通过线。

```powershell
python -X utf8 -m workbench.cli course-status --require-baselines
python -X utf8 -m workbench.cli course-contract --lesson 16
python -X utf8 -m workbench.cli course-spec --lesson 16 --eval-case live_draw_rule_is_enforced
python -X utf8 -m workbench.cli course-submit --lesson 16 --execute-code --eval-case live_draw_rule_is_enforced --session-baseline-ref refs/heads/l16-session-red
python -X utf8 -m workbench.cli course-eval --lesson 16 --case live_draw_rule_is_enforced
docker compose -f deploy/docker-compose.yml up --build
```

- 评审者指定空运行目录，不使用旧 `.runtime`、旧数据库或旧会话。
- 现场复现 20/8/12 阻断、审批后幂等入库、恢复履约。
- 重启后查询同一 Task 和具名审核；抽查一条 Feedback 的后序验证。
- 验证备份可恢复，或按 `deploy/ROLLBACK.md` 完成有证据的恢复演练。

## 四级结业量规与硬门槛

| 维度 | 优秀 | 达成 | 发展中 | 未达成 |
|---|---|---|---|---|
| 冷启动与恢复 | 陌生人零口头补充完成启动、重启、备份恢复 | 空环境可启动，关键状态连续 | 需一次非关键补充或恢复证据不全 | 依赖旧数据/作者操作或无法恢复 |
| 端到端证据 | 成功、正确失败、打回、导出、反馈均可沿 ID 下钻 | 大纲最终通过标准逐项有证据 | 个别链路需口头解释 | blocking 红、匿名审核或链路伪造 |
| 工程答辩 | 五分钟结论清楚，随机追问能定位文件/命令/风险 | 已证明与未证明边界准确 | 叙事完整但风险笼统 | 夸大生产/商用能力或回避失败 |
| 责任与交接 | 安全、知识产权、技术债、责任人和复验入口完整 | 结业检查表和索引可交接 | 责任或期限不清 | 密钥/敏感信息泄露、证据删除 |

通过要求：全部维度至少“达成”，且唯一大纲中的最终通过标准逐项通过。任何伪造证据、旧数据冒充冷启动、匿名审批、blocking 红灯宣称通过或敏感数据泄露，直接未达成。

## 课程达成与持续改进数据

结课只计算真实学生的 CLO 达成率、首次/修订增值、陌生人冷启动成功率、口头补步骤数、随机抽查通过率、证据回链率和过度声明次数。没有两个真实教学周期、学生记录或校方材料时必须标记“待建设/待采集”，不得用参考仓库 Eval 结果补齐国家级课程申报证据。

课程在这里结束的不是学习循环。第一条新现场反馈应重新进入 L03，而不是绕过合同直接回到编码。
