# L04｜委托 Codex 执行一次最小变更

- **核心内容**：非交互执行、工作目录、权限边界、结果采集与人工确认点。
- **演示结果**：读取第 3 讲 Spec，委托 Codex 完成一个小型代码变更并运行测试。
- **课内增量**：完成执行入口和结果摘要；仓库文件由 Codex 在授权工作区直接处理，不额外包装为文件读写 MCP。
- **通过标准**：变更能够运行；基础测试通过；摘要包含修改文件、验证命令和剩余风险；密钥和环境文件未提交。

## 项目主线与评价证据

- **FlowERP 现场问题**：本讲由 FlowERP 真实交付暴露可重复工程问题，用于触发工作台能力验证。

- **ERP 产品增量**：由工作台实现并验收库存导出，覆盖正常、空集和写失败路径。
- **工作台增量**：形成 Codex 执行入口、基线派生的隔离 Worktree、写集边界、执行前后 Eval 和结果摘要，完成 Workbench V0。
- **双线因果**：首个 ERP 实现暴露宽泛委托的越界风险，迫使工作台建立能力信封；升级后的工作台必须真正交付库存导出。
- **ERP 验收证据**：库存导出真实 Diff；正常、空集和写失败用例；非执行者用同一 Spec 独立签收。
- **学生学习证据**：能力信封、真实 Diff、边界测试、独立复验和风险摘要。
- **形成性评价**：执行者不能给自己判定成功，由同伴按文件级因果关系复核。

## 付费行动课交付合同

本讲不是观看 Codex 写代码。学员必须亲手交付：由 L03 验收项反推的读/写/禁止集；一次只计划不写入的越界预测；一次受控真实执行；白名单外写入阻断证据；空集/特殊字符/写失败测试；逐文件 Diff 因果审查；非执行者独立复验和剩余风险摘要。

直接运行宽泛 Prompt、用模型自述代替复验、或把无关重构包装成“顺手优化”，均按未完成处理。

## 主次边界

- **FlowERP 产品状态**：必须完成 L03 库存导出，不扩展到无关采购或 Web；这是一项真实产品增量而非演示夹具；
- **工作台主产物**是能力信封、受控执行入口、写集约束、结果采集和独立复验协议；
- **迁移证明**要求在第二个小型 Spec 上先设计授权，不能靠复用同一 Prompt 证明可迁移。

## 课前独立诊断

在运行 Codex 前提交且不得覆盖：

1. 从 L03 Spec 推导预计读集、写集、禁止集和人工确认点。
2. “改动文件少”为什么仍不一定是最小闭环？
3. 哪些证据必须由非执行者独立取得？

## 混合式学习流程

| 场域 | 学习任务 | 必须留下的证据 |
|---|---|---|
| 线上 30 分钟 | 建立能力信封、六段式委托、最小 Diff 与独立复验模型 | 首次判断、写集草图、越界预测 |
| 线下 70 分钟 | 受控执行、边界测试、Diff 五问和非执行者复验 | 运行轨迹、红绿证据、审查与摘要 |
| 课后迁移 | 在新 Spec 上先设计授权再执行或只做纸面审批 | 迁移能力信封与风险差异 |

## AI 使用与证据边界

- 写入只允许发生在隔离工作区和显式白名单内；网络、依赖安装、提交、推送及敏感文件默认禁止；
- 委托采用目标、上下文、允许、禁止、输出证据、完成/停止六段式，并记录工具、模型可见信息、提交和实际命令；
- 模型声称测试通过不计证据，委托者必须重跑并保存退出码；
- 任何写集扩张、未知脚本、密钥请求或不可逆动作都必须停止并重新授权。

## 本讲主线

L03 的库存可用量导出 Spec 固定后，只授权实现这一条最小闭环。学员比较宽泛委托与受限委托的 Diff，解释每个改动为什么属于导出合同，并由非执行者独立复验。低库存标记只作为课后同构迁移。本讲教授变更控制，不扩建通用 Agent 平台。

## 大纲与前沿硬校准

- **必须完成**：消费 L03 Spec，形成执行入口、受控 Diff、独立复验和包含修改文件/命令/风险的摘要。
- **当前做法**：显式工作目录、写入白名单、最小权限是基础；JSONL 与输出 Schema 是可替换增强。
- **退回条件**：扩建通用 Agent 平台、用 MCP 包装基本文件操作、顺手重构或让执行者给自己判成功。见[校准矩阵](../../docs/courses/16讲主线与前沿校准矩阵.md)。

## 必须教会的知识

1. **能力信封**：请求、写入范围、超时、执行模式和验证命令共同构成授权，Prompt 不是全部权限。
2. **最小变更半径**：从验收项反推最少模块、接口和测试，不“顺手重构”。
3. **边界测试**：空集、稳定顺序、特殊字符和写入失败比单一 happy path 更能约束导出语义。
4. **Diff 审查**：逐文件核对范围、因果关系、兼容性、秘密和生成产物。
5. **独立复验**：模型自述与其运行日志都不能替代委托者重跑命令。

## 课堂任务

```powershell
python -X utf8 -m workbench.cli course-contract --lesson 4
python -X utf8 -m workbench.cli course-spec --lesson 4
python -X utf8 -m workbench.cli course-submit --lesson 4 --execute-code --execution-timeout 900
python -X utf8 -m workbench.cli course-eval --lesson 4
```

- 正常路径：只修改导出所需领域代码和相应测试，字段、可用量与稳定顺序符合 Spec。
- 边界路径：空集、特殊字符和写入失败至少三类断言通过，失败不留半成品。
- 失败路径：要求同时重命名库存模型、改 Web 配色或修改白名单外文件，执行应拒绝或评审退回。
- 不变状态：预占、幂等入库、采购审批行为不变；运行数据库和报告不入库。

## 独有产物与验收

提交基线标签、隔离 Worktree 身份、写集说明、执行前红灯、真实 Diff、执行后绿灯、命令/退出码/Token 记录和剩余风险。任何白名单外写入、基线预先为绿、零改动、无关重构或“Codex 说测试通过但未独立重跑”均退回。

## 提交证据包与四级量规

证据包包含课前授权判断、六段式委托、权限配置、AI 原始轨迹、Diff、边界红绿证据、非执行者复验、修订说明、交付摘要和迁移能力信封。

| 维度 | 优秀 | 达成 | 发展中 | 未达成 |
|---|---|---|---|---|
| 授权控制 | 能力信封可机器约束且遇扩范围会停止 | 读写/禁止集和停止条件明确 | 只在提示词中约束 | 越权写入、联网或读取敏感数据 |
| 最小闭环 | 每个文件都可回指验收项且无因果污染 | 变更范围合理、功能完整 | 少量无关改动或解释不足 | 大规模顺手重构、跳过 Spec |
| 验证证据 | 边界、失败和独立复验齐全 | 基础测试和关键边界通过 | 只有模型日志或单一 happy path | 未运行却写通过、删除失败证据 |
| 学生审查 | 能发现 AI 初稿问题并实质修订 | 至少一项有证据修订 | 只改摘要文字 | AI 自审自签收 |

硬门槛：白名单外写入、秘密/环境文件进入提交、未经授权推送、未独立复验却宣称完成，直接退回。

## 持续改进与迁移

记录越界率、无关改动率、边界漏测率、独立复验完成率和首次/修订量规变化；Token 数据不可核验时写“未知”。迁移必须重新推导能力信封，不能沿用本讲文件白名单。
