# L07｜用 Codex Hooks 建立本地护栏

- **核心内容**：生命周期 Hook、信任边界、超时、失败策略，以及 Hook 与 Git Hook 的区别。
- **演示结果**：Codex 在关键生命周期节点运行质量检查并反馈失败。
- **课内增量**：配置一个项目级质量 Hook，调用统一 Harness，而不是复制另一套质量逻辑。
- **通过标准**：Hook 来源可检查；故意引入违规时流程被阻断；恢复后重新通过。

## 项目主线与评价证据

- **FlowERP 现场问题**：本讲由 FlowERP 真实交付暴露可重复工程问题，用于触发工作台能力验证。

- **ERP 产品增量**：交付销售订单创建；缺货时订单与库存状态均不得变化。
- **工作台增量**：接入项目级 Codex Hook，并明确来源、超时、失败和重入策略。
- **双线因果**：订单进入库存高风险区，而执行者可能漏跑 Harness，迫使工作台在生命周期末端自动复验；领域守卫仍由 ERP 服务执行。
- **ERP 验收证据**：合法销售订单创建成功；缺货订单不落单、不预占；Hook 违规阻断与恢复后的报告可回查。
- **学生学习证据**：三组 Hook 输入输出、违规阻断、恢复通过和安全审查记录。
- **形成性评价**：协议损坏、复制 Eval 或无限重入均须依据原事件修订。

## 付费行动课交付合同

本讲不是把一条命令贴进 Hook 配置。学员必须亲手交付：Hook 来源/权限/哈希审计；项目配置与处理器 Diff；全绿、阻断、`stop_hook_active=true`、畸形 JSON、超时五组协议测试；stdout/stderr 分离证据；失败后的可复现消息；为另一个不可逆风险完成触发点迁移论证。

未经审查启用仓库 Hook、在处理器复制 Eval、协议输出混入日志，或用 PostToolUse 文案冒充撤销副作用，均按未完成处理。

## 主次边界

- **FlowERP 产品状态**：由工作台交付销售订单创建，合法路径成功、缺货路径正确失败，并由 Hook 自动调用既有 Harness；
- **工作台主产物**是可审查的生命周期触发器、协议处理器、重入/超时控制和错误消息合同；
- **迁移证明**要为非 FlowERP 风险选择触发点，并说明为什么不能照搬 Stop Hook。

## 课前独立诊断

调用或启用 Hook 前提交且不得覆盖：

1. Stop、PreToolUse、PostToolUse 分别适合阻断哪类动作？
2. 为什么未知仓库中的 Hook 不能直接信任？
3. `stop_hook_active` 缺失可能产生什么后果？

## AI 使用与证据边界

- 项目 Hook 是将要执行的仓库代码，必须先人工审查来源、命令、哈希、权限、网络和超时；
- Hook 只能调用 L06 的统一 Harness，不得复制、弱化或临时改写质量逻辑；
- stdin/stdout 协议、诊断 stderr 和退出码必须分离；AI 摘要不能替代原事件 JSON；
- 危险动作应在副作用前阻断；已发生副作用不能靠 PostToolUse 文案假装撤销。

## 本讲主线

Harness 已经可靠，但执行者准备结束工作时可能漏跑。学员把统一质量入口接到 Stop Hook，逐字段推演输入、输出、续跑和重入保护。本讲只解决本地生命周期触发，不声称它能保证远端分支可信。

## 大纲与前沿硬校准

- **必须完成**：项目级 Hook 调用同一 Harness，并保存来源审查、违规阻断、恢复通过与重入证据。
- **当前做法**：按开课时官方协议验证结构化决定和 `stop_hook_active`，协议变化时保留相同能力合同。
- **退回条件**：复制或弱化 Eval、把 Hook 当 CI/事务/授权系统、未经审查执行仓库 Hook。见[校准矩阵](../../docs/courses/16讲主线与前沿校准矩阵.md)。

## 必须教会的知识

1. **触发点选择**：结束前复验能阻止无证据收尾；不可逆动作应在更早的业务守卫中阻断。
2. **协议而非脚本拼接**：Hook 从 stdin 读取事件 JSON，通过 stdout 返回结构化决定，诊断信息与协议输出分离。
3. **信任边界**：项目 Hook 是仓库代码，启用前要检查来源、哈希、命令和权限。
4. **重入保护**：`stop_hook_active` 防止失败消息再次触发同一个 Stop Hook 形成无限续跑。
5. **可操作消息**：失败响应只携带报告身份、复现命令和必要尾部证据，不把全部日志塞回上下文。

## 课堂任务

```powershell
python -X utf8 -m workbench.cli course-contract --lesson 7
python -X utf8 -m workbench.cli course-spec --lesson 7
python -X utf8 -m workbench.cli course-submit --lesson 7 --execute-code
python -X utf8 -m workbench.cli course-eval --lesson 7
```

- 配置：`.codex/hooks.json`；处理器：`.codex/hooks/quality_gate.py`。
- 用 `/hooks` 检查来源与信任状态。
- 正常路径：Harness 全绿，Stop 正常完成。
- 失败路径：引入阻断缺陷，Hook 返回继续修复所需证据。
- 重入路径：输入 `stop_hook_active=true`，不得再次续跑。
- Windows 路径必须从 Git 根解析 `commandWindows`，不能依赖讲师机器绝对路径。

## 独有产物与验收

提交三组 Hook 输入/输出 JSON、调用的 Harness 报告、退出行为和安全审查记录。复制 Eval 逻辑进 Hook、信任未知项目脚本、混写 stdout 导致协议损坏或缺少重入保护，均退回。

## 提交证据包与四级量规

证据包包含课前事件判断、来源与权限审查、配置注释、全绿/阻断/重入 JSON、协议故障、Harness 回链、修订稿、同伴复验和迁移选点。

| 维度 | 优秀 | 达成 | 发展中 | 未达成 |
|---|---|---|---|---|
| 事件选点 | 依据可逆性和损失选择最早有效 Gate | Stop/Pre/Post 职责正确 | 选点可用但理由不足 | 在副作用后假装阻断 |
| 信任与权限 | 来源、哈希、命令、网络和最小权限完整 | 启用前完成必要审查 | 只看文件名或讲师口述 | 未审查即执行未知 Hook |
| 协议与重入 | 三种路径可复现且异常安全降级 | JSON 合法、调用同一 Harness、有重入保护 | 消息或超时处理不完整 | 无限循环、stdout 污染或复制 Eval |
| 学生修订 | 能从原事件定位并修订协议问题 | 至少一项实质修订 | 只改提示文案 | 删除失败或直接交 AI 初稿 |

硬门槛：未经审查运行未知 Hook、复制或降低 blocking 规则、无限重入、隐藏失败，直接退回。

## 持续改进与迁移

记录事件选点误判率、协议损坏率、重入阻断率、来源审查完整率和修订增值。产品事件和字段可能变化，正式授课前须按当前官方文档重新核验并注明日期。
