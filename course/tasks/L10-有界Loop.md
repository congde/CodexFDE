# L10｜建立有停止条件的修复 Loop

- **核心内容**：最大轮数、达标即停、无进展检测、时间与 Token 预算、安全退出。
- **演示结果**：修复循环成功收敛一次，并展示一次未收敛退出。
- **课内增量**：串联“执行 → Eval → 生成修复任务 → 再执行”。
- **验收命令**：`python -X utf8 -m agent.loop --max-rounds 3`
- **通过标准**：最多三轮；达标即停止；无进展或预算耗尽时输出剩余失败，不宣称成功。

## 项目主线与评价证据

- **FlowERP 现场问题**：本讲由 FlowERP 真实交付暴露可重复工程问题，用于触发工作台能力验证。

- **ERP 产品增量**：修复订单非法状态迁移，订单只能沿定义状态机前进。
- **工作台增量**：串联执行、Eval、Repair Task 与再执行，加入预算和停止条件。
- **双线因果**：状态机缺陷可能反复失败或振荡，迫使工作台形成有预算的修复 Loop；只有 blocking Eval 全绿才能宣称该 ERP 增量完成。
- **ERP 验收证据**：合法迁移通过、非法跳转保持原状态；收敛轨迹回指最终 Diff，未收敛轨迹保留剩余失败。
- **学生学习证据**：成功与未收敛两条 Loop History、用量和停止原因。
- **形成性评价**：先画控制回路、再运行验证；把轮数用完写成成功直接退回。

## 付费行动课交付合同

本讲不是把 Agent 放进 `for` 循环。学员必须亲手交付：Loop 控制合同；失败签名实现；立即成功、同签名无进展、振荡/新回归、墙钟超时、Token 未知或耗尽至少五条轨迹；每轮 History 与 Diff；执行者/裁判职责分离测试；安全交接包；迁移到一个禁止自动修复任务的启动判决。

只有 `max_rounds=3`、用量不可核验仍继续、失败减少就宣称成功，或循环中修改 Eval/扩大权限，均按未完成处理。

## 主次边界

- **FlowERP 产品状态**：通过有界 Loop 修复订单状态迁移；另保留一条不能收敛的故障轨迹作为诚实退出证据；
- **工作台主产物**是跨轮控制器、预算、停止语义、History 和交接协议；
- **迁移证明**要识别一个不应启动 Loop 的非 ERP 高风险任务，并给出人工入口。

## 课前独立诊断

启动 Loop 前提交且不得覆盖：

1. 连续两轮失败数量不变，什么证据能区分“无进展”与“失败对象发生变化”？
2. 为什么只配置 `max_rounds=3` 仍不是安全 Loop？
3. Token 用量不可核验时应该继续、假定为 0，还是停止？

## AI 使用与证据边界

- 每轮只消费当前 Repair Task，不得暗换目标、扩大写集或修改 Eval；
- 模型执行权限不因进入 Loop 而扩大，仍受 Sandbox、审批、网络和能力信封约束；
- 失败签名、用量、时间和退出码来自运行事实；未知用量不能按 0 处理；
- 达标即停，无进展、振荡、Guardrail 回归、预算耗尽或异常均安全退出并保留剩余失败。

## 本讲主线

同一 Repair Task 连续两轮得到相同失败。学员把“再试一次”改造成可审计控制系统：每轮采样 Harness、执行一次受限动作、比较失败签名，并在成功、无进展或预算耗尽时明确停止。本讲只控制串行修复，不引入并行。

## 大纲与前沿硬校准

- **必须完成**：最多三轮，展示一次全绿收敛与一次未收敛退出，并保留每轮报告、用量和 stop reason。
- **当前做法**：失败签名、无进展/振荡、墙钟和可核验 Token 共同控制；Goal 不扩大原 sandbox/approval。
- **退回条件**：并行任务、暗换目标、未知用量按零、轮数耗尽或失败变少就宣称成功。见[校准矩阵](../../docs/courses/16讲主线与前沿校准矩阵.md)。

## 必须教会的知识

1. **唯一成功态**：只有 blocking Harness 全绿才叫收敛；轮数用完、失败变少或模型自述都不是成功。
2. **失败签名**：用稳定 case identity 与关键 actual 比较轮次，避免把日志时间戳当进展。
3. **进展判定**：Target 改善不能抵消 Guardrail 回归；新失败意味着候选可能扩大了损害。
4. **四类预算**：最大轮次、无进展阈值、墙钟超时、可核验 Token 用量共同限制执行。
5. **安全交接**：停止时保存每轮报告、变更、用量、stop reason 和剩余失败，不伪装成功。

## 课堂任务

```powershell
python -X utf8 -m workbench.cli course-contract --lesson 10
python -X utf8 -m workbench.cli course-spec --lesson 10
python -X utf8 -m workbench.cli course-submit --lesson 10 --execute-code
python -X utf8 -m workbench.cli course-eval --lesson 10
python -X utf8 -m agent.loop --max-rounds 3
python -X utf8 -m agent.loop --max-rounds 3 --codex
python -X utf8 -m agent.loop --max-rounds 3 --timeout 900 --token-budget 30000 --codex
```

- 默认路径不得调用模型，只评估当前基线。
- 全绿路径第一轮立即停止为 success。
- 无进展路径连续相同失败签名后停止。
- 预算路径达到时间或实测 Token 上限后停止；用量不可核验时不得假定仍有预算。

## 独有产物与验收

提交 Loop History，逐轮包含输入报告、Repair Task、执行结果、失败签名、用量和停止原因。只设 `max_rounds`、中途暗换任务、Guardrail 回归仍继续，或把 `max_rounds_reached` 写成完成，均退回。

## 提交证据包与四级量规

证据包包含课前控制判断、控制合同、三类原始轨迹、每轮报告/Diff/用量、停止原因、同伴听证、交接包和迁移设计。

| 维度 | 优秀 | 达成 | 发展中 | 未达成 |
|---|---|---|---|---|
| 停止控制 | 能识别收敛、停滞、振荡和 Guardrail 回归 | 四类核心停止条件有效 | 仅最大轮数可靠 | 无限循环或假成功 |
| 预算执行 | 时间、Token、轮次和计量缺失均受控 | 达预算即停并保留证据 | 只记录配置预算 | 超限继续或把未知当 0 |
| 轨迹追溯 | 每轮输入、动作、报告、Diff 和签名可回放 | 主要字段完整 | 缺一类运行事实 | 覆盖历史或删除失败 |
| 停止交接 | 能据证据选择重试、分拆、转人或改 Spec | 剩余失败和下一步明确 | 只写“未成功” | 将安全退出写成完成 |

硬门槛：修改或降低 Eval、越权扩大任务、预算耗尽仍继续、`max_rounds_reached` 冒充成功，直接退回。

## 持续改进与迁移

记录假成功率、无进展/振荡识别率、预算超限率、停止原因解释正确率和首次/修订变化。成本与 Token 数据必须来自可核验轨迹，无法取得时写“未知”。
