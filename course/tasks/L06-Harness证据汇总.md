# L06｜用 Harness 汇总证据和等级

- **核心内容**：用例发现、统一退出码、阻断级与观察级指标、机器可读报告。
- **演示结果**：Harness 输出分项结果、阻断结论和 JSON 报告。
- **课内增量**：实现最小 Harness，将第 5 讲用例纳入统一执行。
- **通过标准**：阻断用例失败时返回非零退出码；观察项失败只记录告警；报告保留运行时间和失败原因。
- **挑战任务**：增加跨项目回归用例并说明其适用边界。

## 项目主线与评价证据

- **FlowERP 现场问题**：本讲由 FlowERP 真实交付暴露可重复工程问题，用于触发工作台能力验证。

- **ERP 产品增量**：交付统一的可用库存口径，并验证可用库存不得为负。
- **工作台增量**：建立统一 Harness、等级语义、JSON 报告和退出码合同。
- **双线因果**：幂等、库存口径和工程检查同时出现后无法靠多盏散灯放行，迫使工作台建立唯一机器判决。
- **ERP 验收证据**：在库、预占、可用数量三者对账；缺货和异常聚合不修改业务账；相关用例进入 Harness JSON。
- **学生学习证据**：阻断、观察、异常三类报告及 decision/exit code 对照。
- **形成性评价**：学生先预测机器结论，再运行验证并解释预测偏差。

## 付费行动课交付合同

本讲不是运行现成 Harness 看 JSON。学员必须亲手交付：报告 Schema 与消费者合同；用例发现/隔离/分级实现；blocking、observing、error 三个可控夹具；decision/exit code 合同测试；报告写入失败测试；一个只依赖稳定字段的下游消费者；用第二项目报告验证兼容边界。

只展示 `.runtime` 成品、把异常记成 pass、让 observing 误阻断，或让 Hook/CI 复制质量逻辑，均按未完成处理。

## 主次边界

- **FlowERP 产品状态**：新增可用库存查询并与 L05 幂等入库共同进入 Harness；聚合异常不得改变业务账；
- **工作台主产物**是与具体 ERP 解耦的 Harness、机器报告、退出码和消费者合同；
- **迁移证明**必须让一个非 FlowERP 命名报告或第二项目用例进入同一 Schema，并说明适用边界。

## 课前独立诊断

调用 AI 前提交且不得覆盖：

1. “16 绿 1 个 blocking 红”和“1 个 observing 红”应分别怎样退出？
2. 用例异常或报告写入失败能否记为通过？
3. 哪些字段是 Hook、CI、Loop 和 Graph 都需要的稳定合同？

## 混合式学习流程

| 场域 | 学习任务 | 必须留下的证据 |
|---|---|---|
| 线上 30 分钟 | 建立分级、报告 Schema、decision/exit code 合同 | 首次裁决、字段责任表、结果预测 |
| 线下 70 分钟 | 运行 blocking、observing 和 error 三类场景并让同伴消费报告 | JSON、退出码、异常证据、具名裁决 |

## AI 使用与证据边界

- AI 可解释报告和提出 Schema 草案，但不得替学生决定业务风险等级；等级变化必须有具名理由；
- 命令状态必须标为已执行、执行失败或未执行，发现入口不能写成已经运行；
- Harness 只聚合和裁决，不让模型从失败文本编造唯一根因，也不执行修复；
- 报告、运行目录和日志若含敏感字段，先最小化或脱敏再用于模型分析。

## 本讲主线

业务 Eval、秘密扫描、观察指标和运行异常同时出现时，谁决定能否放行？学员把不同信号纳入一个稳定 JSON 合同，并验证 `decision` 与进程退出码绝不矛盾。本讲教授聚合与判决，不讲何时自动触发 Harness。

## 大纲与前沿硬校准

- **必须完成**：统一发现 L05 用例，输出 blocking/observing/error 语义、稳定 JSON 和一致退出码。
- **当前做法**：Trace 用于调试，版本化 Dataset/Eval run 用于重复比较；快速变化的观测字段只作观察。
- **退回条件**：Harness 猜根因或修代码、模型评分替代确定性判决、下游复制第二套质量规则。见[校准矩阵](../../docs/courses/16讲主线与前沿校准矩阵.md)。

## 必须教会的知识

1. **Eval Harness 职责**：组织用例、隔离执行、记录证据、分级并给出机器判决；不编造根因，不执行修复。
2. **等级语义**：blocking 失败阻断；observing 失败保留为告警；未执行和基础设施异常不能伪装成通过。
3. **报告 Schema**：suite、case identity、status、expected/actual、evidence、duration、decision 和生成时间要稳定。
4. **退出码合同**：blocking 全绿退出 0；任一 blocking 失败退出 1；报告写入失败也必须非零。
5. **消费者合同**：本地、Hook、CI、Loop、Graph 读取同一报告，不复制另一套质量逻辑。

## 独有产物与验收

提交 Harness JSON、三种运行的退出码对照表和一份消费者字段合同。固定测试数量、只看终端颜色、observing 失败阻断，或 `decision=pass` 但退出非零，均退回。

## 提交证据包与四级量规

证据包包含课前预测、blocking/observing/error 三类原始运行、JSON、退出码、字段合同、预测偏差修订、同伴消费者结论和迁移 Schema。

| 维度 | 优秀 | 达成 | 发展中 | 未达成 |
|---|---|---|---|---|
| 分级判断 | 能依据失败代价解释等级并识别误分级 | blocking/observing/error 语义正确 | 只记颜色、不解释风险 | 观察项阻断或阻断项放行 |
| 报告合同 | 身份、状态、证据、耗时和决策稳定且可扩展 | 关键字段齐全可消费 | 字段缺失或依赖固定数量 | 报告丢失、异常记 pass |
| 退出一致 | 终端、JSON、退出码三者完全一致 | blocking 红非零，观察红不阻断 | 只核对其中两项 | decision 与退出码矛盾 |
| 学生裁决 | 能解释预测偏差并具名修订 | 至少一项有证据修订 | 仅抄 Harness 结论 | 让 AI 编造根因或签收 |

硬门槛：blocking 失败仍退出 0、异常吞掉、报告写入失败却写通过或修改历史报告，直接退回。

## 持续改进与迁移

记录分级误判率、报告/退出码矛盾数、异常吞噬率、消费者复现率和修订增值。跨项目字段不得照搬业务数量，应保留稳定身份、状态与证据语义。
