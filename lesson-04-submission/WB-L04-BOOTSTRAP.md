# WB-L04-BOOTSTRAP｜个人研发工作台 V0 建设与复验合同

## 来源

本合同依据 L04“委托 Codex 执行一次最小变更”的课程要求，承接 L01 的工作台 Spec、任务与命令证据账，L02 的 AGENTS 规则，以及 L03 的 Spec 模板与解析器。

本轮要解决的问题是：有了规则与需求合同，仍需证明工作台能限制 Codex 的修改范围、保留真实执行和检查结果，并将接受决定交给人。学生直接监督 Codex 补齐工作台，通过 Ticket A 独立验收当前控制版本后，才由 V0 组织库存导出 Ticket B。

这是待本人核对的建设合同初稿，不是已完成记录。开始建设前，在已有任务记录中补充前序成果的实际路径、当前版本、已有能力、本轮缺口、构建者及独立复验者。课堂设定与真实经历分别标注，不补写未发生的访谈、失败或验收。

## 目标

完成或复验个人研发工作台 V0 的最小交付链：读取并绑定 Spec → 明确执行模式和授权范围 → 受控执行 → 收集实际 Diff 与命令结果 → 运行最小 Eval → 生成摘要 → 等待具名人工确认。

任务及页面能够回查本次合同、代码版本、候选目录、允许修改的文件、实际变化、检查结果和审核决定。仅复验模式明确显示没有调用 Codex 编码；真实编码模式必须留下实际调用及修改证据。

将本次发现的越界、失败留证或误签收问题落实为可重复检查的控制能力，为下一步库存导出提供可靠执行条件。

## 非目标

- Ticket A 不实现库存导出，也不代替 Ticket B 的业务验收。
- 不新增订单、采购、财务或其他 ERP 功能。
- 不复刻后续课程全部页面、完整 Harness 平台、记忆系统或工作流蒸馏闭环。
- 不另建假数据页面，不让测试通过自动触发人工批准、合并或发布。
- 不以本合同的创建、解析成功或参考仓库绿灯证明学生已经完成建设。

## 约束

1. 使用项目 `.venv` 和现有 Spec、任务、执行、Eval 与页面入口；优先采用 Python 标准库，不为课程跟跑新增外部服务依赖。
2. 修改前由构建者核对实际缺口，记录本轮逐文件允许清单、理由及检查命令。目录级边界不能代替本次逐文件授权；需要扩大范围时先说明并取得对应授权。
3. 复验与编码模式显式区分。编码执行必须绑定候选目录、允许文件、超时和停止条件；缺少允许文件清单时不得启动编码。
4. 不直接修改运行数据库、验收身份或源码指纹来绕过状态和接受条件；不提交密钥、`.env`、运行数据库或生成报告。
5. 执行器退出码、实际 Diff 和 Eval 分别核对。退出码为零不能覆盖越界或验收失败；异常、超时及失败证据必须保留。
6. 网页与命令使用同一工作台运行目录；工作台与 FlowERP 的业务数据库分开。页面应显示真实记录，尚未贯通的显示连接如实记录。
7. 建设者先运行针对性检查自查，再由实际非构建者亲自复验并审核。任务已在待审核状态时，不直接重复运行同一任务；需要重验时按合法返工路径处理或创建关联的新复验任务，保留旧记录。
8. 控制源码变化后，原接受记录不能继续作为 B 的执行资格。完成当前版本复验与独立接受后，才能重新提交 B。

## 验收用例

| 编号 | 输入或操作 | 预期结果与需保留的证据 |
|---|---|---|
| A1 合同接入 | 使用六段齐全的能力合同创建并准备任务；另用缺少“完成定义”的副本尝试准备 | 有效合同可回查；无效合同明确拒绝且不启动编码。保存输入、输出与任务状态。 |
| A2 仅复验 | 创建不带编码授权的任务并运行复验 | 不调用 Codex 编码，不产生编码 Diff；记录本次检查命令、退出码和结果，页面明确显示仅复验。 |
| A3 授权完整 | 在隔离检查中提交有明确允许文件的编码请求，再提交缺少允许文件清单的请求 | 前者进入受控执行；后者在编码启动前拒绝。检查替身与真实调用分别标注。 |
| A4 失败与超时 | 在隔离检查中分别让执行器报错及超过设定时限 | 有界停止，记录错误、超时、已有输出和实际变化，不进入已完成状态，不删除失败证据。 |
| A5 范围控制 | 让检查替身返回退出码零，同时产生允许范围外的改动；另验一次范围内改动 | 越界仍被阻断，指出实际越界文件；范围内改动继续进入检查。保留真实测试 Diff 与断言。 |
| A6 检查与人审 | 分别运行通过和失败的最小 Eval | 通过后停在待审核；失败保留原因并进入返工或失败状态。页面、任务原始记录和退出结论一致。 |
| A7 独立接受 | 非构建者亲自复验同一控制版本并记录审核决定；另测试缺少独立接受时提交 B | 合格 A 可供后续交付引用；未接受、自签或缺少独立复验的 A 不能启动 B。不得虚构署名。 |
| A8 版本失效 | 在受控练习副本中改变已接受的控制源码后尝试引用旧 A | 旧接受失效，B 在调用编码前被阻断；保留差异与拒绝结果，重新复验当前版本。 |
| A9 页面回查 | 打开自己的 A，查看合同、执行方式、写集、检查结果与人工确认入口 | 能从同一任务定位原始证据；仅复验无编码变化时如实显示，页面可见不代替底层行为验证。 |

已有能力首次检查即通过时记录为已有，不人为制造建设红灯。新增或修复能力保留同案修改前结果、范围内 Diff 与修改后结果；环境错误不能充当目标行为失败。上述控制实验不替代 B 的真实 Codex 调用和库存 CSV 验收。

## 完成定义

- 本轮实际缺口已补齐；相关测试和阻断级 Eval 通过，退出码与结论一致。尚未覆盖的验收项明确列出，不以统一绿灯代填。
- 任务保留合同、控制版本、授权范围、实际 Diff、原始执行与验证记录；摘要列出修改文件、验证命令和剩余风险。
- 本人能在工作台演示一次正常路径和一次拒绝或失败路径，并解释规则、Spec、执行、检查与人工确认如何衔接。
- 实际非构建者已亲自复验当前控制版本并具名接受；若没有独立复验者或仍有关键失败，状态保留为待独立接受或返工。
- 接受时核对密钥和环境文件未提交。接受后的控制变化须重新复验，不沿用失效记录。
- A 独立接受后，将其真实编号交给库存导出 B；B 的产品变化、业务用途确认与独立验收另行留证。A 完成不等于 B 完成，也不证明跨任务复用闭环已经实现。
