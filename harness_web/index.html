这是什么？

FlowERP：要持续交付的电商 ERP（库存、订单、采购）。

Harness：研发自动化工作台——接需求、受控改代码、跑 Eval、留证据、老板终审。

两层词汇：交付轨道按软件研发分工：业务 → 产品（兼 PM）→ 开发 → 测试 → Leader。Harness 运行时对照 DeepSeek / Codex：User、Agent、Tools、Session/Thread、Turn/Step、Event stream、Interrupt。侧栏芯片是运行时视角，不是三个独立登录账号。

两种审批：交付终审是老板/Leader 具名通过或驳回；工具 ask 是 approval=ask 一次性放行。二者不是同一件事，8010 也不做成审批队列产品。

OPC 定位：多 Agent 是可选挑战，不是大纲 L01～L16 通过标准；结业仍以 Eval、具名人审和证据链为准。

职责分离：开发负责执行，测试负责挑刺，只有老板/Leader 能终审通过；自动化 actor 不能 approve。

侧栏筛选：全部 / 进行中 / 待验收 / 终态。

死信：自动化耗尽后的终态。用「复制会话再试」并启用改代码继续。

顶部进度条：跟踪「这一次改 FlowERP」的交付轨道与当前角色。

过程页：对照 DeepSeek Trajectory / Codex event stream 的只追加 Session 日志。按 User / Agent / 工具，或按来源（turn/step、tool、模型、交付）筛选；前三项是 Harness 内核，交付是课程 task/* 扩展。

对照 DeepSeek Harness：设置里的 Profile / dump-config 对应 dsh --dump-config。本仓库是教学交付 Harness，不是 Cordis，也不能安装官方 @deepseek-ai/* 插件。

对照 Codex Harness：对话对应 Thread / Session；过程对应 event stream；暂停对应 Interrupt。没有接入 openai/codex app-server JSON-RPC，模型也不随 Harness 开源。
