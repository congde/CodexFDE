这是什么？

FlowERP：要持续交付的电商 ERP（库存、订单、采购）。

Harness：研发自动化工作台——接需求、受控改代码、跑 Eval、留证据、老板终审。

职责投影：规格员 / 工程师 / 质检员首先是流水线节点和事件标签，不等于三个独立 Agent。当前是否有真实模型执行，以设置中的 LLM Provider 为准；template 只代表模板驱动。

OPC 定位：多 Agent 是可选挑战，不是大纲 L01～L16 通过标准；结业仍以 Eval、具名人审和证据链为准。

职责分离：实现职责负责执行，质检职责负责挑刺，只有老板能终审通过；自动化 actor 不能 approve。

侧栏筛选：全部 / 进行中 / 待验收 / 终态。

死信：自动化耗尽后的终态。用「复制会话再试」并启用改代码继续。

顶部进度条：跟踪「这一次改 FlowERP」的流水线与当前职责。

过程页：事件账本（含 agent:* 职责 actor），用于复盘和答辩。
